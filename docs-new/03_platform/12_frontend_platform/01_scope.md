## 1. Назначение документа

Документ фиксирует границу фронтенд-платформы, состав общего фронтенд-слоя,
три приложения и ответственность соседних платформенных областей.

## 2. Что входит

Факт относится к фронтенд-платформе, если он описывает общий механизм фронтенда,
публичный пакет фронтенда, оболочку приложения, запуск, маршрутизацию, навигацию,
общий UI-компонент, рендерер настроенного runtime или общую интеграцию приложения
с контекстом платформы, сессией и API-клиентом.

Факт не относится к фронтенд-платформе, если он описывает предметную модель,
схему артефакта, серверное исполнение операции, каталог прав, хранилище аудита
или бизнес-сценарий конкретной платформенной области.

### Критерий включения и состав области

| Обязанность | Входит | Не входит | Соседний владелец | Основание |
| --- | --- | --- | --- | --- |
| Рабочая область фронтенда | `apps/*`, `packages/*`, корневые скрипты, ограничения Node/pnpm. | Рабочая область серверной части и топология развёртывания. | Foundation / Operations | [`package.json`][frontend-package]; [`pnpm-workspace.yaml`][workspace] |
| Профили приложений | Общая модель приложений `Admin`, `Runtime`, `Studio` и различия уровня оболочки. | Предметные сценарии конкретных функций. | Tenant Security, Configuration, Value Sets, Settings | [`@dmp/app-admin`][admin-package]; [`@dmp/app-runtime`][runtime-package]; [`@dmp/app-studio`][studio-package] |
| Слой UI runtime | Хосты, адаптеры, провайдеры, рендереры и хуки для настроенного пользовательского слоя. | Схема артефактов и серверное исполнение операций. | Configuration / Object Runtime / Workflow | [`runtime-react`][runtime-react-index] |
| UI-контракты | Контракты TypeScript для настроенного пользовательского слоя, `grid`, `lookup`, `operation`, `personalization` и `workspace`. | Каноническая серверная семантика этих данных. | Владельцы контрактов серверной части | [`runtime-contracts`][runtime-contracts-index] |
| Общий набор UI-компонентов | Оболочка, навигация, компоненты списков, форм, действий и диалогов. | Представление конкретной функции и бизнес-правила. | Область-владелец функции | [`экспорты ui`][ui-index] |
| Локализация фронтенда | Выбор `ru-RU`/`en-US`, резервные тексты и использование языка сессии/браузера. | Локализация предметных значений на сервере. | Tenant Security и владельцы серверной части | `@dmp/shared`, запуск приложений |
| Интеграция оболочки приложения | `TenantLoginPage`, `BrowserRouter`, `PlatformContextProvider`, верхняя и боковая панели, разметка страницы. | Серверная аутентификация и каталог прав. | Tenant Security | `main.tsx` и `App.tsx` приложений |

## 3. Что не входит

| Тема | Владелец | Причина |
| --- | --- | --- |
| Схема `ObjectType`, `View`, `Action`, `Menu` | Configuration | Фронтенд-платформа потребляет опубликованную/эффективную модель, но не определяет свойства схемы. |
| Исполнение объектов runtime | Object Runtime | Фронтенд вызывает Runtime API и отображает результат, но не исполняет конвейер изменения данных. |
| Роли, права, политика выдачи и контракт сессии | Tenant Security | Фронтенд применяет видимость и защиту маршрутов, но серверная авторизация остаётся источником истины. |
| Состояния, команды и история Workflow | Workflow | Фронтенд отображает доступные команды и историю по проекции сервера/runtime. |
| Сценарий редактора Value Sets | Value Sets | Общая оболочка и рендерер принадлежат фронтенд-платформе; сценарий данных и API остаётся у Value Sets. ([UX][value-sets-ux]) |
| Семантика Configuration Explorer и редактора артефакта | Configuration | Сценарий функции Studio описывается у Configuration; фронтенд-платформа описывает общую оболочку и границу runtime. ([UX][configuration-ux]) |
| Хранилище аудита и политика аудита | Audit History | Фронтенд не является источником записей аудита. |

## 4. Граница с соседними областями и модулями

Фронтенд-платформа ведет документацию не как три независимые области, а как одну
область с профилями приложений:

| Уровень | Владелец документации | Что фиксируется |
| --- | --- | --- |
| Общий фронтенд-слой | Фронтенд-платформа | Пакеты, экспорты, контракты, общие UI-компоненты, локализация, примитивы оболочки и отображение runtime. |
| Профиль приложения: Admin | Фронтенд-платформа | Поведение Admin на уровне оболочки, удалённая/локальная навигация и граница подключения функций. |
| Профиль приложения: Runtime | Фронтенд-платформа | Рабочее место опубликованного runtime, точка входа, хост разрешённого маршрута и навигация runtime. |
| Профиль приложения: Studio | Фронтенд-платформа | Компоновка Studio на уровне оболочки, интеграция контекста Configuration и граница подключаемых функций. |
| Сценарий функции внутри приложения | Область-владелец функции | Tenant Security, Configuration, Value Sets, Settings и другие предметные сценарии. |

Это означает: общий код фронтенда, который используется несколькими функциями,
описывается здесь. Экран предприятий, редактор артефакта или редактор данных
Value Sets при этом не становятся частью этой области: их предметные правила,
поля и операции по-прежнему описываются у владельцев соответствующих функций.

## 5. Соответствие требованиям

| Требование | Покрытие | Решение | Документ-владелец |
| --- | --- | --- | --- |
| Общая инфраструктура фронтенда для `Admin`, `Runtime`, `Studio` | Подтверждено кодом рабочей области и общих пакетов. | Входит в текущую границу. | `02_architecture.md`, `03_contracts.md` |
| Разделение общего слоя и сценариев функций | Подтверждено кодом приложений и документами владельцев. | Общие механизмы описываются здесь, предметные сценарии остаются у владельцев. | `06_user_experience.md` и UX-документы областей |
| Совместимость контрактов фронтенда и серверной части при миграции | Требование целевого результата; полный манифест не подтверждён кодом. | Текущее ограничение фиксируется здесь, манифест остаётся открытым решением `FE-DEC-01 — источник совместимости контрактов фронтенда`. | `03_contracts.md`, `90_traceability.md` |

Соседние области уже указывают на эту границу: Configuration описывает только
свои функции Studio и отправляет оболочку/маршрутизацию/общие пакеты runtime в
фронтенд-платформу; Tenant Security явно исключает общие приложения/оболочку/запуск;
Value Sets фиксирует свой провайдер функции и маршрут, а общие правила меню и
маршрутизации передаёт фронтенд-платформе. ([Configuration UX][configuration-ux];
[Tenant Security UX][tenant-security-ux]; [Value Sets UX][value-sets-ux])

Трассировки Configuration и Object Runtime также маршрутизируют рендерер,
разметку, элементы управления UI, рендерер `TemplateCode`, поведение целей Menu и разметку списка
во фронтенд-платформу. ([Configuration traceability][configuration-traceability];
[Object Runtime traceability][object-runtime-traceability])

## 6. Ограничения версии

Фронтенд-платформа описывает только подтверждённые общие механизмы фронтенда и
границы приложений. Предметные экраны, серверная авторизация и семантика
операций остаются у владельцев соответствующих областей.
