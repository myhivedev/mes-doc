# Трассировка требований ПР03 - 03 Plant Structure

## 1. Назначение документа

Документ фиксирует соответствие между исходным проектным решением, общей стратегией документации, DMP_DATA и принятыми проектными решениями по модулю `03 Plant Structure`.

Трассировка используется как контрольная карта документов модуля. Она не заменяет доменную модель, модель Object Runtime, UI, жизненный цикл или права.

## 3. Трассировка функциональных требований

| Требование | Решение модуля | Статус |
| --- | --- | --- |
| REQ-03-B-001 | Внутренние производственные единицы ведутся через `ProductionUnit`. | Входит |
| REQ-03-B-002 | Внешние элементы производственной структуры ведутся через `Subcontractor`. | Входит |
| REQ-03-B-003 | Места хранения ведутся как `OrganizationalUnit` с `IsInventoryStorageLocation = true` и зависимыми параметрами хранения. | Входит |
| REQ-03-B-004 | Структура ячеистого склада ведется через `StorageArea`, `WarehouseBinType`, `WarehouseBin`. | Входит |
| REQ-03-B-005 | Принадлежность зон и ячеек задается ссылкой на `OrganizationalUnit`, доступную как место хранения. | Входит |
| REQ-03-C1-001 | Площадки, участки, посты, зоны отгрузки и временного хранения отражаются в производственной структуре и местах хранения. | Входит |
| LIM-03-O-001 | Транспортная, инженерная и пространственная инфраструктура не моделируется в первой границе модуля. | Ограничение |
| LIM-03-O-002 | Сложные правила доступности мест хранения, зон и ячеек отложены для отдельной проработки. | Ограничение |

## 4. Трассировка объектов

| Объект / элемент | Источник | Решение | Где детализируется |
| --- | --- | --- | --- |
| `OrganizationalUnit` | ПР03, DMP_DATA | Абстрактный базовый объект и единая ссылочная точка на собственные и внешние организационные единицы. | `02_domain_model.md`, `03_object_runtime_model.md` |
| `ProductionUnit` | ПР03, DMP_DATA | Собственная производственная единица, наследник `OrganizationalUnit`. | `02_domain_model.md`, `03_object_runtime_model.md`, `06_ui_views.md` |
| `Subcontractor` | ПР03, DMP_DATA | Внешняя организационная единица, наследник `OrganizationalUnit`. | `02_domain_model.md`, `03_object_runtime_model.md`, `06_ui_views.md` |
| `Company` | ПР03, DMP_DATA | Балансовая организация; объект принадлежит модулю. | `02_domain_model.md`, `03_object_runtime_model.md`, `06_ui_views.md` |
| `Contractor` | ПР01, 01 GMD, DMP_DATA, `TERM-004` | Внешний объект `01_general_master_data`; ссылки из `Company` и `Subcontractor` необязательные. Необязательность `Subcontractor.Contractor` является осознанным уточнением буквального требования `TERM-004`; обязательность может вводиться процессом смежного модуля, которому нужен контрагент. | Только как внешняя ссылка в документах модуля |
| `OrganizationalUnitInventoryParameters` | DMP_DATA, решение по ПР03 | Зависимый объект параметров места хранения. | `02_domain_model.md`, `03_object_runtime_model.md`, `06_ui_views.md` |
| `StorageArea` | ПР03, DMP_DATA | Зона хранения внутри места хранения. | `02_domain_model.md`, `03_object_runtime_model.md`, `06_ui_views.md` |
| `WarehouseBinType` | ПР03, DMP_DATA | Тип складской ячейки. | `02_domain_model.md`, `06_ui_views.md` |
| `WarehouseBin` | ПР03, DMP_DATA | Складская ячейка внутри места хранения; nullable колонка `InventoryStatusId` резервируется для будущей ссылки. | В v1 status-поле не публикуется в Object Runtime и UI. |
| `PlantParameters` | DMP_DATA | Не является объектом модуля; настройки регистрируются модулями-владельцами. | Не детализируется в модуле |
| `ProductionUnitOperationParameters` | ПР03, DMP_DATA, принятое межмодульное решение | Объект принадлежит модулю управления ресурсами и ссылается на `ProductionUnit`. Модуль 03 не владеет настройкой. | Внешняя ссылка и граница с модулем управления ресурсами |
| `OrganizationalUnitWorkSchedule` | ПР04, DMP_DATA, принятое межмодульное решение | Единый объект принадлежит модулю управления ресурсами и ссылается на внешний `OrganizationalUnit`; модуль 03 предоставляет обратную runtime-навигацию для конкретных `ProductionUnit` и `Subcontractor`. | `02_domain_model.md`, `03_object_runtime_model.md` |
| `InventoryStatus` | DMP_DATA | Не является объектом модуля; стабильный контракт целевого объекта пока отсутствует. | В v1 сохраняются пять nullable GUID-колонок без FK и runtime reference; публикация ссылок отложена до модуля производственной логистики. |

## 5. Принятые проектные решения

| Решение | Итог | Влияние на документацию |
| --- | --- | --- |
| Граница модуля и ПР04 | Модуль проектируется до детального ПР04; ресурсы, рабочие места, персонал, оборудование и графики не входят в модуль. | В документации модуля фиксируются только внешние потребители ссылок на производственную структуру. |
| `Company` | `Company` остается в модуле как балансовая организация; `ProductionUnit` имеет не более одной необязательной ссылки `Company`. | Поля и ограничения описываются в `02_domain_model.md`; множественная связь с `ProductionUnit` не вводится, связь с `Contractor` внешняя и необязательная. |
| `OrganizationalUnit` | Одна физическая таблица с дискриминатором и абстрактным контрактом Object Runtime. | Требуется детальное описание abstract/reference-only поведения в `03_object_runtime_model.md`. |
| Статусы | Универсальное поле `Status` из старой модели не переносится. | Жизненный цикл проектируется только для `OrganizationalUnit`, `ProductionUnit`, `Subcontractor`. |
| `ProductionUnitType` | Фиксированный системный enum; `ValueSet` для него не используется, состав не расширяется в v1. | Линии, посты, отделы, службы, бюро, кладовые и другие элементы используют подходящий существующий тип либо `Other`; новые стабильные коды не вводятся. |
| `Plant` / `Site` | Целевой термин платформы - `Site / Площадка`; старое `Plant` должно быть мигрировано в коде и документации платформы. | В модуле используется `ProductionUnitType.Site`; платформа синхронизируется по backlog `plans/025_plant_to_site_platform_migration_backlog.md`. |
| Иерархия `ProductionUnit` | Допускается несколько корневых `Enterprise` в одном `Tenant`; `Main` является root-ссылкой hierarchy capability. Для остальных типов матрица допустимых пар родитель → потомок в v1 не вводится. | После корневого `Enterprise` допускаются произвольные цепочки значений `ProductionUnitType`; сохраняются запрет дочернего `Enterprise`, tenant scope и общие проверки циклов. |
| Места хранения | Местом хранения допускается `ProductionUnit` или `Subcontractor`; ссылка зон и ячеек должна идти на `OrganizationalUnit`. | Расхождение с отдельными местами DMP_DATA фиксируется как целевое изменение модели. |
| `PlantParameters` | Не объект модуля и не вкладка карточки. | Настройки регистрируются владельцами прикладных модулей через платформенные settings. |
| `OrganizationalUnitInventoryParameters` | Входит в модуль как зависимый объект места хранения; собственные enum-поля параметров определяются как SystemEnum ПР03, а `InventoryLocationControlType` переиспользуется из GMD. | Описывается в доменной модели, runtime и UI карточек; повторная регистрация `InventoryLocationControlType` в baseline ПР03 запрещена. |
| Удаление `OrganizationalUnitInventoryParameters` | При отключении места хранения зависимая запись физически удаляется в той же транзакции. | Soft delete, архивирование и самостоятельные create/delete/archive не применяются; при повторном включении создается новая запись с начальными значениями. |
| `SegmentStageUsage` | Одно скалярное поле флагового SystemEnum `WIPSegmentStage`, хранящее числовую битовую маску. | В C# используется `[Flags]`, в baseline — `IsFlags = true`; коллекция и связующая таблица не создаются. |
| Параметры уровня передела | `ScrapWarehouse`, `ScrapWarehouseBin`, `WIPSerialNumbersControlStage`, `SegmentStageUsage` и `Transfer*DefaultType` редактируются только при `OrganizationalUnit.IsSegmentLevel = true`. | Серверное правило `PS-IP-010` синхронизировано с доступностью полей в UI. |
| Жизненный цикл параметров места хранения | `OrganizationalUnitInventoryParameters` изменяется только когда владелец находится в `Draft`; при `Published` и `Archived` доступен только для чтения. | `PlantStructureStorageResponsible` не получает `ReturnToDraft`; ограничение проверяется Object Runtime, а не только UI. |
| Размещение запаса в иерархии `WarehouseBin` | Любая ячейка, включая имеющую дочерние ячейки, может содержать запас. | `Parent` задает иерархическое расположение самостоятельных ячеек; `HasChildren` не является признаком запрета размещения. Это принятое уточнение трактовки `TERM-009`. |
| Зависимый выбор складской ячейки | Для любой пары `*Warehouse` / `*WarehouseBin` ячейка выбирается только после места хранения и только среди его ячеек. | Lookup ячейки недоступен без места хранения; очистка или замена места хранения очищает ячейку; сервер запрещает сохранять ячейку без места хранения или для другого места хранения. |
| Независимое редактирование настроек v1 | Кроме явно определенных правил `PS-IP-*`, поля `OrganizationalUnitInventoryParameters` редактируются независимо; `Transfer*DefaultType` не управляют обязательностью или очисткой других полей. | Содержательную корректность сочетания значений контролирует пользователь. Дополнительные условные зависимости отложены до уточнения производственной и логистической логики на последующих этапах. |
| Отложенные ссылки `InventoryStatus` | В физической модели v1 сохраняются nullable колонки `InventoryStatusId`, `TransferYieldDefaultStatusId`, `TransferRejectDefaultStatusId`, `TransferScrapDefaultStatusId` и `WarehouseBin.InventoryStatusId`. | Поля не включаются в object contracts, baseline, datasets, UI и mutation payload; `PS-ST-004` не активируется. После появления контракта логистики колонки публикуются как ссылки без изменения схемы колонок. |
| Межмодульные dependency checks | В v1 ПР03 проверяет только собственные объекты и ссылки; входящие зависимости других модулей не блокируют `ReturnToDraft`, архивирование или отключение места хранения. | Общий механизм dependency checks отложен. До его появления каждый модуль-потребитель защищает собственную целостность и учитывает состояние объектов ПР03 при чтении. |
| UI v1 | Проектируются списки и карточки только для объектов модуля. | Нет UI для `PlantParameters` и `ProductionUnitOperationParameters`. |
| Права | Специальные операции прав модуля не вводятся; используются стандартные Object Runtime rights и прикладные роли. | Матрица ролей описывается в `11_permissions.md`. |
| Меню навигации | Пункты ПР00 раздела `Производственная структура` открывают списки объектов модуля. | Пункты главного меню и связь со списками фиксируются в `15_navigation_menu.md`. |

## 6. Граница с другими модулями

| Модуль / область | Связь с модулем |
| --- | --- |
| `00_common` | Общие механизмы справочников, архивирования, Audit/ExternalId и терминология используются без дублирования. |
| `01_general_master_data` | Владеет `Contractor`, классификаторами контрагентов и SystemEnum `InventoryLocationControlType`. ПР03 ссылается на `Contractor` и переиспользует этот enum без дублирования. |
| Модуль состава и версий | Может регистрировать настройки состава и версий, ранее находившиеся в `PlantParameters`. Модуль их не владеет. |
| Модуль управления ресурсами | Использует `OrganizationalUnit` и `ProductionUnit` как внешние ссылки для ресурсов и рабочих мест; владеет `ProductionUnitOperationParameters` и `OrganizationalUnitWorkSchedule`. Модуль 03 предоставляет организационные единицы и обратную runtime-навигацию, но не изменяет эти записи. ПР10 использует эффективные значения параметров при управлении операциями. |
| Модуль производственной логистики | Использует места хранения, зоны, ячейки и параметры хранения в логистических алгоритмах. |
| Платформа | Владеет `Tenant`, `Site`, settings, правами, Object Runtime, baseline и конфигурационными артефактами. |
| Object Runtime hierarchy capability | Обеспечивает parent/root/level/path, запрет циклов и выборку деревьев для `ProductionUnit` и `WarehouseBin`. |

## 7. Статус открытых и спорных вопросов

| Вопрос | Статус | Решение |
| --- | --- | --- |
| Нужно ли сначала проектировать модуль управления ресурсами | Закрыт | Модуль можно и нужно проектировать раньше модуля управления ресурсами. |
| Владение и связь `Company` | Закрыт | Модуль владеет `Company` как балансовой организацией; `ProductionUnit.Company` является одиночной необязательной ссылкой. |
| Связи `Company.Contractor` и `Subcontractor.Contractor` | Закрыт | Обе ссылки внешние и необязательные. Для `Subcontractor.Contractor` это решение явно уточняет `TERM-004`; ПР03 не проверяет обязательность ссылки при создании субподрядчика. |
| Абстрактный `OrganizationalUnit` | Закрыт | Нужен абстрактный объект и конкретные наследники `ProductionUnit`, `Subcontractor`. |
| SystemEnum / ValueSet | Закрыт | ПР03 вводит собственные SystemEnum, кроме `InventoryLocationControlType`, который переиспользуется из GMD; собственные ValueSet не вводятся. |
| `PlantParameters` | Закрыт | Исключен из объектов модуля; настройки регистрируют владельцы модулей. |
| `OrganizationalUnitInventoryParameters` | Закрыт | Включен в модуль как зависимый объект места хранения. |
| `ProductionUnitOperationParameters` | Закрыт | Принадлежит модулю управления ресурсами; модуль 03 предоставляет `ProductionUnit` как внешний объект ссылки и не владеет настройкой. |
| Навигация к назначениям графиков | Закрыт | `OrganizationalUnit.WorkSchedules` описывается в модуле 03 как внешняя коллекция режима `Навигация`; для `ProductionUnit` и `Subcontractor` применяются ограничения `UnitKind`, а создание и изменение строк выполняет модуль управления ресурсами. |
| `Plant` vs `Site` | Закрыт для модуля, требует платформенной миграции | В модуле используется `Site / Площадка`; миграция платформенного термина ведется отдельным backlog. |
| Сложные правила доступности мест хранения | Отложены; разработку ПР03 v1 не блокируют | Не входят в первую границу модуля и будут проработаны отдельно. |
