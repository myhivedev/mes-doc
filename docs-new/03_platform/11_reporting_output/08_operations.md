# Эксплуатация — Reporting и Output

## 1. Назначение документа

Документ описывает конкретные операции запуска, готовности, диагностики и
восстановления. Общие правила развёртывания host принадлежат Platform Operations.

## 2. Запуск и готовность

| Шаг запуска | Условие | Идемпотентность | Критерий готовности | Откат |
| --- | --- | --- | --- | --- |
| Зарегистрировать сервисы отчётов runtime | Host вызывает регистрацию runtime-компонентов | Повторная регистрация не должна создавать второй client | Сервисы разрешаются через DI | Перезапуск host |
| Настроить `Runtime:ReportService` | Доступны `BaseUrl`, timeout и параметры preview | Конфигурация читается при старте | Runtime может создать HTTP client | Исправить параметры и перезапустить |
| Настроить общий корневой каталог файлов отчётов | Runtime и Java-сервис видят один каталог | Каталог используется повторно | Файлы design/schema/data доступны сервису рендеринга | Исправить подключение каталога и права |
| Проверить готовность Java-сервиса | `GET /health/ready` возвращает `UP` | Только чтение | Рендеринг и проверка готовности BIRT работают | Перезапустить или диагностировать сервис |

## 3. Миграции

| Изменение | Порядок | Совместимость | Проверка | Откат |
| --- | --- | --- | --- | --- |
| Schema содержимого Configuration | Сначала миграция Configuration, затем публикация определений | Определяется Configuration | Проверка публикации | Процедура Configuration |
| Пакет design отчёта | Экспорт → импорт → проверка → публикация | Нужны совместимые поля и schema | `isValid = true` и ссылки на содержимое | Вернуть предыдущий опубликованный design |
| Версия Java-сервиса рендеринга | Обновить сервис и проверить контракт рендеринга | Согласовать форматы и ошибки | Интеграционные тесты Java и проверка готовности | Вернуть предыдущую версию сервиса |

Отдельной Reporting/Output database migration в текущей реализации не подтверждено.

## 4. Диагностика

| Сигнал | Диагностика | Действие | Критерий восстановления | Эскалация |
| --- | --- | --- | --- | --- |
| `OutputNotFound` или `ReportNotFound` | Проверить опубликованные определения, контекст модуля/объекта и код источника | Исправить Configuration и опубликовать | Определение снова разрешается провайдером | Configuration |
| `OutputFormatUnsupported` | Проверить `Output.Format` и сопоставление Runtime | Использовать `Pdf` или `Excel` | Сопоставление проходит до сервиса рендеринга | Reporting/Output |
| `OutputDeliveryModeUnsupported` | Проверить `DeliveryMode` | Использовать `Download` или `Inline` | Ответ возвращается клиенту | Reporting/Output |
| `ReportOperationalXmlIdentityUnknown` | Проверить код отчёта и зарегистрированные identity | Добавить подтверждённую identity | XML создаётся до рендеринга | Runtime |
| `REPORT_FILE_NOT_FOUND` | Проверить `RootPath`, имена файлов и общий доступ каталогов | Восстановить корневой каталог файлов | Java-сервис читает все три файла | Report Service / Operations |
| `REPORT_FILE_ACCESS_DENIED` | Проверить права учётной записи сервиса | Исправить права | Рендеринг получает доступ | Operations |
| `REPORT_SERVICE_UNAVAILABLE` | Проверить `BaseUrl`, `/health/ready`, timeout и журналы сервиса | Восстановить сервис или связь | Запрос рендеринга получает HTTP-ответ | Report Service / Operations |
| `RENDER_FAILED` | Проверить идентификатор запроса, файлы `design`/`schema`/`data` и журналы BIRT | Исправить входные данные или сервис рендеринга | Возвращён непустой результат | Report Service |

## 5. Восстановление

1. Сохранить `requestId` и технический код ошибки.
2. Проверить опубликованные определения и общий корневой каталог файлов.
3. Проверить `/health/ready` Java-сервиса.
4. Повторить запрос только после устранения причины; автоматический retry этим
   документом не гарантируется.

## 6. Откат и эскалация

- Ошибка design/конфигурации исправляется в Configuration и повторной публикацией.
- Ошибка сервиса рендеринга эскалируется владельцу `DMP.ReportService`.
- Ошибка Dataset или контекста объекта эскалируется владельцу соответствующего
  application-порта.
- Ошибка прав или Tenant/Site эскалируется владельцу Tenant/Security.
