# Правила — Управление документацией

## 1. Назначение документа

Документ определяет предметные инварианты, ограничения изменения, правила ссылочной целостности, архивирования и удаления.

## 2. Общие правила модуля

| Правило | Проверка | Ошибка при нарушении |
|---|---|---|
| Граница предприятия | Документ, тип, каталог, содержимое и связи принадлежат одному предприятию (`TenantId`). | Объект другого предприятия. |
| Обязательные поля | При сохранении заполнены каталог, тип документа, номер документа и наименование. | Обязательное поле не заполнено. |
| Права | Каждое изменение повторно проверяется на сервере. | Недостаточно прав. |
| Одновременное изменение | Сохранение не перезаписывает более новую версию данных; для update/delete/action передаётся `ConcurrencyToken`. | Конфликт изменения. |

## 3. Нумерация

| Объект и поле | Правило | Ручное изменение |
|---|---|---|
| Тип документа — «Код типа документа» (`DocumentType.Code`) | При создании автоматически формируется по шаблону `{Numerator:00}` в пределах предприятия. Поле обязательно. | Разрешено до создания первого документа этого типа. |
| Документ — «Номер документа» (`Document.Number`) | При создании автоматически формируется по шаблону `{DocumentType.Code}-{Numerator:0000}`. Счётчик отдельный для предприятия и типа документа. Поле обязательно. | Разрешено до сохранения и далее в черновике. |
| Новая версия — «Номер документа» (`Document.Number`) | Копируется из исходного документа; правило нумерации не запускается. | Разрешено по общим правилам черновика. |

Оба правила поставляются активными и опубликованными с запуском при создании. Если обязательный номер сформировать не удалось, карточка может быть открыта, но документ не сохраняется.

## 4. Документ и версии

Инварианты:

| Правило | Проверка | Ошибка при нарушении |
|---|---|---|
| Уникальность версии | Сочетание типа, номера документа и номера версии уникально в предприятии. | Версия документа с таким номером уже существует. |
| Первая версия | Номер версии равен 1; ссылка на первоначальный документ пуста. | Нарушена структура цепочки версий. |
| Последующая версия | Ссылка указывает на первую версию; номер версии является следующим свободным. | Нарушена структура цепочки версий. |
| Ответственное подразделение | Выбрана внутренняя производственная единица текущего предприятия; подрядчик исключён. | Недопустимое ответственное подразделение. |

Ограничения изменения:

| Поле или данные | Когда запрещено менять | Причина |
|---|---|---|
| Бизнес-поля документа | В состояниях «Опубликован» (`Published`) и «Архив» (`Archived`). | Изменение разрешено после возврата той же версии в черновик. |
| Тип документа (`DocumentTypeId`) | После первого прикрепления содержимого. | Тип определяет хранилище и ограничения файлов. |
| Ответственные | Без отдельного разрешения на изменение ответственных. | Доступ ограничен матрицей прав. |

Состояния и переходы не повторяются здесь и определены в [04_workflows.md](04_workflows.md).

## 5. Каталоги, типы и хранилища

| Правило | Проверка | Ошибка при нарушении |
|---|---|---|
| Корневой каталог | При подключении предприятия существует корневой каталог «Документы». | Начальная конфигурация модуля не установлена. |
| Каталог документа | Документ ссылается на каталог текущего предприятия. | Каталог не выбран или недоступен. |
| Иерархия каталогов | Каталог не является своим родителем или потомком. | Обнаружен цикл каталогов. |
| Уникальность кода каталога | Код каталога уникален в предприятии. | Каталог с таким кодом уже существует. |
| Уникальность кода типа | Код типа документа уникален в предприятии. | Тип документа с таким кодом уже существует. |
| Хранилище типа | Обязательное поле «Хранилище» (`DocumentType.StorageId`) заполнено записью текущего предприятия. | Хранилище не выбрано или недоступно. |
| Ограничения типа | Тип может только уменьшить максимальный размер файла и сузить перечень расширений предприятия. | Ограничение типа шире ограничения предприятия. |

При подключении модуля создаётся системная логическая запись хранилища «База
данных». При создании типа поле «Хранилище» (`DocumentType.StorageId`)
заполняется её идентификатором из начальных данных модуля. Физическое хранение
выполняет Platform Content Storage; пользовательские хранилища и возможность
выбора другого провайдера отложены после MVP (`DM-Q-024`).

## 6. Содержимое документа

| Правило | Проверка | Ошибка при нарушении |
|---|---|---|
| Вид содержимого | Выбран один вид: «Файл» (`Binary`), «Ссылка» (`Url`) или «Текст» (`Text`). | Не выбран или неверно заполнен вид содержимого. |
| Данные вида | Заполнены только поля выбранного вида. | Заполнены несовместимые данные содержимого. |
| Адрес ссылки | Адрес начинается с `http://` или `https://`. | Некорректная ссылка. |
| Неизменяемость | После первого прикрепления вид и данные содержимого не меняются. | Прикреплённое содержимое нельзя изменить. |
| Уникальность связи | Одно содержимое нельзя дважды прикрепить к одному документу. | Содержимое уже прикреплено. |
| Основное содержимое | У документа не более одной основной связи; первая успешная связь становится основной. | У документа указано несколько основных содержимых. |
| Отвязка основного | Первым по порядку назначается оставшееся содержимое. | Основное содержимое не переназначено. |
| Последняя связь | После удаления последней связи содержимое сразу мягко удаляется в той же целостной операции. | Не удалось завершить отвязку содержимого. |

Для вида «Файл» (`Binary`) в MVP обязательно заполнен `ContentRef` на
финализированный ресурс Platform Content Storage. Бинарное содержимое не
передаётся в доменный объект; внешние providers и расширенная настройка
размещения отложены после MVP (`DM-Q-025`).

## 7. Файлы

Начальный максимальный размер файла — 100 МБ. Разрешены:

`.pdf`, `.doc`, `.docx`, `.xls`, `.xlsx`, `.ppt`, `.pptx`, `.rtf`, `.txt`, `.csv`, `.jpg`, `.jpeg`, `.png`, `.bmp`, `.tif`, `.tiff`, `.dwg`, `.dxf`, `.step`, `.stp`, `.iges`, `.igs`.

Архивы `.zip` и `.7z`, исполняемые файлы и сценарии запрещены. Расширение проверяется без учёта регистра; сервер дополнительно сопоставляет тип содержимого. Технический предел сервера не должен быть меньше прикладного.

## 8. Связи с записями бизнес-объектов

| Правило | Проверка | Ошибка при нарушении |
|---|---|---|
| Тип записи | Квалифицированный код типа зарегистрирован. | Тип связанного бизнес-объекта не зарегистрирован. |
| Запись | Запись существует в текущем предприятии и доступна пользователю для просмотра. | Связанная запись недоступна. |
| Уникальность | Связь документа с той же записью отсутствует. | Связь уже существует. |
| Последующая недоступность | Связь сохраняется, но сведения записи не раскрываются. | Пользователю показывается только сообщение «Связанный объект недоступен». |

## 9. Правила удаления и архивирования

| Пользовательский объект | Правило |
|---|---|
| Документ (`Document`) | Архивирование; физическое удаление запрещено. |
| Каталог документов (`DocumentFolder`) | Архивирование; физическое удаление запрещено. |
| Тип документа (`DocumentType`) | Архивирование; физическое удаление запрещено. |
| Содержимое документа (`DocumentContent`) | Мягкое удаление после удаления последней связи. |
| Связь документа с содержимым (`DocumentContentLink`) | Удаляется строка связи; документ и используемое другими документами содержимое сохраняются. |
| Связь документа с бизнес-объектом (`DocumentObjectLink`) | Удаляется только строка связи. |

## 10. Граница с другими модулями

- существование и доступность связанной записи проверяются через платформенный контракт модуля-владельца;
- ответственное подразделение выбирается из производственных единиц модуля производственной структуры;
- ответственный выбирается из сотрудников модуля «Управление ресурсами»;
- секреты провайдера хранения принадлежат защищённой платформенной конфигурации.

## 11. Отложенные решения

| Идентификатор | Вопрос |
|---|---|
| `DM-Q-008` | Дополнительные обязательные поля по типу документа; целевая структура — `DocumentTypeRequiredField`, реализация после MVP. |
| `DM-Q-024` | Пользовательские хранилища и расширенный жизненный цикл после MVP. |
| `DM-Q-025` | Внешнее хранение файлов после MVP. |

## 12. Политика файлов

Итоговая политика файлов формируется из ограничений платформы, настроек модуля
и политики типа документа. Каждый нижний уровень может только сузить список
разрешённых расширений, размер и количество файлов. Динамические обязательные
поля типа документа (`DM-Q-008`) в MVP не реализуются.
