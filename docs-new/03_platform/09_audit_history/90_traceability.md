# Трассировка и открытые вопросы - Audit History

## 1. Назначение документа

Документ связывает текущий код, тесты и старые материалы с документами Audit
History. Здесь фиксируются только устойчивые ограничения MVP, расхождения и
будущие маршруты. Открытые темы не являются текущими гарантиями и не требуют
решения пользователя, если не блокируют описание текущего контракта.

## 3. Принятые решения

| Решение | Формулировка | Документ-владелец | Статус сведения |
| --- | --- | --- | --- |
| Общий конверт записи | `AuditRecord` и `IAuditHistoryWriter` являются текущей общей границей записи; смысл `Details` остаётся у потребителя | `03_contracts.md` | Подтверждено MVP |
| Ограниченное чтение | `GetSnapshot` возвращает полный доступный снимок; HTTP API чтения, фильтры и пагинация не являются текущей гарантией | `03_contracts.md`, `04_runtime.md` | Подтверждено, но ограничено |
| Разделение моделей | Audit History не владеет историей Workflow, историей бизнес-объекта, технической трассировкой или интеграционными событиями | `01_scope.md`, `05_security_and_audit.md` | Подтверждено MVP |
| Маскирование Object Runtime | `ObjectRuntimeAuditSink` заменяет чувствительные старые и новые значения на `[REDACTED]` по `IsSensitive` | `05_security_and_audit.md`, `04_runtime.md` | Подтверждено MVP |

| `AUD-REQ-02` | Минимальные категории обязательного аудита | Старые материалы о категориях обязательного аудита | Код подтверждает отдельные записи Tenant/Security, Object Runtime, Workflow, Settings и GMD | Старые материалы перечисляют `login/logout`, отказ в авторизации, критические действия, публикацию/откат конфигурации, действия Workflow, security/IAM, экспорт/доставку, межсервисные вызовы и чувствительные интеграционные операции; общей матрицы покрытия нет | Не блокирует: текущая документация говорит только о проверенных сценариях | Будущая доработка | Владельцы областей + Audit History: составить матрицу покрытия и правило обязательности | `07_quality.md`, документы областей-потребителей |
| `AUD-REQ-03` | Режим добавления записей и защита от изменения | Требование append-only и защищённого журнала | Средство записи предоставляет только операции создания и чтения, но политика схемы и БД не запрещает UPDATE/DELETE | Требование неизменяемого и защищённого журнала не подтверждено на уровне СУБД | Не блокирует: пакет не называет хранилище полным неизменяемым журналом соответствия требованиям | Будущая доработка | Audit History + Platform Operations: определить разрешения БД, защиту от изменения и legal hold | `02_architecture.md`, `05_security_and_audit.md`, `08_operations.md` |
| `AUD-REQ-04` | Провайдер хранения для промышленной среды | ADR-010 о запрете хранения в памяти в production | Host-приложение выбирает SQL Server при `ConnectionStrings:Platform`, иначе EF Core InMemory; черновой ADR запрещает хранение в памяти в production | Проверки конфигурации промышленной среды и автоматическое применение этого запрета не найдены | Не блокирует описание текущих провайдеров; блокирует только политику промышленной среды | Открытый вопрос | Architecture + Platform Operations: принять и проверить политику хранения в промышленной среде | `08_operations.md`, документация развёртывания host |
| `AUD-REQ-05` | Сквозная корреляция API, событий, аудита и технической трассировки | Требование общей передачи контекста корреляции | `AuditRecord` хранит `CorrelationId`; Object Runtime, Workflow, Settings и Tenant/Security передают его из контекста | Сквозная гарантия сопоставления с каждым API, событием и трассировкой, а также поведение при отсутствии контекста не оформлены единым контрактом | Не блокирует: поле и локальные сценарии потребителей описаны, сквозная гарантия не заявлена | Будущая доработка | Foundation / Integration Events / Platform Operations + Audit History: определить передачу и обязательность корреляции | `03_contracts.md`, `04_runtime.md`, общая карта взаимодействий |

## 5. Маршрут в целевые документы

| Тема | Владелец | Целевой документ | Действие |
| --- | --- | --- | --- |
| Решение о доступе и доступ к исходной операции | Tenant/Security | Документы Tenant/Security | Описать политику выполнения операции; Audit History принимает результат |
| Схема и смысл изменения configuration | Configuration | Документы Configuration | Описать модель изменения; Audit History хранит переданную запись |
| История переходов Workflow | Workflow | Документы Workflow | Описать состояние и историю Workflow; не дублировать общий writer |
| Предметная временная шкала объекта | Domain Module | Документ соответствующего Domain Module | Добавить предметный смысл и пользовательское представление при реализации |
| Конверт события, outbox, доставка и повторная обработка | Integration Events | Документы Integration Events | Описать отдельный канал событий; не использовать запись аудита как конверт события |
| Метрики, журналы, spans и проверки состояния | Platform Operations / observability | Документы Platform Operations | Описать техническую диагностику и health checks |
| Экран просмотра, host-маршрут и элементы интерфейса | фронтенд-платформа | Документы фронтенд-платформа | Определить интерфейс и маршрут только при появлении реализации viewer |
