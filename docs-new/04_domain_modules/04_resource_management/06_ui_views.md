# Пользовательские представления - 04 Управление ресурсами

## 1. Назначение документа

Документ описывает пользовательские списки, списки выбора, карточки и
вложенные представления модуля `04_resource_management`.

Доменная модель описана в [`02_domain_model.md`](02_domain_model.md), доступ
объектов через Object Runtime - в
[`03_object_runtime_model.md`](03_object_runtime_model.md), а предметные
проверки - в [`05_rules.md`](05_rules.md). Поля в этом документе указываются
только для настройки конкретного представления и не заменяют описание модели.

## 2. Общие решения UI

### 2.1 Общие правила списков и карточек

- Списки по умолчанию показывают доступные неархивные и неудаленные объекты.
- Уже сохраненная ссылка на архивный объект может отображаться в карточке или
  связанном списке владельца.
- Стандартные команды Object Runtime подключаются по общим правилам платформы:
  создание, изменение, сохранение, отмена, обновление, управление колонками,
  поиск, фильтр строк и пагинация.
- Настройки поиска и фильтрации сохраняются для пользователя по общему
  механизму пользовательских представлений; при наличии поддержки именованных
  режимов пользователь может сохранять настроенный набор условий.
- Для объектов без отдельного предметного workflow используются архивирование
  и восстановление. Старое действие ПР04 «Изменить статус» в целевой модели не
  добавляется.
- Системные поля Common и вычисляемые свойства отображаются по общим правилам
  платформы и не становятся редактируемыми полями прикладной формы.
- Вложенные объекты открываются в форме владельца как коллекции. Базовые
  логические типы не получают отдельного списка или карточки.

### 2.2 Общие правила списков выбора

Список выбора открывается из ссылочного поля и получает его контекст. Для
ссылок на объекты другого модуля используется lookup-контракт модуля-владельца.

| Список выбора | Объект | Контекст и ограничения |
|---|---|---|
| `WorkPlace_LookupView` | `WorkPlace` | Поиск по `Code`, `Name`, `Acronym`; при переданной `WorkPlaceGroup` показываются только ее члены. |
| `Personnel_LookupView` | `Personnel` | Поиск по `Code`, `Name`, `Number`, ФИО; при переданной `PersonnelGroup` показываются только ее члены. |
| `ToolBase_LookupView` | `Tooling` и `Gage` | Объединенный lookup только для ссылок, допускающих оба самостоятельных типа; `ToolBase` не показывается как отдельный объект. |
| `WorkPlaceGroup_LookupView` | `WorkPlaceGroup` | Только группы рабочих мест текущего tenant. |
| `PersonnelGroup_LookupView` | `PersonnelGroup` | Только группы сотрудников текущего tenant. |
| `ProductionUnit_LookupView` | внешний `ProductionUnit` | Предоставляется модулем 03; выбираются доступные производственные единицы. |
| `WorkSchedule_LookupView` | `WorkSchedule` | Доступные графики работы с учетом контекста назначения. |
| `ShiftRotationModel_LookupView` | `ShiftRotationModel` | Доступные модели для назначения сотруднику или группе сотрудников. |

Если одновременно заданы группа и конкретный ресурс, конкретный ресурс
показывается как выбранное значение, но при сохранении проверяется его
принадлежность группе. Количество ресурса, альтернативные наборы и подбор
конкретного экземпляра по норме в UI модуля 04 не задаются.

`AllowanceType`, документ-основание и период действия. `WorkPlace` остается
необязательным.
