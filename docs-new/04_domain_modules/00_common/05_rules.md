# Правила поведения - 00 Common

## 1. Назначение документа

Документ описывает поведение объектов на базе Common.

Он отвечает на вопросы:

- что происходит при создании объекта;
- что происходит при изменении объекта;
- как работает архивирование;
- как работает восстановление из архива;
- чем архив отличается от удаления;
- как работает мягкое удаление;
- когда допустимо физическое удаление;
- как runtime должен скрывать архивные и удаленные объекты;
- как должны отображаться уже сохраненные ссылки;
- какие ограничения действуют для архивных объектов.

Документ не повторяет полный состав полей. Поля описаны в `02_domain_model.md`, использование Object Runtime - в `03_object_runtime_model.md`.

## 2. Общие принципы

Для объектов на базе `CommonObject` действуют общие правила:

- системные поля не редактируются пользователем напрямую;
- поля создания заполняются при создании;
- поля изменения заполняются при изменении;
- audit/lifecycle-поля (`CreatedAtUtc`, `ModifiedAtUtc`, `ArchivedAtUtc`,
  `DeletedAtUtc`) не являются временем факта, замера или события внешнего
  источника;
- архивирование и удаление не являются одним и тем же;
- наличие архивных полей не означает, что объект можно архивировать;
- наличие полей удаления не означает, что объект можно удалить;
- архивные объекты остаются видимыми по уже сохраненным ссылкам;
- удаленные объекты скрываются из обычной рабочей модели;
- Object Runtime применяет системные фильтры централизованно.

## 3. Создание объекта

При создании объекта на базе `CommonObject` runtime должен заполнить:

```text
CreatedAtUtc = текущее время UTC
CreatedBy = текущий инициатор
ModifiedAtUtc = null
ModifiedBy = null
```

Если объект создается как неархивный и неудаленный, значения должны быть:

```text
IsArchived = false
ArchivedAtUtc = null
ArchivedBy = null
ArchiveReason = null

IsDeleted = false
DeletedAtUtc = null
DeletedBy = null
DeleteReason = null
```

Обычный пользовательский запрос создания не должен принимать:

```text
CreatedAtUtc
CreatedBy
ModifiedAtUtc
ModifiedBy
ArchivedAtUtc
ArchivedBy
DeletedAtUtc
DeletedBy
```

Исключения допустимы только для явно описанных сценариев миграции, импорта или администрирования.

## 4. Изменение объекта

При изменении объекта runtime должен заполнить:

```text
ModifiedAtUtc = текущее время UTC
ModifiedBy = текущий инициатор
```

Поля создания не меняются:

```text
CreatedAtUtc
CreatedBy
```

Обычное изменение объекта не должно менять архивные поля и поля удаления напрямую.

Для изменения этих полей нужны специальные сценарии:

- действие `Archive`;
- действие `Restore`;
- workflow-переход;
- мягкое удаление;
- административная операция;
- миграционный или импортный режим.

## 5. Инициатор операции

Поля:

```text
CreatedBy
ModifiedBy
ArchivedBy
DeletedBy
```

хранят идентификатор инициатора.

Если в runtime-контексте нет пользователя, должен использоваться явно определенный системный инициатор.

Запрещено молча записывать:

```text
Guid.Empty
```

в поля инициатора.

Отображаемое имя инициатора должно разрешаться через IAM / ActorDisplayResolver.

## 6. Архивирование

Архивирование означает, что объект больше не используется активно, но остается бизнес-фактом.

При архивировании должны быть установлены:

```text
IsArchived = true
ArchivedAtUtc = текущее время UTC
ArchivedBy = текущий инициатор
ArchiveReason = причина, если она передана
```

Архивирование должно быть доступно только если оно явно описано для типа объекта:

- прямым действием `Archive` в контракте объекта;
- или workflow-командой `Archive`, которая переводит объект в архивное состояние.

Если ни прямого действия, ни workflow-команды нет, объект нельзя архивировать, даже если архивные поля есть в `CommonObject`.

## 7. Восстановление из архива

При восстановлении должны быть очищены архивные поля:

```text
IsArchived = false
ArchivedAtUtc = null
ArchivedBy = null
ArchiveReason = null
```

Восстановление должно быть доступно только если оно явно разрешено:

- прямым действием `Restore`;
- или workflow-командой `Restore`;
- или специальной административной операцией.

Если тип объекта не поддерживает восстановление, архивный объект остается только для просмотра.

## 8. Архивирование без workflow

Если тип объекта не управляется workflow, архивирование выполняется прямым действием.

Правило для `Archive`:

```text
проверить право на действие
проверить правила объекта
проверить ограничения по ссылкам, если они есть
установить архивные поля
записать Audit History
опубликовать события, если они нужны типу объекта
```

Правило для `Restore`:

```text
проверить право на действие
проверить правила объекта
очистить архивные поля
записать Audit History
опубликовать события, если они нужны типу объекта
```

## 9. Архивирование через workflow

Если тип объекта управляется workflow, архивирование выполняется только через workflow.

Архивное состояние workflow должно иметь признак:

```text
IsArchiveState = true
```

При входе в архивное состояние runtime должен установить архивные поля.

При выходе из архивного состояния runtime должен очистить архивные поля.

Для одного типа объекта нельзя смешивать:

```text
прямое действие Archive/Restore
архивирование через workflow
```

Если объект имеет workflow, источник архивного состояния - workflow state.

## 10. Видимость архивных объектов

Обычные списки и поиск должны скрывать архивные объекты:

```text
IsArchived = false
```

Пользователь может включить системный фильтр:

```text
Показать архивные
```

Runtime-код фильтра:

```text
__runtime_include_archived
```

Логика:

```text
false или не передан
  показывать только неархивные объекты

true
  показывать неархивные и архивные объекты
```

Фильтр "Показать архивные" является фильтром списка, а не действием интерфейса.

## 11. Ссылки на архивные объекты

Уже сохраненные ссылки на архивные объекты должны продолжать отображаться.

Пример:

```text
Документ ссылается на справочник.
Позже справочник архивировали.
Карточка документа должна продолжать показывать эту ссылку.
```

При выборе нового значения архивные объекты по умолчанию не предлагаются.

То есть runtime должен различать:

```text
отображение уже сохраненной ссылки
  архивный объект видим по правам

выбор нового ссылочного значения
  архивный объект скрыт по умолчанию
```

## 12. Режим только для просмотра у архивных объектов

Архивный объект доступен для просмотра по правам.

Обычное редактирование архивного объекта запрещено.

Исключения должны быть явно описаны:

- восстановление из архива;
- workflow-переход;
- специальная административная операция;
- изменение технических данных в техническом режиме.

Прикладной модуль не должен молча разрешать обычное редактирование архивного объекта.

## 13. Мягкое удаление

Мягкое удаление означает, что объект исключен из обычной рабочей модели.

При мягком удалении должны быть установлены:

```text
IsDeleted = true
DeletedAtUtc = текущее время UTC
DeletedBy = текущий инициатор
DeleteReason = причина, если она передана
```

Мягкое удаление доступно только если тип объекта явно разрешил:

```text
DeleteCapability = SoftDelete
```

Если `DeleteCapability = Disabled`, удаление запрещено.

## 14. Видимость удаленных объектов

Обычные запросы должны исключать удаленные объекты:

```text
IsDeleted = false
```

Это правило применяется к:

- спискам;
- поиску;
- lookup;
- выбору ссылочного значения;
- обычному открытию карточки по `Id`.

Разработчики прикладных модулей не должны вручную добавлять фильтр `IsDeleted = false` в каждый список.

Object Runtime применяет это правило системно.

Для временных рядов и telemetry момент события хранится отдельно как
`OccurredAtUtc`, а момент приема системой - как `IngestedAtUtc`. Эти правила
будут определены при подготовке будущей capability Time Series / Telemetry
Storage; текущие правила модулей не зависят от несуществующего хранилища.

## 15. IncludeDeleted

Для технических сценариев вводится режим:

```text
IncludeDeleted
```

Он предназначен для:

- администрирования;
- аудита;
- восстановления;
- проверки ссылочной целостности;
- технических расследований.

Семантика:

```text
обычный запрос:
  IsDeleted = false

IncludeDeleted = true:
  активные + удаленные

IncludeDeleted = true + IsDeleted = true:
  только удаленные
```

`IncludeDeleted` не должен показываться как обычный пользовательский фильтр списка.

## 16. Физическое удаление

Физическое удаление означает удаление записи из хранилища.

Оно допустимо только если тип объекта явно разрешил:

```text
DeleteCapability = HardDelete
```

Физическое удаление должно применяться осторожно.

Для значимых бизнес-объектов предпочтительно:

```text
архивирование
или SoftDelete
```

Физическое удаление допустимо только для объектов, где это безопасно:

- временные технические записи;
- импортные буферы;
- дочерние строки без самостоятельного бизнес-смысла;
- данные, для которых явно разрешено физическое удаление.

Перед физическим удалением должна быть проверка ссылочной безопасности.

Если есть сомнение, физическое удаление запрещается.

## 17. Права на удаление

Удаление должно проверять отдельное право:

```text
{ModuleCode}.{ObjectTypeCode}.Delete
```

Право:

```text
*.Edit
```

не должно автоматически разрешать удаление.

Если у пользователя нет права `*.Delete`, runtime не должен показывать или выполнять стандартное действие удаления.

## 18. Удаление и workflow

Workflow не является обязательной частью удаления.

Если тип объекта не использует workflow, удаление определяется:

- `DeleteCapability`;
- правами;
- правилами проверки;
- настройками коллекций.

Если тип объекта использует workflow, удаление не должно обходить жизненный цикл объекта.

Для workflow-объекта удаление может быть разрешено только если это явно предусмотрено:

- правилами состояния;
- workflow-командой;
- специальным правилом типа объекта.

## 19. Удаление строк коллекций

Удаление строки коллекции и удаление самостоятельного объекта - разные операции.

Настройки коллекции отвечают на вопрос:

```text
что делать со строкой в контексте владельца
```

`DeleteCapability` отвечает на вопрос:

```text
можно ли удалить тип объекта как самостоятельную сущность
```

Если строка коллекции является частью владельца, она может удаляться по правилам коллекции.

Если строка коллекции является самостоятельным `CommonObject`, ее удаление должно быть согласовано с `DeleteCapability` целевого типа объекта.

## 20. Архивирование и удаление

Архивирование и удаление нельзя использовать как взаимозаменяемые механизмы.

Архив:

```text
объект остается бизнес-фактом
виден по сохраненным ссылкам
может открываться на просмотр
скрыт из активных списков по умолчанию
может быть восстановлен, если это разрешено
```

Удаление:

```text
объект исключен из обычной рабочей модели
не показывается в обычных списках
не предлагается при выборе нового ссылочного значения
не открывается как обычный рабочий объект
доступен только в технических режимах, если это разрешено
```

Для справочников и основных бизнес-объектов пользовательская операция по умолчанию должна быть архивированием, а не удалением.

## 21. Audit History и события

Изменение системных состояний Common должно попадать в Audit History:

- создание;
- изменение;
- архивирование;
- восстановление;
- мягкое удаление;
- физическое удаление, если оно выполняется.

Для объектов с workflow архивирование и восстановление также должны отражаться в workflow history.

Публикация доменных или интеграционных событий зависит от конкретного типа объекта.

Common задает общую обязанность фиксировать значимые операции, но не навязывает всем объектам одинаковый набор событий.

## 22. Ошибки и запреты

Runtime должен возвращать ошибку, если:

- пользователь пытается архивировать тип объекта без действия `Archive` и без workflow-команды `Archive`;
- пользователь пытается восстановить тип объекта без действия `Restore` и без workflow-команды `Restore`;
- пользователь пытается удалить тип объекта с `DeleteCapability = Disabled`;
- пользователь пытается удалить объект без права `*.Delete`;
- пользователь пытается редактировать архивный объект без явно разрешенного сценария;
- пользователь пытается открыть удаленный объект в обычном режиме;
- физическое удаление нарушает или может нарушить ссылочную целостность.

Точные коды ошибок должны быть уточнены в backlog реализации Object Runtime.
