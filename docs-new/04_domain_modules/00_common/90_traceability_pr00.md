# Трассировка требований ПР00 - 00 Common

## 1. Назначение документа

Документ показывает, как требования из ПР00 отражаются в целевой модели модуля `00 Common`.

Трассировка нужна не для того, чтобы один к одному перенести все исходные классы и поля. Ее задача - явно зафиксировать:

- какие элементы ПР00 входят в Common v1;
- какие элементы перенесены с уточнением смысла;
- какие элементы не переносятся в базовые типы Common;
- какие решения добавлены по результатам анализа текущего кода и Object Runtime.

## 2. Источники

Основные источники:

- `DMP ПР00 Общие требования.docx`;
- `DMP ПР01 Общая НСИ.docx`;
- `DMP ПР09 Производственная логистика.docx` - только для настройки `DurationFormat`, вынесенной из старых параметров предприятия в Common и переименованной в целевой модели в `TimeAmountFormat`;
- текущий код модуля Common;
- текущие контракты Object Runtime;
- проектные решения по интеграционному модулю.

## 3. Краткий итог

Common v1 не копирует исходную модель ПР00 без изменений.

Целевая модель строится вокруг двух базовых типов:

```text
CommonObject
CommonCatalogObject : CommonObject
```

`CommonObject` задает общие технические признаки прикладного объекта: идентификатор, внешний идентификатор, поля создания и изменения, архивирование и мягкое удаление.

`CommonCatalogObject` добавляет к ним `Code` и `Name`. Эти поля есть только у справочных и классифицируемых объектов, которым действительно нужны код и наименование.

Статус из ПР00 не переносится в базовые типы Common. Для объектов со статусной моделью целевым механизмом должен быть workflow или отдельное объектное решение.

## 5. Что важно для согласования

Целевая модель Common v1 сознательно меньше и точнее исходной модели ПР00.

В базовый тип не попадают поля, которые нужны только части объектов: `Code`, `Name`, `Status`, `TenantId`, `SiteId`, `SourceSystemCode`.

В базовый тип попадают поля, которые должны одинаково обрабатываться Object Runtime для всех прикладных объектов: аудит, архивирование и мягкое удаление.

Если в дальнейшем появится общий шаблон workflow для статусных объектов, он должен развивать эту модель, а не возвращать общий `Status` в `CommonObject`.
