# Граница модуля - 01 General Master Data

## 1. Назначение документа

Документ фиксирует границу ответственности модуля `01_general_master_data`.

Документ отвечает на вопросы:

- какими объектами владеет GMD;
- какие объекты GMD только использует как внешние ссылки;
- какие требования ПР01 не входят в GMD v1;
- какие платформенные механизмы используются модулем, но не реализуются внутри него.

Состав полей и связей описывается в `02_domain_model.md`. Правила проверки описываются в `05_rules.md`.

## 2. Принцип границы

GMD владеет справочными объектами, признаками основных данных и общими политиками использования этих объектов.

Поле или объект не выносится из GMD только потому, что его будут использовать логистика, производство, склад, закупки или качество.

Поле не входит в GMD, если его смысл и правила проверки принадлежат конкретному другому модулю и без этого модуля поле нельзя корректно валидировать.

## 5. Элементы ПР01 вне GMD

Некоторые элементы ПР01 не становятся объектами GMD и покрываются платформенными возможностями.

| Элемент ПР01 | Решение |
|---|---|
| `NumeratorDescriptor` / `NumeratorDescription` | Не объект GMD. Правило нумерации относится к Platform Numbering. |
| `Numerator` / `NumeratorValue` | Не объект GMD. Счетчик выполнения относится к Platform Numbering. |
| `BarcodeTemplate` | Не объект GMD. Настройка машиночитаемой идентификации относится к общей платформенной возможности. |
| `BarcodeData` / `Barcode` | Не объект GMD. Присвоенный машиночитаемый идентификатор хранится общим механизмом идентификации. |

## 6. Внешние объекты и ссылки

GMD может ссылаться на объекты других модулей, но не становится их владельцем.

| Внешний объект или область | Как используется |
|---|---|
| `Lot` | Может быть владельцем партионного пересчета в `UnitOfOperation`, но сама партия не входит в GMD. |
| `TransportUnit` | Фактическая единица транспортировки с номером не входит в GMD. В GMD остается только `TransportUnitType`. |
| Производственная структура | Используется через ссылки на производственные подразделения, ресурсы или ответственных, если такие поля есть в политике НП. |
| Склады и ячейки | Используются как внешние ссылки для значений по умолчанию и политик НП. |
| Персонал | Используется как внешняя ссылка для ответственных лиц. |
| Документы, остатки и движения | Используют GMD как справочник, но не входят в GMD. |

## 7. Граница номенклатуры

`Nomenclature` входит в GMD как основная карточка номенклатурной позиции.

В GMD остаются:

- ЕИ как базовая основная единица измерения НП;
- группа и вид номенклатуры;
- общие признаки хранения, контроля партий, серийных номеров и срока годности;
- требование исполнения;
- набор упаковок;
- учет по единицам транспортировки;
- основные производственно-логистические политики и значения по умолчанию из ПР01.

Не входят в GMD:

- фактические остатки НП;
- движения НП;
- складские и производственные документы;
- операции с НП;
- состояние НП в конкретном заказе, партии, маршруте или документе.

По полям `IsMain` и `BlankSize` ожидается ответ аналитика. До получения ответа эти поля не используются как основание для других проектных решений.

## 8. Граница упаковок и единиц транспортировки

`PackSet` и `Pack` входят в GMD как справочная модель допустимых упаковок и правил пересчета.

GMD хранит:

- карточку набора упаковок;
- карточку упаковки;
- связь упаковки с `PackSet` или конкретной `Nomenclature`;
- единицу упаковки;
- пересчет упаковки через `UnitOfOperation`.

GMD не хранит в v1:

- фактические экземпляры упаковок;
- остатки и движения упаковок;
- правила складского размещения упаковок;
- паллетизацию;
- возвратность;
- габариты, объем и вес брутто, если эти характеристики относятся к логистическому сценарию.

`TransportUnitType` входит в GMD. `TransportUnit` как фактическая единица транспортировки не входит в GMD.

## 9. Граница серийных номеров

`SerialNumber` входит в GMD как реестр серийных номеров номенклатуры.

GMD хранит:

- связь серийного номера с номенклатурой;
- связь с исполнением, если она нужна;
- изготовителя или внешний источник, если это задано ПР01;
- уникальность серийного номера в пределах правил GMD.

GMD не хранит:

- остатки по серийному номеру;
- местонахождение;
- историю движений;
- производственное или складское состояние;
- историю контрольных операций.

## 10. Граница контрагентов

`Contractor`, `ContractorGroup`, `ContractorInContractorGroup` и `ContractorContact` входят в GMD v1.

GMD хранит простой справочник внешних субъектов и их базовые контакты.

В GMD v1 не входят:

- договоры;
- цены;
- условия поставки и оплаты;
- банковские реквизиты;
- структурированная адресная модель;
- проверки по государственным реестрам;
- CRM-сценарии;
- закупочная квалификация;
- история взаимодействий.

## 11. Платформенные механизмы вне GMD

| Механизм | Решение |
|---|---|
| Object Runtime | GMD публикует объекты через стандартный механизм выполнения операций с бизнес-объектами. Отдельный основной API по ПР01 не проектируется. |
| Механизм жизненного цикла | Подключается только для объектов, которым нужен жизненный цикл подготовки, публикации и архивации. |
| ValueSetData | Используется для общих списков значений. Локальные списки значений реквизитов НП остаются в `NomenclatureParameterEnumValue`. |
| Platform Numbering | Используется для автоматической нумерации поддерживаемых полей. Правила и счетчики не входят в GMD. |
| Машиночитаемая идентификация | Используется как общая возможность для объектов GMD. Шаблоны и присвоенные идентификаторы не входят в GMD. |
| Integration Foundation | Отвечает за полноценное сопоставление объектов с внешними системами. `ExternalId` в GMD не заменяет эту модель. |
| Audit History | Отвечает за полную историю изменений. GMD хранит только текущие поля аудита через Common. |
