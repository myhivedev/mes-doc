# Права доступа - 03 Plant Structure

## 1. Назначение документа

Документ фиксирует проектное решение по доступу к объектам модуля `03 Plant Structure`: какие объекты защищаются самостоятельными правами, какие роли вводятся для модуля и какие особые правила доступа применяются.

Документ не описывает кнопки интерфейса, стандартные действия Object Runtime и внутреннюю реализацию Tenant Security.

## 2. Принципы доступа

Модуль использует стандартную модель прав Object Runtime:

| Действие | Смысл |
|---|---|
| Просмотр | Пользователь может видеть объект в списках, карточках и списках выбора. |
| Создание | Пользователь может создать новый объект. |
| Изменение | Пользователь может изменить существующий объект. |
| Удаление | Пользователь может удалить или архивировать объект в рамках правил модуля. |

Жизненный цикл защищается отдельно от изменения карточки:

| Действие | Смысл |
|---|---|
| Просмотр жизненного цикла | Пользователь видит состояние объекта и доступные переходы. |
| Выполнение перехода | Пользователь может выполнить разрешенный переход жизненного цикла. |

Собственные специальные permission-коды модуля не вводятся.

Доступ к `OrganizationalUnit` как abstract/reference-only типу определяется через конкретный тип записи:

- для `ProductionUnit` применяются права на `ProductionUnit`;
- для `Subcontractor` применяются права на `Subcontractor`;
- общий список выбора `OrganizationalUnit` показывает только те записи, которые пользователь имеет право читать как конкретные объекты.

## 3. Самостоятельно защищаемые объекты

| Объект | Русское название | Стандартные права | Жизненный цикл | Основание |
|---|---|---|---|---|
| `ProductionUnit` | Производственная единица | Просмотр, создание, изменение, удаление | Да | Ведется самостоятельным списком и карточкой. |
| `Subcontractor` | Субподрядчик | Просмотр, создание, изменение, удаление | Да | Ведется самостоятельным списком и карточкой. |
| `Company` | Организация | Просмотр, создание, изменение, удаление | Нет | Ведется самостоятельным списком и карточкой. |
| `OrganizationalUnitInventoryParameters` | Параметры места хранения | Просмотр, изменение | Нет | Ведется из карточки места хранения. Создание и физическое удаление выполняет системная синхронизация владельца; прямые create/delete/archive не предоставляются. |
| `StorageArea` | Зона хранения | Просмотр, создание, изменение, удаление | Нет | Ведется самостоятельным списком и карточкой. |
| `WarehouseBinType` | Тип складской ячейки | Просмотр, создание, изменение, удаление | Нет | Ведется самостоятельным списком и карточкой. |
| `WarehouseBin` | Складская ячейка | Просмотр, создание, изменение, удаление | Нет | Ведется самостоятельным списком и карточкой. |

`OrganizationalUnit` не является самостоятельным объектом назначения прав для создания и изменения, потому что экземпляры создаются только как `ProductionUnit` или `Subcontractor`.

## 4. Прикладные роли

| Роль | Код роли | Назначение | Область действия | Базовый доступ |
|---|---|---|---|---|
| Администратор производственной структуры | `PlantStructureAdmin` | Полное ведение объектов модуля. | Предприятие (tenant) | Все стандартные права и права жизненного цикла на объекты модуля. |
| Пользователь производственной структуры | `PlantStructureUser` | Просмотр производственной структуры, организаций, мест хранения, зон и ячеек. | Предприятие (tenant) | Просмотр самостоятельных объектов модуля. |
| Ответственный за производственную структуру | `PlantStructureResponsible` | Ведение производственных единиц, субподрядчиков и организаций. | Предприятие (tenant) | Ведение производственных единиц, субподрядчиков и организаций; выполнение жизненного цикла производственных единиц и субподрядчиков. |
| Ответственный за места хранения | `PlantStructureStorageResponsible` | Ведение параметров мест хранения, зон, типов ячеек и складских ячеек. | Предприятие (tenant) | Просмотр организационных единиц; ведение объектов складской детализации. |

Удаление и архивирование объектов в рабочих ролях не включается по умолчанию. Такое право назначается администратору производственной структуры или отдельной роли сопровождения.

## 5. Матрица доступа

В матрице используются сокращения:

| Сокращение | Состав прав |
|---|---|
| Просмотр | Просмотр объекта. Для объектов с жизненным циклом также просмотр состояния жизненного цикла. |
| Ведение | Просмотр, создание и изменение объекта. |
| Жизненный цикл | Выполнение переходов жизненного цикла. |
| Все действия | Просмотр, создание, изменение, удаление и жизненный цикл, если он есть у объекта. |

| Объект | Администратор производственной структуры | Пользователь производственной структуры | Ответственный за производственную структуру | Ответственный за места хранения |
|---|---|---|---|---|
| Производственные единицы | Все действия | Просмотр | Ведение, жизненный цикл | Просмотр |
| Субподрядчики | Все действия | Просмотр | Ведение, жизненный цикл | Просмотр |
| Организации | Все действия | Просмотр | Ведение | Просмотр |
| Параметры места хранения | Все действия | Просмотр | Просмотр | Ведение |
| Зоны хранения | Все действия | Просмотр | Просмотр | Ведение |
| Типы складских ячеек | Все действия | Просмотр | Просмотр | Ведение |
| Складские ячейки | Все действия | Просмотр | Просмотр | Ведение |

Право `Ведение` параметров места хранения не отменяет жизненный цикл владельца. `PlantStructureStorageResponsible` может изменять `OrganizationalUnitInventoryParameters` только у `ProductionUnit` или `Subcontractor` в состоянии `Draft`. Роль не получает переход `ReturnToDraft`; перевод опубликованного владельца в черновик выполняет `PlantStructureResponsible` или администратор с соответствующим правом жизненного цикла.

Для строки `Параметры места хранения` значение `Ведение` в матрице означает просмотр и изменение существующей зависимой записи. Оно не включает прямые создание, удаление или архивирование.

## 6. Особые правила доступа

| Сценарий | Правило доступа |
|---|---|
| Выбор `Contractor` в `Company` или `Subcontractor` | Пользователь должен иметь право чтения `Contractor` в `01_general_master_data`. |
| Выбор `OrganizationalUnit` как места хранения | Пользователь должен иметь право чтения конкретной записи `ProductionUnit` или `Subcontractor`. |
| Выбор `WarehouseBin` | Пользователь должен иметь право чтения складской ячейки и ее места хранения. |
| Изменение опубликованного объекта | Выполняется по правилам `04_workflows.md`: объект сначала возвращается в черновик, если для него включен жизненный цикл. |
| Изменение параметров места хранения | Требуется право изменения `OrganizationalUnitInventoryParameters` и право просмотра организационной единицы, для которой ведутся параметры. |
| Изменение зон и ячеек места хранения | Требуется право изменения соответствующего объекта складской детализации и право просмотра организационной единицы, используемой как место хранения. |

## 7. Техническое отображение

Технические решения для реализации:

| Элемент | Решение |
|---|---|
| Код модуля | `PlantStructure` |
| Область действия прав | Предприятие (tenant) |
| Кто может назначать права | Администратор предприятия (tenant) |
| Область назначения ролей | Предприятие (tenant) |
| Корпоративные роли | Не вводятся в v1. |

Модуль не вводит собственную модель разграничения данных по площадкам. Объекты модуля не имеют `SiteId`, поэтому платформенный `Site` scope не используется как область назначения ролей ПР03 в v1. Если площадочная видимость понадобится внедрению, она проектируется отдельным правилом сопоставления объектов модуля с платформенным `Site` и не заменяет производственную структуру модуля.
