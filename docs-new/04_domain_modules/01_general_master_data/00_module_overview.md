# Обзор модуля - 01 General Master Data

## 1. Назначение модуля

`01_general_master_data` - прикладной модуль DMP для ведения общей НСИ и основных данных, которые используются производственными, складскими, логистическими, закупочными, контрольными и другими процессами.

Модуль владеет справочными объектами и общими политиками их использования. Модуль не выполняет производственные, складские или логистические операции.

## 2. Термины и имена классов

Термины GMD используются по исходным требованиям и тематическому глоссарию `../../11_glossary/manufacturing_terms.md`.

В проектных документах техническое имя класса указывается на английском языке, а русское название объекта - рядом с ним. В `02_domain_model.md` для этого используется отдельная колонка.

## 3. Базовые проектные решения

Модуль строится поверх решений `00_common`.

Это означает:

- справочные объекты с `Code` и `Name` наследуются от `CommonCatalogObject`;
- не-каталоговые и связующие объекты наследуются от `CommonObject`;
- `Status` из ПР01 не переносится как обязательное поле всех объектов;
- `Presentation` не хранится как обязательное физическое поле;
- `ExternalId` используется как поле совместимости с внешними источниками;
- записи, которыми владеет GMD, относятся к предприятию и явно хранят `TenantId`;
- архивирование и мягкое удаление выполняются по правилам Common.

## 4. Граница ответственности

GMD отвечает за бизнес-смысл и правила справочных данных.

GMD не заменяет:

- Object Runtime;
- механизм жизненного цикла;
- ValueSetData;
- Platform Numbering;
- механизм машиночитаемой идентификации;
- Integration Foundation;
- производственную логистику;
- производственную структуру;
- управление складами, остатками, движениями и документами.

Если объект GMD используется другим модулем, это не делает поле или объект внешним. Поле остается в GMD, если оно описывает сам справочный объект, общий признак основных данных или общую политику его использования.

## 5. Основные зависимости

Модуль опирается на:

- `00 Common`;
- Business Object Runtime / Object Runtime;
- ValueSetData для общих списков значений;
- Platform Numbering для автоматической нумерации поддерживаемых полей;
- общий механизм машиночитаемой идентификации объектов;
- IAM для прав доступа;
- Audit History для истории изменений;
- Integration Foundation для полноценного сопоставления с внешними системами.

Полная ответственность этих механизмов остается в соответствующих платформенных модулях.

## 6. Что входит в GMD v1

В GMD v1 входит ведение:

- единиц измерения;
- групп единиц измерения;
- единиц измерения операций;
- номенклатурных групп;
- номенклатуры;
- исполнений номенклатуры;
- серийных номеров;
- наборов упаковок;
- упаковок;
- типов единиц транспортировки;
- видов номенклатуры;
- реквизитов номенклатуры и их назначений;
- локальных значений перечислимых реквизитов;
- значений реквизитов НП, исполнений НП и серийных номеров как строк коллекций Object Runtime;
- контрагентов;
- групп контрагентов;
- контактов контрагентов.

## 7. Что не входит в GMD v1

В GMD v1 не входит:

- заявки на изменение НСИ, согласования и история по заявкам;
- фактические партии как операционные объекты;
- фактические единицы транспортировки с номерами;
- остатки, движения, складские документы и производственные документы;
- физические характеристики упаковки, если они относятся к логистическим сценариям;
- договоры, цены, банковские реквизиты и расширенная модель сторон, контрагентов и CRM-функций;
- правила нумерации и счетчики выполнения нумераторов;
- шаблоны и значения машиночитаемых идентификаторов как собственные объекты GMD;
- отдельный слой API, копирующий API ПР01 вместо Object Runtime.

## 8. Связь с требованиями

Источник требований модуля: `../../00_governance/requirements/001_dmp_functional_requirements_and_constraints.md`, раздел `01 Общая НСИ и основные данные (General Master Data)`.

Основные идентификаторы: `REQ-01-B-001..REQ-01-B-011`, `REQ-01-C1-001..REQ-01-C1-002`, `LIM-01-O-001..LIM-01-O-004`.

Детальная трассировка требований ведется в `01_scope.md`.
