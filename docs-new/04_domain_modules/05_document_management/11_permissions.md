# Права доступа — Управление документацией

## 1. Назначение документа

Документ определяет защищаемые объекты, наследование доступа для строк связей, роли и особые серверные проверки.

## 2. Принципы доступа

- область действия прав — текущее предприятие (`TenantId`);
- у объектов нет поля «Площадка» (`SiteId`), поэтому права не являются площадочными;
- сервер проверяет право независимо от интерфейса;
- роль «Администратор модуля „Управление документацией“» включает роль «Работа с документами»;
- недоступная связанная запись не раскрывается в данных или сообщении об ошибке.

## 3. Самостоятельно защищаемые объекты

| Объект | Русское название | Стандартные права | Жизненный цикл | Основание |
|---|---|---|---|---|
| Документ (`Document`) | Документ | просмотр, создание, изменение | Черновик / Опубликован / Архив | Основной бизнес-объект. |
| Каталог документов (`DocumentFolder`) | Каталог документов | просмотр, создание, изменение, архивирование | стандартное архивирование | Самостоятельный классификатор. |
| Тип документа (`DocumentType`) | Тип документа | просмотр, создание, изменение, архивирование | стандартное архивирование | Самостоятельный классификатор. |
| Содержимое документа (`DocumentContent`) | Содержимое документа | просмотр; изменение только через прикладные операции | мягкое удаление | Переиспользуемый корневой объект. |
| Хранилище документов (`DocumentStorage`) | Хранилище документов | нет пользовательского управления в MVP | системная запись | Пользовательские хранилища относятся к целевому расширению после MVP. |

## 4. Строки, защищаемые через владельца

| Строка или объект | Владелец | Как проверяется доступ |
|---|---|---|
| Связь документа с содержимым (`DocumentContentLink`) | Документ (`Document`) | Требуется доступ к документу; открытие содержимого дополнительно требует доступа хотя бы к одному связанному документу. |
| Связь документа с бизнес-объектом (`DocumentObjectLink`) | Документ (`Document`) | Требуется доступ к документу и право просмотра связанной записи. |
| Навигационный список версий | Документ (`Document`) | Каждая версия проверяется как самостоятельный документ. |

## 5. Роли

| Роль                                                                  | Назначение                                                                   | Область действия | Базовый доступ                                                   |
| --------------------------------------------------------------------- | ---------------------------------------------------------------------------- | ---------------- | ---------------------------------------------------------------- |
| Просмотр документов                                                   | Просмотр документов, версий, связей и доступного содержимого.                | предприятие      | просмотр объектов модуля                                         |
| Работа с документами                                                  | Создание и изменение документов, жизненный цикл, версии, содержимое и связи. | предприятие      | включает роль «Просмотр документов»                              |
| Администратор модуля «Управление документацией» | Ведение каталогов, типов документов, хранилищ и настроек. | предприятие | включает роль «Работа с документами» |

## 6. Матрица доступа ролей

| Объект или действие | Просмотр документов | Работа с документами | Администратор модуля «Управление документацией» |
|---|:---:|:---:|:---:|
| Просматривать документы и версии | да | да | да |
| Открывать и скачивать содержимое | да | да | да |
| Создавать и изменять черновик | нет | да | да |
| Копировать и создавать новую версию | нет | да | да |
| Управлять содержимым и связями | нет | да | да |
| Публиковать и возвращать в черновик | нет | да | да |
| Архивировать и восстанавливать документ | нет | да | да |
| Изменять ответственных | нет | да, отдельное разрешение | да, отдельное разрешение |
| Вести каталоги и типы | нет | нет | да |
| Вести хранилища и настройки | нет | нет | настройки да; хранилища после MVP |

## 7. Особые правила доступа

- в опубликованный и архивный документ нельзя внести изменения, в том числе в содержимое документа;
- пользователь может открыть содержимое документа, если ему доступен для просмотра хотя бы один документ, к которому это содержимое прикреплено;
- создание связи с записью бизнес-объекта требует роли «Работа с документами» и права просмотра документа;
- изменение полей «Ответственное подразделение» (`ProductionUnitResponsible`) и «Ответственный» (`ResponsibleEmployeeId`) требует отдельного разрешения для роли «Работа с документами»;
- секреты провайдера хранения доступны только защищённой платформенной конфигурации.

## 8. Техническое отображение

| Предметное действие | Технический шаблон |
|---|---|
| Просмотр документа | стандартное право чтения типа «Документ» (`DocumentManagement:Document`) |
| Создание и изменение черновика | стандартные права создания и изменения типа «Документ» плюс проверка состояния |
| Переход жизненного цикла | право роли «Работа с документами» и команда платформенного жизненного цикла |
| Управление содержимым | право изменения документа и прикладная операция над связью |
| Открытие содержимого | право чтения содержимого через доступный связанный документ |
| Ведение каталогов и типов | стандартные права роли «Администратор модуля „Управление документацией“» |
| Ведение настроек | право платформенной студии настроек для роли «Администратор модуля „Управление документацией“» |

## 10. Права для Content Storage

Право на действие модуля и право чтения ресурса проверяются раздельно.
Document Management регистрирует owner policy для `Read`, `Attach` и `Detach`;
замена и очистка поля в MVP реализуются последовательностью этих операций.
Видимость элемента интерфейса не заменяет серверную проверку.
