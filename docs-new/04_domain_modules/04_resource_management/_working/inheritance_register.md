# Рабочий реестр наследования и физического владения ПР04

Реестр фиксирует различие между логическим наследованием ПР04 и физическим хранением целевой модели. Он используется перед подготовкой `02_domain_model.md` и `03_object_runtime_model.md`.

| Логический базовый тип | Concrete-типы | Реальная общая ссылка / lookup | Физическое решение v1 | Обоснование |
|---|---|---|---|---|
| `ResourceBase` | `WorkPlace`, `Personnel`, `ToolBase` | Общей ссылки на любой ресурс нет; `ToolBase` имеет отдельный подтвержденный контракт | Parent table не создается; общие поля входят в контракты наследников | Логическое наследование не создает общий прикладной реестр |
| `ResourceGroupBase` | `WorkPlaceGroup`, `PersonnelGroup` | Общего lookup любой группы нет | Отдельные concrete tables | Группы рабочих мест и сотрудников используются раздельно |
| `ResourceInResourceGroupBase` | `WorkPlaceInWorkPlaceGroup`, `PersonnelInPersonnelGroup` | Общей ссылки на строку членства нет | Parent table не создается | Строки принадлежат конкретной группе и конкретному типу ресурса |
| `ToolBase` | `Tooling`, `Gage` | `ProcessToolingPositionBase.Tooling` в ПР02 | Общее физическое хранилище с discriminator | Реальная полиморфная ссылка ПР02 требует объединенного lookup |
| `ResourceLocationBase` | `WorkPlaceLocation`, `PersonnelLocation` | Общего lookup местоположений нет | Parent table не создается; поля входят в concrete tables | Владельческие ссылки различаются; `Previous` остается в concrete типе |
| `ResourceWorkSchedule` | Concrete назначения графика | Общей ссылки на назначение графика нет | Parent table не создается; отдельная таблица для каждого владельца | Назначение определяется типом владельца |

## Внешние владельцы

| Объект | Владелец | Что делает ПР04 |
|---|---|---|
| `OrganizationalUnit` / `ProductionUnit` / `Subcontractor` | ПР03 / GMD по принятой модели | Хранит ссылку и использует организационный контекст |
| `EquipmentUnit` | Внешний модуль оборудования / MDC по принятой границе | Хранит внешнюю ссылку в `WorkPlace`; не создает объект автоматически |
| Документы и файлы | ПР05 | Использует документные связи; не хранит документ, файл или его версию |
| Нормативные ресурсные позиции | ПР02 | Предоставляет объекты, lookup и проверки для ссылок ПР02 |

## Источник структуры данных

Фактический путь сверки структуры данных:

```text
C:\@WORK\@СИГМА\01 РАЗРАБОТКА\02 Требования\01 Проектные решения\DMP_DATA
```

`DMP_DATA` уточняет исходное mapping, но не отменяет принятые решения о границе владения и физическом хранении.
