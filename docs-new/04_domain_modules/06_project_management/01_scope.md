# Граница модуля - 06 Управление проектами

## 1. Назначение документа

Документ фиксирует границу ответственности PR06 `06_project_management`.

Документ определяет:

- какие объекты принадлежат PR06;
- какие данные PR06 предоставляет другим модулям;
- какие внешние объекты PR06 только использует через ссылки;
- какие требования исходного ПР06 входят в MVP, а какие отложены;
- какие функции не должны дублироваться в PR07, PR05, PR03, PR04 и плановых модулях.

Состав полей и связей описывается в [02_domain_model.md](02_domain_model.md), Object Runtime - в [03_object_runtime_model.md](03_object_runtime_model.md), а предметные проверки - в [05_rules.md](05_rules.md).

## 2. Что входит в модуль

| Область | Входит | Комментарий |
|---|---:|---|
| Ведение проектов | да | PR06 создает и изменяет `Project` как самостоятельный бизнес-объект, а не как справочник PR07. |
| Ведение этапов проектов | да | PR06 создает и изменяет `ProjectPhase`, принадлежащий проекту. |
| Общие реквизиты проекта и этапа | да | Поля логического `ProjectBase`: код, наименование, описание и ответственность. |
| Иерархия этапов | да | Неограниченное структурное дерево через `ProjectPhase.Parent` внутри одного проекта. |
| Проектная аналитика | да | `Project` и `ProjectPhase` предоставляются как ссылки для внешних объектов планирования и учета. |
| Согласованность пары проект / этап | да | Lookup этапа фильтруется по проекту; при выборе этапа проект подставляется автоматически. |
| Ответственность | да | Внутреннее ответственное подразделение, ответственный сотрудник и организационная единица-исполнитель. |
| Исполнитель-субподрядчик | да | `ExecutorOrganizationalUnit` может ссылаться на `ProductionUnit` или `Subcontractor`. |
| Архивирование и удаление | да | Используются стандартные операции Object Runtime с предметными проверками зависимостей. |
| Ведение кодов затрат | да | PR06 ведет самостоятельный иерархический каталог `CostCode` в пределах tenant. |
| Связи с документами | частично | К проекту или этапу можно прикреплять существующие документы через document links PR05; документы PR06 не создает. |

## 3. Что не входит в модуль

| Область | Не входит | Где должно быть описано |
|---|---|---|
| Высокоуровневый план проекта | Этапы с плановыми датами, ожидаемыми результатами и длительностью как элементы плана. | Будущий проектный план / планирование |
| Работы проекта | Работы, связи между работами, календарно-сетевой график и критический путь. | Будущий проектный план / планирование |
| План-факт | Плановые и фактические показатели, проценты выполнения, внутренние графики выполнения этапов. | Будущие варианты и версии плана проекта |
| Baseline | Версии базового плана и фиксация контрольной версии. | Будущий проектный план |
| Контрольные точки | Milestone / контрольная точка как элемент календарно-сетевого плана. | Будущий проектный план |
| Прикладной workflow | Состояния и переходы публикации, утверждения или контроля проекта и этапа. | Не создается в MVP; используется Object Runtime |
| Связь кода затрат с проектом или этапом | Назначение `CostCode` непосредственно проекту или этапу. | Не входит в MVP; внешние объекты могут хранить собственные ссылки на `CostCode`. |
| Заказы | Заказы и позиции заказов. | PR07 |
| Документы и файлы | Документы, версии, содержимое, хранилища и создание файлов. | PR05 |
| Производственная структура | Производственные единицы, субподрядчики и организационные единицы. | PR03 |
| Сотрудники | Сотрудники как самостоятельные объекты. | PR04 |
| Финансы проекта | Бюджеты, сметы, плановые и фактические затраты, KPI и финансовые лимиты. | Будущий финансовый / проектный контур |

## 4. Граница с соседними модулями

| Модуль | Граница взаимодействия |
|---|---|
| `00_common` | PR06 использует общие поля, tenant-границу, мягкое удаление, архивирование, восстановление и стандартное поведение Object Runtime. |
| `01_general_master_data` | Внешние модули могут использовать `ProjectManagement:CostCode`; PR06 владеет каталогом кодов затрат и его иерархией. |
| `03_plant_structure` | PR06 использует `ProductionUnit`, `OrganizationalUnit` и `Subcontractor`. PR03 владеет этими объектами. |
| `04_resource_management` | PR06 использует `Personnel` для ссылки на ответственного сотрудника. PR04 владеет сотрудниками. |
| `05_document_management` | PR06 использует document links для связи с существующими документами. Создание и жизненный цикл документов принадлежат PR05. |
| `07_order_management` | PR06 владеет проектом и этапом. PR07 владеет заказами и хранит ссылки на `Project` и `ProjectPhase`; ведение проекта в PR07 исключается. |
| `08_planning_scheduling` | Будущие плановые объекты используют проект и этап как аналитические измерения. План проекта не входит в MVP PR06. |
| Учет и логистика | Потребляющие объекты используют проект и этап в своих аналитиках; поля и операции этих объектов принадлежат их модулям. |

Межмодульные ссылки передаются через публичные API, события или Object Runtime-контракты. PR06 не обращается напрямую к таблицам соседних модулей.

## 5. Соответствие функциональным требованиям

Источник требований: исходное проектное решение `DMP ПР06 Управление проектами_исх. ТР v0.1.docx` и раздел PR06 в `../../00_governance/requirements/001_dmp_functional_requirements_and_constraints.md`.

| Требование | Статус покрытия | Решение / документ |
|---|---|---|
| `REQ-06-B-001` | `частично` | Ведение `Project` и `ProjectPhase` входит в PR06. Контрольные точки не входят в MVP и относятся к будущему плану проекта. |
| `REQ-06-B-002` | `не входит в v1` | Высокоуровневый план по этапам, срокам и ожидаемым результатам отложен. |
| `REQ-06-B-003` | PR06 | PR06 ведет tenant-owned каталог `CostCode` с иерархией; прямой связи с `Project` и `ProjectPhase` нет. |
| `REQ-06-B-004` | `частично` | PR06 предоставляет `Project` и `ProjectPhase` как аналитические ссылки. Поля внешних объектов и их учетные правила принадлежат модулям-потребителям. |
| `REQ-06-B-005` | `не входит в v1` | Версии базового плана не входят в MVP. |
| `REQ-06-B-006` | `не входит в v1` | Прикладной контроль состояния проекта и этапа не входит в MVP. |

Фрагмент исходного ПР06 о создании документа из интерфейса «Работа с документами» исключается из PR06. Прикрепление существующего документа к проекту или этапу остается внешней связью через PR05.

## 6. Ограничения версии

В текущей версии PR06:

- `Project` и `ProjectPhase` являются единственными объектами владения модуля;
- `ProjectBase` является только логическим общим предком и не публикуется как runtime object type;
- прикладные `Status` и workflow не переносятся из DMP_DATA;
- сроки, результаты, работы, план-факт, baseline, контрольные точки и бюджеты не моделируются;
- `CostCode` не добавляется непосредственно в проект и этап; внешние потребители используют самостоятельные ссылки на каталог PR06;
- ответственности и исполнитель не являются обязательными;
- значения ответственности этапа не наследуются автоматически от проекта;
- архивирование допускается при внешних ссылках, а удаление блокируется при зависимостях;
- новые lookup-ссылки выбирают только активные объекты, но архивные сохраненные ссылки отображаются;
- отдельный глобальный пункт меню для этапов не создается;
- отдельный `04_workflows.md` не создается.

Подробные отличия от исходного ПР и DMP_DATA приведены в [90_traceability_pr06.md](90_traceability_pr06.md).
