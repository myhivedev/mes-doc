# Runtime-модель объектов - 06 Управление проектами

## 1. Назначение документа

Документ определяет публикацию `Project`, `ProjectPhase` и `CostCode` через Object Runtime, правила представления, lookup-ограничения, иерархию и подключенные возможности платформы.

Предметные поля и связи определены в [02_domain_model.md](02_domain_model.md), пользовательские представления - в [06_ui_views.md](06_ui_views.md), а прикладные операции - в [13_operations.md](13_operations.md).

## 2. Базовое решение

- `Project` и `ProjectPhase` являются самостоятельными типами Object Runtime;
- `CostCode` является самостоятельным tenant-owned типом Object Runtime;
- `ProjectBase` не публикуется как runtime object type;
- все выборки ограничены текущим предприятием (`TenantId`);
- архивные и удаленные записи не входят в обычные lookup, но ранее сохраненные ссылки могут их отображать;
- представление объекта формируется из `Code` и `Name` через общий механизм Object Runtime;
- коллекции `Phases` и `Children` являются навигационными и не создают отдельный составной объект.

## 3. Объявляемые типы объектов

| Тип объекта | Русское название | Доступность через Object Runtime | Примечание |
|---|---|---|---|
| `ProjectManagement:Project` | Проект | список, карточка, создание, изменение, архивирование, восстановление, удаление | Объект-владелец проекта; удаление проверяет этапы и внешние ссылки. |
| `ProjectManagement:ProjectPhase` | Этап проекта | карточка, создание, изменение, архивирование, восстановление, удаление | Объект этапа; принадлежит проекту и поддерживает иерархию. |
| `ProjectManagement:CostCode` | Код затрат | список, карточка, lookup, создание, изменение, архивирование, восстановление, удаление | Иерархический каталог PR06; записи принадлежат текущему tenant. |

`ProjectManagement:ProjectBase` не является типом Object Runtime и не имеет собственного набора permissions.

## 4. Правила представления объектов

| Тип объекта | Правило представления | Источник |
|---|---|---|
| `Project` | Код проекта и наименование проекта | `Code` + `Name` |
| `ProjectPhase` | Код этапа и наименование этапа | `Code` + `Name` |
| `CostCode` | Код затрат и наименование | `Code` + `Name` |

Архивность, техническое состояние и идентификаторы не заменяют бизнес-представление и показываются по общим правилам Object Runtime.

## 5. Объекты

### 5.1. Project

| Элемент | Решение |
|---|---|
| Тип объекта | `ProjectManagement:Project` |
| Представления | `Project_ListView`, `Project_DetailView`, `Project_LookupView` |
| Коллекции | `Phases` - режим `Навигация` |
| Особые обработчики | Проверка кода и наименования, проверка зависимостей при archive/delete, открытие дерева этапов проекта. |

Ссылочные поля:

| Поле | Источник значений | Ограничение выбора |
|---|---|---|
| `ResponsibleProductionUnit` | `PlantStructure:ProductionUnit` | Активная внутренняя производственная единица текущего предприятия. |
| `ResponsiblePerson` | `ResourceManagement:Personnel` | Доступный сотрудник текущего предприятия. |
| `ExecutorOrganizationalUnit` | `PlantStructure:OrganizationalUnit` | Активная `ProductionUnit` или `Subcontractor` текущего предприятия. |

Коллекции Object Runtime:

| Владелец | Коллекция | Тип строки | Режим | Комментарий |
|---|---|---|---|---|
| `Project` | `Phases` | `ProjectPhase` | `Навигация` | Показывает этапы проекта и позволяет перейти к карточке этапа. Создание и изменение выполняются операциями `ProjectPhase`. |

### 5.2. ProjectPhase

| Элемент | Решение |
|---|---|
| Тип объекта | `ProjectManagement:ProjectPhase` |
| Представления | `ProjectPhase_DetailView`, `ProjectPhase_LookupView` |
| Коллекции | `Children` - режим `Навигация` |
| Особые обработчики | Фильтрация проекта и родителя, проверка принадлежности дереву, запрет циклов, проверка зависимостей при archive/delete. |

Ссылочные поля:

| Поле | Источник значений | Ограничение выбора |
|---|---|---|
| `Project` | `ProjectManagement:Project` | Активный проект текущего предприятия. При выборе этапа в другом контексте заполняется автоматически. |
| `Parent` | `ProjectManagement:ProjectPhase` | Активный этап того же проекта; текущий этап и его потомки исключаются из выбора. |
| `ResponsibleProductionUnit` | `PlantStructure:ProductionUnit` | Активная внутренняя производственная единица текущего предприятия. |
| `ResponsiblePerson` | `ResourceManagement:Personnel` | Доступный сотрудник текущего предприятия. |
| `ExecutorOrganizationalUnit` | `PlantStructure:OrganizationalUnit` | Активная `ProductionUnit` или `Subcontractor` текущего предприятия. |

Коллекции Object Runtime:

| Владелец | Коллекция | Тип строки | Режим | Комментарий |
|---|---|---|---|---|
| `ProjectPhase` | `Children` | `ProjectPhase` | `Навигация` | Показывает непосредственных дочерних этапов. Создание и изменение выполняются операциями `ProjectPhase`. |

### 5.3. CostCode

| Элемент | Решение |
|---|---|
| Тип объекта | `ProjectManagement:CostCode` |
| Представления | `CostCode_ListView`, `CostCode_DetailView`, `CostCode_LookupView` |
| Коллекции | `Children` - режим `Навигация` |
| Особые обработчики | Фильтрация по tenant, проверка родителя, запрет циклов, проверка зависимостей при archive/delete. |

Ссылочные поля:

| Поле | Источник значений | Ограничение выбора |
|---|---|---|
| `Parent` | `ProjectManagement:CostCode` | Активный код того же tenant; текущий код и его потомки исключаются из выбора. |

Коллекции Object Runtime:

| Владелец | Коллекция | Тип строки | Режим | Комментарий |
|---|---|---|---|---|
| `CostCode` | `Children` | `CostCode` | `Навигация` | Показывает непосредственных дочерних кодов затрат. |

## 6. Подключенные возможности платформы

| Возможность | Решение модуля | Статус зависимости |
|---|---|---|
| Object Runtime | Публикация трех типов объектов, стандартные mutation-команды, lookup и технические данные. | используется |
| Tenant-aware ссылки | Проверка принадлежности всех объектов текущему предприятию. | используется |
| Иерархические объекты | Чтение деревьев `ProjectPhase` и `CostCode`, выбор родителя с исключением текущего узла и потомков. | используется; контракт платформы |
| Архивирование и восстановление | Общие операции Object Runtime с прикладными проверками дочерних объектов. | используется |
| Мягкое удаление | Удаление не уничтожает запись физически; перед операцией проверяются внутренние и внешние зависимости. | используется |
| Проверка внешних ссылок | Проверка использования проекта, этапа или кода затрат объектами других модулей. | требуется общий межмодульный контракт |
| Concurrency | Изменения выполняются с общей защитой от одновременного изменения. | используется |
| Workflow Engine | Для `Project`, `ProjectPhase` и `CostCode` не подключается в MVP. | не используется |

## 7. Граница с интерфейсом

Сценарии начинаются со списка `Project` или списка `CostCode`. В карточке проекта отображается навигационное дерево `ProjectPhase`, а в разделе кодов затрат - дерево `CostCode`. Отдельный пункт меню для этапов не создается, но карточка этапа доступна из дерева и из внешних lookup.

Колонки, фильтры, вкладки, команды и порядок элементов интерфейса определены в [06_ui_views.md](06_ui_views.md). Этот документ не дублирует конкретную раскладку формы.
