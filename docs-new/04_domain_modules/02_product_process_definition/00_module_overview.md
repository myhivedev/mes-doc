# Обзор модуля - 02 Составы и технологии

## 1. Назначение модуля

Модуль `02 Product & Process Definition` / `Составы и технологии` ведет нормативные данные, которые описывают из чего и как изготавливается, ремонтируется, разбирается или испытывается продукция.

Модуль является источником:

- спецификаций и составов изделия;
- технологических описаний и попередельных маршрутов;
- нормативных технологических операций;
- материальных позиций переделов и операций;
- нормативных позиций оборудования, персонала и технологической оснастки;
- мест использования технологических документов и материалов;
- схем кооперации;
- правил замены номенклатуры;
- результатов анализа состава.

## 2. Базовое решение

Основная единица управления в модуле - конкретная ревизия нормативного документа:

```text
ManufacturingBill Rev.1
ManufacturingBill Rev.2

ProcessDefinition Rev.1
ProcessDefinition Rev.2

CooperationScheme Rev.1
CooperationScheme Rev.2
```

Ревизия имеет:

- доменную ревизионность через `Initial`, `Revision`, `ExternalRevision`;
- период действия `ValidFrom` / `ValidTo`;
- области использования `UseInPlanning`, `UseInProduction`, `UseInCosting`, `AllowNewOperationalSelection`;
- условия применимости;
- жизненный цикл `ProcessDocumentLifecycle`.

Workflow не является бизнес-фильтром продуктивного подбора. Алгоритмы подбора используют хранимые признаки Common/Object Runtime, области использования, период действия, условия применимости и совместимость связанных ревизий.

## 3. Что входит в модуль v1

| Область | Объекты |
|---|---|
| Настройки шаблонов | `ManufacturingBillTemplate`, `ProcessTemplate` |
| Классификаторы технологии | `LabourType`, `ProcessingOperation`, `ManufacturingOperationType`, `WorkEnvironment` |
| Спецификации | `ManufacturingBill`, `ManufacturingBillPosition` |
| Технологические описания | `ProcessDefinition`, `ProcessSegment`, `ProcessOperation`, материальные позиции, позиции оборудования, персонала, оснастки и связанный документный контекст технологического описания |
| Кооперация | `CooperationScheme`, `CooperationSchemePosition` |
| Условия применимости | единый `UseCondition` в коллекциях условий владельцев |
| Замены номенклатуры | `NomenclatureSubstitution` |
| Анализ состава | `ProductComposition`, `ProductCompositionParameterValue`, `ProductCompositionPosition` |
| Системные перечисления | fixed SystemEnum модуля, описанные в `02_domain_model.md` |

## 4. Что не входит в модуль v1

Модуль не владеет:

- номенклатурой, единицами измерения, исполнениями НП и контрагентами;
- производственной структурой, производственными единицами, местами хранения, зонами и ячейками;
- справочниками оборудования, рабочих мест, персонала, инструмента, оснастки, календарями и мощностями;
- документами, файлами, версиями файлов, URL-хранилищем и электронным архивом;
- производственными заказами, заданиями, WIP, фактическими операциями и движениями материалов.

Такие объекты используются как внешние ссылки или будущие зависимости, но не становятся владением модуля.

## 5. Основные зависимости

| Модуль | Как используется |
|---|---|
| `00_common` | Common-поля, архивирование, удаление, Object Runtime, стандартная видимость архивных/удаленных объектов. |
| `01_general_master_data` | Номенклатура, исполнения НП, единицы измерения, единицы операции, контрагенты, `NomenclatureObtainMethod`, `ProcessType`. |
| `03_plant_structure` | Производственные единицы, организационные единицы, субподрядчики, места хранения и складские ячейки; зоны хранения учитываются через данные складской ячейки. |
| `Resource Management` | Справочники ресурсов, рабочих мест, оборудования, персонала, профессий, групп оплаты, календарей, мощностей и доступности. |
| `Document Management` | Документы, файлы, версии, хранилища, права, жизненный цикл документов и связи документов с бизнес-объектами. |
| Планирование / APS | Использует ревизии с `UseInPlanning = true`. |
| Производственные заказы | Используют ревизии с `UseInProduction = true`. |
| Калькуляция | Использует ревизии с `UseInCosting = true`. |
