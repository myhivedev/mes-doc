# Прикладные функции — Управление документацией

## 1. Назначение документа

Документ определяет составные операции модуля, которые содержат предметный алгоритм сверх стандартного создания, сохранения, чтения и переходов жизненного цикла.

## 2. Общие принципы

- каждая операция проверяет предприятие, права, состояние и обязательные данные на сервере;
- операция выполняется целиком, если для множественной загрузки явно не установлен результат по каждому файлу;
- стандартные переходы жизненного цикла описаны в [04_workflows.md](04_workflows.md) и здесь не повторяются;
- программные результаты и категории ошибок определены в [08_api_contracts.md](08_api_contracts.md).

## 3. Данные, используемые функциями

| Пользовательские данные | Технические данные | Назначение |
|---|---|---|
| Документ | документ (`Document`) | владелец содержимого, связей и цепочки версий |
| Содержимое документа | содержимое (`DocumentContent`) | файл, ссылка или текст |
| Связь документа с содержимым | связь (`DocumentContentLink`) | порядок и признак основного содержимого |
| Связь документа с бизнес-объектом | связь (`DocumentObjectLink`) | универсальная ссылка на запись внешнего модуля |
| Метка изменения | `ConcurrencyToken` Object Runtime | защита от перезаписи более новой версии данных |

## 4. Создать новую версию

Назначение функции: создать новый черновик той же цепочки версий.

Входные данные: опубликованный документ.

Алгоритм:

1. Проверить право, состояние и актуальность исходного документа.
2. Определить первую версию и следующий номер версии.
3. Создать черновик с тем же номером документа и ссылкой на первую версию.
4. Перенести бизнес-поля, связи с записями объектов и связи с содержимым.
5. Заполнить системные сведения по текущему пользователю и времени.

Результат: идентификатор нового черновика; исходный документ не изменяется.

## 5. Копировать документ

Назначение функции: создать самостоятельный документ версии 1.

Входные данные: исходный документ и признаки переноса связей с бизнес-объектами и содержимого.

Алгоритм:

1. Проверить право просмотра исходного документа и право создания нового.
2. Сформировать новый номер документа.
3. Скопировать тип, каталог, наименование, комментарий и ответственных.
4. Показать два независимых признака: «Перенести связи с бизнес-объектами» и «Перенести содержимое документа». Для каждого признака пользователь выбирает «Да» или «Нет»; по умолчанию установлено «Нет». При выборе «Да» создать для копии новые связи с теми же записями бизнес-объектов или с теми же записями содержимого. Сами бизнес-объекты и содержимое не копировать.
5. Заполнить новые системные сведения; историю и внешний идентификатор не копировать.

Результат: самостоятельный черновик версии 1.

## 6. Загрузить файлы

Назначение функции: создать содержимое вида «Файл» (`Binary`) и связать его с документом.

Входные данные: документ либо запись бизнес-объекта и набор файлов.

Алгоритм:

1. Определить существующий документ или создать один документ для всех файлов по правилам внешней вкладки.
2. Для каждого файла проверить право, размер, расширение, тип содержимого и хранилище типа документа.
3. Сохранить допустимый файл выбранным способом и создать связь с документом.
4. Первое успешно прикреплённое содержимое назначить основным.

Результат: итог «Загружен» или «Не загружен» и причина отдельно по каждому файлу. Если обязательные данные нового документа определить нельзя, документ не создаётся и ни один файл не загружается.

## 7. Добавить ссылку

Назначение функции: создать содержимое вида «Ссылка» (`Url`).

Входные данные: документ либо запись бизнес-объекта, наименование и адрес HTTP/HTTPS.

Алгоритм:

1. Определить существующий документ или создать документ по правилам вкладки «Документы» в карточке записи бизнес-объекта.
2. Проверить адрес, создать неизменяемое содержимое и связь с документом. Сервер не загружает и не проверяет внешний ресурс.

Результат: созданные содержимое и связь; при необходимости — созданный документ. Если обязательные данные нового документа определить нельзя, документ, содержимое и связь не создаются.

## 8. Добавить текст

Назначение функции: создать содержимое вида «Текст» (`Text`).

Входные данные: документ либо запись бизнес-объекта, наименование и текст.

Алгоритм:

1. Определить существующий документ или создать документ по правилам вкладки «Документы» в карточке записи бизнес-объекта.
2. Создать содержимое и связь с документом; после первого прикрепления текст неизменяем.

Результат: созданные содержимое и связь; при необходимости — созданный документ. Если обязательные данные нового документа определить нельзя, документ, содержимое и связь не создаются.

## 9. Прикрепить содержимое документа

Назначение функции: переиспользовать существующее содержимое без копирования.

Входные данные: документ либо запись бизнес-объекта и выбранные записи содержимого.

Алгоритм:

1. Проверить доступ, предприятие, отсутствие мягкого удаления и дублирующей связи.
2. Если функция вызвана из карточки записи бизнес-объекта без документов, создать документ и связь документа с этой записью.
3. Создать связи выбранного документа с содержимым.

Результат: созданные связи; при необходимости — созданный документ.

## 10. Отвязать содержимое

Назначение функции: удалить связь документа с содержимым без нарушения остальных документов.

Входные данные: документ, содержимое и метка изменения.

Алгоритм:

1. Удалить связь документа с содержимым.
2. При необходимости переназначить основное содержимое.
3. Проверить связи этого содержимого с другими документами.
4. Если связей не осталось, сразу мягко удалить содержимое.

Результат: обновлённый состав содержимого и признак мягкого удаления. Все шаги выполняются одной целостной операцией.

## 11. Назначить основным

Назначение функции: изменить основное содержимое документа.

Входные данные: документ и выбранная связь с содержимым.

Алгоритм: установить выбранной связи признак основного содержимого и снять его с прежней связи в той же операции.

Результат: одна основная связь документа.

## 12. Прикрепить документ

Назначение функции: создать универсальную связь документа с записью другого модуля.

Входные данные: документ, квалифицированный код типа и строковый идентификатор записи.

Алгоритм: проверить регистрацию типа, существование записи, предприятие, право просмотра и отсутствие дубликата; создать связь.

Результат: созданная связь документа с бизнес-объектом.

## 13. Отвязать документ от записи бизнес-объекта

Назначение функции: удалить только связь документа и записи.

Входные данные: идентификатор связи.

Алгоритм: проверить право изменения документа и удалить строку связи.

Результат: документ и запись бизнес-объекта сохраняются без изменений.

## 14. Открыть содержимое

Назначение функции: вернуть данные в соответствии с видом содержимого.

Входные данные: содержимое и контекст доступного документа.

Результат:

- для файла — поток файла после проверки доступа;
- для текста — текст в режиме просмотра;
- для ссылки — адрес HTTP/HTTPS для открытия клиентом после предупреждения.

Скачивание файла и открытие ссылки записываются через `IAuditHistoryWriter` с action codes `DocumentManagement.Content.Download` и `DocumentManagement.Content.OpenUrl`.

## 15. Удалить содержимое

Назначение функции: мягко удалить содержимое, не связанное с документами.

Входные данные: содержимое из самостоятельного списка.

Алгоритм: проверить отсутствие связей; при наличии хотя бы одного документа отклонить операцию, иначе выполнить мягкое удаление.

Результат: мягко удалённое содержимое. Физическая очистка не входит в первую версию.

## 16. Предметные ошибки

| Ошибка | Условие |
|---|---|
| Недостаточно прав | Нет права на документ, содержимое или связанную запись. |
| Неверное состояние | Действие недоступно в текущем состоянии документа. |
| Объект другого предприятия | Объекты операции имеют разные значения предприятия (`TenantId`). |
| Конфликт изменения | Данные изменены после открытия карточки. |
| Недопустимый файл | Нарушены ограничения размера, расширения или типа содержимого. |
| Дублирующая связь | Такая связь документа уже существует. |
| Недоступная запись | Связанная запись отсутствует или недоступна пользователю. |
| Ошибка хранилища | Файл не удалось сохранить или прочитать выбранным способом. |

## 17. Использование другими модулями

Вкладка «Документы» в карточке записи внешнего модуля использует операции «Загрузить файлы», «Прикрепить содержимое документа» и «Прикрепить документ». Модуль-владелец записи передаёт квалифицированный код типа и идентификатор записи; предметные данные внешнего объекта модуль документов не копирует.

## 18. Отложенные решения

- дополнительные обязательные поля по типу документа через `DocumentTypeRequiredField` (`DM-Q-008`);
- пользовательские хранилища и расширенный жизненный цикл хранилищ (`DM-Q-024`);
- внешние providers и расширенная настройка размещения файлов (`DM-Q-025`).

## 19. Операции Content Storage

Модуль использует ограничения платформы: максимальный размер файла по умолчанию
100 МБ, время жизни сессии загрузки 30 минут и срок хранения незакреплённого
ресурса 24 часа. Настройки модуля могут только сузить политику; очистку и
миграции `platform_content` выполняет платформа.
