# Прикладные операции и алгоритмы - 01 General Master Data

## 1. Назначение документа

Документ описывает прикладные операции, функции и алгоритмы модуля `01 General Master Data`, которые используются самим GMD и другими модулями DMP.

Документ не описывает API, экраны и полную доменную модель. Объекты и поля описаны в `02_domain_model.md`, правила проверки - в `05_rules.md`, доступность объектов через Object Runtime - в `03_object_runtime_model.md`.

## 2. Общие принципы

В GMD большинство разделов документа являются переиспользуемыми прикладными функциями: они вызываются обработчиками Object Runtime, операциями GMD или модулями-потребителями.

Прикладная функция GMD описывает предметный алгоритм работы с основными данными.

GMD отвечает за:

- выбор допустимых единиц операции;
- определение единицы операции по умолчанию;
- проверку применимости единицы операции;
- пересчет количества по правилам `UnitOfOperation`;
- синхронизацию базовой единицы операции НП;
- формирование и проверку значений реквизитов НП.

Модули-потребители отвечают за:

- момент вызова функции;
- хранение количества в своих документах, остатках, заказах и операциях;
- реакцию на ошибки проверки;
- правила изменения своих открытых документов и операций.

## 3. Данные, используемые функциями пересчета

Функции используют следующие объекты GMD:

| Объект | Использование |
|---|---|
| `Nomenclature` | НП и ее базовая ЕИ `Unit`. |
| `Unit` | Единица измерения и точность количества. |
| `UnitGroup` | Общие пересчеты между ЕИ группы. |
| `UnitOfOperation` | Допустимая единица операции, коэффициент, точность, делимость, область применения и признак по умолчанию. |
| `PackSet` | Набор типовых упаковок НП. |
| `Pack` | Типовая или индивидуальная упаковка, для которой задан пересчет через `UnitOfOperation`. |
| `TransportUnitType` | Тип единицы транспортировки и правила вместимости по НП. |

Допустимые владельцы и цели `UnitOfOperation` описаны в `05_rules.md`.

## 4. Получение доступных единиц операции

Назначение функции: вернуть список единиц операции, которые можно выбрать для НП в заданном контексте.

Входные данные:

| Параметр | Назначение |
|---|---|
| `Nomenclature` | НП, для которой выбирается единица операции. |
| `ApplicationArea` | Область применения единицы операции из `UnitApplicationAreaFlags`: производство, закупки или сбыт. |
| `Lot` | Партия, если пересчет зависит от партии. |
| `PackSet` / `Pack` | Упаковочный контекст, если единица выбирается для упаковки. |

Алгоритм:

1. Найти активные `UnitOfOperation`, владельцем которых является указанная `Nomenclature`.
2. Если базовая ЕИ НП входит в группу ЕИ, дополнить список активными `UnitOfOperation` этой группы.
3. Если передана партия, дополнить список активными `UnitOfOperation`, владельцем которых является эта партия.
4. Если у НП указан `PackSet`, дополнить список единицами операции упаковок этого набора.
5. Если у НП есть индивидуальные упаковки, дополнить список единицами операции этих упаковок.
6. Оставить только записи, у которых `ApplicationArea` содержит требуемую область применения. Если `ApplicationArea` у `UnitOfOperation` не заполнено, запись считается применимой во всех областях.
7. Исключить архивные и удаленные записи.
8. Вернуть список с отображением по правилам `03_object_runtime_model.md`.

Результат: список допустимых `UnitOfOperation`.

Если список пуст, для указанного контекста нет допустимой единицы операции. Исключение возможно только для сценария, где модуль-потребитель явно разрешает работу в базовой ЕИ НП без выбора `UnitOfOperation`.

## 5. Определение единицы операции по умолчанию

Назначение функции: определить `UnitOfOperation`, которую нужно подставить в документ, заказ, операцию или строку данных по умолчанию.

Входные данные:

| Параметр | Назначение |
|---|---|
| `Nomenclature` | НП, для которой выбирается единица операции. |
| `ApplicationArea` | Область применения единицы операции из `UnitApplicationAreaFlags`. |
| `Lot` | Партия, если выбор зависит от партии. |
| `Pack` | Упаковка, если выбор выполняется внутри упаковочного сценария. |

Алгоритм:

1. Получить список доступных единиц операции по правилам раздела 4.
2. Найти активную запись с `IsDefault = true`, у которой `ApplicationArea` содержит требуемую область применения или не заполнено.
3. Если найдена одна запись, вернуть ее.
4. Если найдено несколько записей, вернуть ошибку настройки. Такая ситуация нарушает правила `05_rules.md`.
5. Если запись не найдена, вернуть базовую единицу операции НП.

Базовая единица операции НП - это запись:

```text
Nomenclature = текущая НП
ToUnit = Nomenclature.Unit
ConversionFactor = 1
IsDefault = true
```

## 6. Проверка применимости единицы операции

Назначение функции: проверить, можно ли использовать выбранную `UnitOfOperation` для заданной НП и области применения.

Входные данные:

| Параметр | Назначение |
|---|---|
| `Nomenclature` | НП операции. |
| `UnitOfOperation` | Выбранная единица операции. |
| `ApplicationArea` | Область применения единицы операции из `UnitApplicationAreaFlags`. |
| `Quantity` | Количество для проверки делимости и точности. |

Алгоритм:

1. Проверить, что `UnitOfOperation` активна и относится к тому же предприятию.
2. Проверить, что владелец `UnitOfOperation` применим к указанной НП: сама НП, партия этой НП, упаковка этой НП, набор упаковок этой НП или допустимый общий пересчет группы ЕИ.
3. Проверить, что `ApplicationArea` содержит требуемую область применения или не заполнено.
4. Проверить, что `ConversionFactor > 0`.
5. Если передано количество и `IsDivisible = false`, проверить отсутствие дробной части.
6. Если передано количество, проверить точность количества по `Precision`.

Результат: успешная проверка или предметная ошибка с причиной отказа.

## 7. Пересчет количества в базовую ЕИ НП

Назначение функции: перевести количество из выбранной единицы операции в базовую ЕИ НП.

Входные данные:

| Параметр | Назначение |
|---|---|
| `Nomenclature` | НП, базовая ЕИ которой используется как результат. |
| `UnitOfOperation` | Единица операции исходного количества. |
| `Quantity` | Исходное количество. |
| `ApplicationArea` | Область применения единицы операции для проверки допустимости. |

Алгоритм:

1. Проверить применимость `UnitOfOperation` по правилам раздела 6.
2. Если `UnitOfOperation.ToUnit = Nomenclature.Unit`, рассчитать `Quantity * ConversionFactor`.
3. Если `UnitOfOperation` описывает упаковку, раскрыть цепочку упаковок до ЕИ НП.
4. Если цепочка упаковок не приводит к базовой ЕИ НП, вернуть ошибку настройки.
5. Округлить результат по точности базовой ЕИ НП.

Результат: количество в `Nomenclature.Unit`.

## 8. Пересчет количества из базовой ЕИ НП

Назначение функции: перевести количество из базовой ЕИ НП в выбранную единицу операции.

Входные данные:

| Параметр | Назначение |
|---|---|
| `Nomenclature` | НП, базовая ЕИ которой является исходной. |
| `UnitOfOperation` | Целевая единица операции. |
| `BaseQuantity` | Количество в базовой ЕИ НП. |
| `ApplicationArea` | Область применения единицы операции для проверки допустимости. |

Алгоритм:

1. Проверить применимость `UnitOfOperation` по правилам раздела 6.
2. Найти общий коэффициент пересчета целевой единицы операции в базовую ЕИ НП.
3. Если коэффициент не найден или равен нулю, вернуть ошибку настройки.
4. Рассчитать `BaseQuantity / коэффициент`.
5. Округлить результат по точности `UnitOfOperation.Precision`.
6. Если `IsDivisible = false`, проверить, что результат не имеет дробной части.

Результат: количество в выбранной единице операции.

## 9. Пересчет через упаковки

Упаковка содержит количество в ЕИ или другую упаковку.

Поддерживаемые цепочки:

```text
Pack -> ToUnit
Pack -> ToPack -> ToUnit
Pack -> ToPack -> ToPack -> ToUnit
```

Алгоритм расчета коэффициента:

1. Начать с коэффициента текущей `UnitOfOperation`.
2. Если цель `ToUnit`, завершить цепочку.
3. Если цель `ToPack`, найти `UnitOfOperation` целевой упаковки.
4. Умножить текущий коэффициент на коэффициент найденной упаковки.
5. Повторять, пока цепочка не завершится `ToUnit`.
6. Если цепочка содержит цикл или не завершается ЕИ, вернуть ошибку настройки.

Целевая ЕИ завершенной цепочки должна приводиться к базовой ЕИ НП через допустимый пересчет GMD. Если такого пересчета нет, цепочка считается ошибочной.

## 10. Синхронизация базовой единицы операции НП

Назначение функции: поддерживать обязательную базовую запись `UnitOfOperation` для НП.

Функция выполняется обработчиком сохранения `Nomenclature` через Object Runtime.

При создании НП:

1. Создать `UnitOfOperation` владельца `Nomenclature`.
2. Заполнить `ToUnit = Nomenclature.Unit`.
3. Заполнить `ConversionFactor = 1`.
4. Заполнить `IsDefault = true`.
5. Не заполнять `ApplicationArea`: пустое значение означает применение во всех областях.
6. Заполнить `Precision` и `IsDivisible` по правилам базовой ЕИ.

При изменении `Nomenclature.Unit`:

1. Проверить допустимость смены базовой ЕИ по правилам `05_rules.md`.
2. Найти базовую `UnitOfOperation` НП.
3. Обновить `ToUnit`, `ConversionFactor`, `Precision` и `IsDivisible`.
4. Не менять другие дополнительные единицы операции автоматически.

## 11. Формирование и проверка значений реквизитов НП

Назначение функции: отобразить фактически созданные значения реквизитов владельца, предоставить допустимые варианты для новой строки и проверить их при сохранении.

Функция используется для владельцев:

| Владелец | Коллекция значений |
|---|---|
| `Nomenclature` | `ParameterValues` |
| `NomenclatureVariant` | `ParameterValues` |
| `SerialNumber` | `ParameterValues` |

Входные данные:

| Параметр | Назначение |
|---|---|
| `Owner` | Объект-владелец значений: НП, исполнение НП или серийный номер. |
| `OwnerLevel` | Уровень владельца: НП, исполнение НП или серийный номер. |
| `Nomenclature` | НП, по которой определяется вид НП и применимые назначения реквизитов. |
| `NomenclatureKind` | Вид НП, если он задан у НП. |
| `ExistingValues` | Уже сохраненные или введенные строки значений владельца. |

Алгоритм формирования списка и вариантов выбора для карточки НП:

1. Найти активные общие назначения реквизитов.
2. Если у НП задан `NomenclatureKind`, добавить активные назначения этого вида НП.
3. Добавить прямые активные назначения текущей НП.
4. Оставить только назначения, применимые к уровню владельца: НП, исполнение НП или серийный номер.
5. Показать только строки из `ExistingValues`; не создавать подготовленные строки для отсутствующих значений.
6. Для команды создания сформировать варианты из применимых общих и видовых назначений, а также из всех реквизитов с `AssignmentArea = Nomenclature`, у которых еще нет прямого назначения текущей НП.
7. Исключить реквизиты, уже присутствующие в сохраненных или несохраненных строках коллекции.
8. При выборе общего или видового реквизита перенести в строку идентификатор назначения, код, тип и типизированное значение по умолчанию назначения.
9. При выборе реквизита области `Nomenclature` заполнить код и тип, оставив назначение пустым до сохранения владельца.

Алгоритм проверки при сохранении:

1. Проверить, что реквизит строки входит в эффективный набор реквизитов владельца.
2. Проверить, что `AttributeCode` строки совпадает с `NomenclatureParameter.AttributeCode`.
3. Проверить применимость реквизита к уровню владельца.
4. Не применять `IsMandatory` до уточнения отдельного правила обязательности.
5. Проверить тип значения по `NomenclatureParameter.DataType`.
6. Проверить, что заполнено только одно типизированное поле значения, соответствующее типу значения.
7. Для `LocalEnum` проверить `ReferenceCode` по `NomenclatureParameterEnumValue.Number`.
8. Для `ValueSet` проверить `ReferenceCode` по Platform ValueSetData.
9. Проверить, что у одного владельца нет двух активных строк значения одного реквизита.
10. Для новой строки НП с реквизитом области `Nomenclature` в той же транзакции создать прямое назначение и связать с ним значение.
11. При удалении такой строки в той же транзакции удалить ее прямое назначение; для общего или видового реквизита удалить только строку значения.

Результат подготовки: фактически созданные строки значений для отображения и отдельный набор допустимых вариантов для новой строки.

Результат сохранения: сохраненные строки значений в коллекции владельца или предметная ошибка проверки.

Правила структуры строк значений описаны в `02_domain_model.md`. Правила валидности реквизитов, назначений и значений описаны в `05_rules.md`.

Для объектов других модулей используется тот же алгоритм определения применимых реквизитов. Тип элемента значения и таблица хранения принадлежат модулю-владельцу объекта.

## 12. Граница с платформенной функциональностью

Общий сценарий создания объекта на основании существующего, правила системных полей и интеграция с UI реализуются на уровне Object Runtime.

GMD разрешает корневой сценарий для `Nomenclature` (`CreateFromExistingUsage = Root`):

- обычные редактируемые скалярные и ссылочные поля предзаполняются стандартным механизмом Object Runtime;
- `Code` исходной НП не переносится, чтобы новая НП получила самостоятельный уникальный код;
- коллекции единиц операции, исполнений, серийных номеров, индивидуальных упаковок, назначений и значений реквизитов не переносятся, поскольку для них не задано явное `Include`;
- новая запись создается только после сохранения карточки пользователем и проходит обычные проверки создания GMD.

Для остальных типов объектов GMD сценарий остается выключенным (`CreateFromExistingUsage = None`) до появления отдельного предметного решения. GMD не регистрирует собственный provider: используется декларативная политика контракта и стандартная реализация Object Runtime.

## 13. Использование другими модулями

Модули-потребители используют функции GMD для единообразного выбора и пересчета количества.

Типовые потребители:

| Модуль-потребитель | Использование |
|---|---|
| Закупки | ЕИ заказа, поставки и приемки. |
| Производство | ЕИ производственного задания, выпуска, потребления материалов. |
| Склад и логистика | ЕИ складского документа, упаковки, отгрузки и перемещения. |
| Контроль качества | ЕИ измерений и контрольных операций, если они основаны на НП. |
| Планирование | Приведение потребностей и доступности к базовой ЕИ НП. |

Модуль-потребитель должен хранить свои операционные количества по своим правилам. GMD не хранит документы, остатки, резервы и движения.

## 14. Границы отдельных решений

| ID | Граница | Решение GMD |
|---|---|---|
| GMD-OP-001 | Партия принадлежит другому модулю. | Прикладная функция GMD принимает внешний контекст партии, но GMD не становится владельцем объекта `Lot`. |
| GMD-OP-002 | `UnitOfOperation.ApplicationArea` является флаговым перечислением `UnitApplicationAreaFlags`. | Базовая единица операции НП создается без заполнения `ApplicationArea`; пустое значение означает применение во всех областях единицы операции. |
