# Жизненный цикл - 01 General Master Data

## 1. Назначение документа

Документ фиксирует жизненный цикл объектов GMD, для которых в ПР01 требуется статусная модель `Черновик / Опубликованный / Архивный`.

GMD не вводит физическое поле `Status` во все объекты. Статусная модель реализуется как возможность типа объекта через Object Runtime и механизм жизненного цикла.

## 2. Объекты с жизненным циклом

| Тип объекта | Русское название | Почему нужен жизненный цикл |
|---|---|---|
| `Nomenclature` | Номенклатурная позиция | НП должна быть подготовлена до использования в документах, операциях и ссылках других объектов. |
| `NomenclatureKind` | Вид номенклатуры | Вид НП задает состав реквизитов и должен быть стабилен перед назначением НП. |
| `NomenclatureParameter` | Реквизит номенклатуры | Реквизит задает правило ввода значений и должен быть опубликован до применения в НП и видах НП. |

Остальные объекты GMD используют архивирование Common без отдельного жизненного цикла публикации.

## 3. Состояния

| Состояние | Русское название | Смысл | Выбор в новых ссылках |
|---|---|---|---|
| `Draft` | Черновик | Объект создается или настраивается. | Запрещен. |
| `Published` | Опубликованный | Объект разрешен к рабочему использованию. | Разрешен, если объект не архивирован и не удален. |
| `Archived` | Архивный | Объект выведен из активного использования. | Запрещен. |

Архивное состояние жизненного цикла синхронизируется с архивированием Common. Для объекта с жизненным циклом прямое изменение архивных полей Common не используется.

## 4. Переходы

| Команда | Из состояния | В состояние | Назначение |
|---|---|---|---|
| `Publish` | `Draft` | `Published` | Разрешить объект к рабочему использованию. |
| `ReturnToDraft` | `Published` | `Draft` | Вернуть объект на доработку. |
| `Archive` | `Draft`, `Published` | `Archived` | Вывести объект из активного использования. |
| `Restore` | `Archived` | `Draft` | Вернуть объект из архива на проверку и доработку. |

После `Restore` объект повторно проходит `Publish` перед рабочим использованием.

## 5. Правила переходов

Раздел описывает только прикладные проверки GMD. Выполнение команды, проверка прав, запись истории перехода и применение состояния выполняются платформенным механизмом жизненного цикла.

### 5.1 Публикация НП

Перед публикацией `Nomenclature` проверяется:

| Проверка | Правило |
|---|---|
| Обязательные поля | Заполнены обязательные поля НП из `02_domain_model.md`. |
| Базовая единица операции | Есть `UnitOfOperation` для основной ЕИ НП: `ToUnit = Nomenclature.Unit`, `ConversionFactor = 1`, `IsDefault = true`. |
| Единицы операции по умолчанию | Для одной области применения НП не задано больше одной единицы операции по умолчанию. |
| Вид НП | Если указан `NomenclatureKind`, он находится в состоянии `Published`. |
| Обязательные реквизиты | Для обязательных реквизитов НП есть строки значений, соответствующие типу реквизита. |
| Упаковки и тара | Упаковки, набор упаковок и правила вместимости проходят правила `05_rules.md`. |

В состоянии `Published` НП редактируется только через возврат в `Draft`.

### 5.2 Публикация вида НП

Перед публикацией `NomenclatureKind` проверяется:

| Проверка | Правило |
|---|---|
| Обязательные поля | Заполнены `Code` и `Name`. |
| Назначения реквизитов | Назначения реквизитов не содержат дублей. |
| Реквизиты | Все реквизиты, назначенные виду НП как действующие, находятся в состоянии `Published`. |
| Значения по умолчанию | Значения по умолчанию на назначениях соответствуют типу реквизита и источнику допустимых значений. |

В состоянии `Published` вид НП редактируется только через возврат в `Draft`.

### 5.3 Публикация реквизита НП

Перед публикацией `NomenclatureParameter` проверяется:

| Проверка | Правило |
|---|---|
| Обязательные поля | Заполнены код реквизита, наименование, тип данных, область применения и область присвоения. |
| Локальное перечисление | Если `AllowedValuesSource = LocalEnum`, задано хотя бы одно активное значение перечисления. |
| Общий список значений | Если `AllowedValuesSource = ValueSet`, указан `ValueSetCode`. |
| Назначения | Значения по умолчанию на назначениях соответствуют типу реквизита и источнику допустимых значений. |

В состоянии `Published` реквизит НП редактируется только через возврат в `Draft`.

## 6. Возврат на доработку

`ReturnToDraft` разрешается, если возврат не нарушает уже опубликованные данные GMD.

| Объект | Проверка GMD |
|---|---|
| `Nomenclature` | Нет опубликованных объектов GMD, где эта НП используется как обязательная ссылка. Дочерние строки самой НП не блокируют возврат, потому что дорабатываются вместе с НП. |
| `NomenclatureKind` | Нет опубликованных НП, которым назначен этот вид. |
| `NomenclatureParameter` | Нет активных назначений реквизита в опубликованном виде НП или опубликованной НП. Нет строк значений реквизита у опубликованных владельцев GMD. |

ПР01 не задает правила проверки входящих ссылок из других модулей при возврате объекта в черновик. В GMD такие проверки не проектируются.

## 7. Архивирование

`Archive` выводит объект из активного использования и запрещает выбор объекта в новых ссылках.

Перед архивированием проверяются правила GMD из `05_rules.md`: дочерние строки, обязательные ссылки и запреты удаления/архивирования для реквизитов НП.

Существующие ссылки на архивный объект сохраняются для чтения истории и ранее созданных данных.

## 8. Отображение в интерфейсе

Карточка объекта с жизненным циклом показывает:

| Элемент | Правило |
|---|---|
| Состояние | Текущее состояние жизненного цикла. |
| Команды переходов | Только команды, разрешенные из текущего состояния. |
| Рабочие поля | В `Published` и `Archived` доступны только для чтения. Для изменения нужен `ReturnToDraft` или `Restore`. |

Состав списков, карточек и фильтров описан в `06_ui_views.md`.
