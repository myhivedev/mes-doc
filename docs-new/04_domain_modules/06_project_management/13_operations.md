# Прикладные операции и алгоритмы - 06 Управление проектами

## 1. Назначение документа

Документ определяет составные операции PR06, которые содержат предметные проверки сверх стандартных операций Object Runtime.

Обычные создание, чтение, изменение, архивирование, восстановление и мягкое удаление выполняются стандартными командами Object Runtime с применением правил этого документа и [05_rules.md](05_rules.md).

## 2. Общие принципы

- стандартные проверки прав, предприятия и конкурентного изменения выполняются Object Runtime; операции PR06 определяют только прикладные предусловия и проверки;
- операции изменения дерева выполняются атомарно;
- внешние ссылки не переназначаются и не удаляются автоматически;
- ошибки не раскрывают данные объектов, к которым у пользователя нет права просмотра;
- `ProjectBase` не является входным или выходным объектом отдельной операции;
- операции будущего плана проекта, baseline, plan/fact и контроля исполнения в PR06 MVP отсутствуют.

## 3. Данные, используемые функциями

| Пользовательские данные | Технические данные | Назначение |
|---|---|---|
| Проект | `Project` | Владелец этапов и верхний уровень проектной аналитики. |
| Этап проекта | `ProjectPhase` | Узел структурного дерева и аналитическая ссылка. |
| Родительский этап | `ProjectPhase.Parent` | Проверка принадлежности дереву и запрет циклов. |
| Код затрат | `CostCode` | Владелец иерархического tenant-owned каталога кодов затрат. |
| Родительский код затрат | `CostCode.Parent` | Проверка принадлежности tenant и запрет циклов. |
| Ответственность | `ProductionUnit`, `Personnel`, `OrganizationalUnit` | Проверка ссылок на подразделение, сотрудника и исполнителя. |
| Внешние ссылки | контракты модулей-потребителей | Проверка использования объекта перед удалением. |
| Метка изменения | `ConcurrencyToken` Object Runtime | Защита от перезаписи более новой версии данных. |

## 4. Проверить согласованность проекта и этапа

Назначение функции: проверить и нормализовать пару `Project` / `ProjectPhase` во внешнем объекте, который использует оба аналитических поля.

Входные данные:

| Параметр | Назначение |
|---|---|
| `ProjectId?` | Выбранный проект. |
| `ProjectPhaseId?` | Выбранный этап. |
| `TenantId` | Предприятие операции. |

Алгоритм:

1. Убедиться, что переданные записи доступны в контексте текущего предприятия.
2. Если передан только `ProjectPhaseId`, получить его `ProjectId` и заполнить проект.
3. Если переданы оба значения, проверить, что `ProjectPhase.ProjectId = ProjectId`.
4. Если проект изменен и текущий этап относится к другому проекту, очистить этап в UI-контексте.
5. При серверном сохранении противоречивой пары отклонить операцию.

Результат: согласованная пара либо пустой этап при измененном проекте.

Ошибки:

| Ошибка | Условие |
|---|---|
| Недоступный объект | Проект или этап отсутствует, архивен для нового выбора или недоступен пользователю. |
| Несогласованный этап | Этап относится к проекту, отличному от выбранного. |
| Недоступный контекст | Запись недоступна в текущем предприятии или по правилам Object Runtime. |

## 5. Проверить и изменить положение этапа в дереве

Назначение функции: создать или переместить `ProjectPhase` с сохранением принадлежности проекту и без образования цикла.

Входные данные:

| Параметр | Назначение |
|---|---|
| `ProjectPhaseId?` | Изменяемый этап; отсутствует при создании. |
| `ProjectId` | Проект этапа. |
| `ParentId?` | Новый родительский этап. |
| `ConcurrencyToken` | Актуальная версия изменяемой записи. |

Алгоритм:

1. Проверить доступность проекта и родителя в текущем предприятии.
2. Проверить, что `Parent.ProjectId = ProjectId`.
3. При изменении существующего этапа исключить сам этап и всех его потомков из допустимых родителей.
4. Проверить отсутствие циклической цепочки родителей.
5. Сохранить этап и родительскую ссылку одной операцией.

Результат: сохраненный этап с допустимым родителем.

Ошибки:

| Ошибка | Условие |
|---|---|
| Неверный родитель | Родитель относится к другому проекту. |
| Цикл иерархии | Родителем выбран текущий этап или его потомок. |
| Недоступный объект | Проект или родитель недоступны в текущем контексте. |

## 6. Проверить и изменить положение кода затрат в дереве

Назначение функции: создать или переместить `CostCode` с сохранением tenant-границы и без образования цикла.

Входные данные:

| Параметр | Назначение |
|---|---|
| `CostCodeId?` | Изменяемый код; отсутствует при создании. |
| `TenantId` | Tenant операции. |
| `ParentId?` | Новый родительский код. |
| `ConcurrencyToken` | Актуальная версия изменяемой записи. |

Алгоритм:

1. Проверить доступность кода и родителя в текущем tenant.
2. При наличии родителя проверить его принадлежность тому же tenant.
3. При изменении исключить текущий код и всех его потомков из допустимых родителей.
4. Проверить отсутствие циклической цепочки родителей.
5. Сохранить код и родительскую ссылку одной операцией.

Результат: сохраненный `CostCode` с допустимым родителем.

Ошибки:

| Ошибка | Условие |
|---|---|
| Неверный родитель | Родитель относится к другому tenant. |
| Цикл иерархии | Родителем выбран текущий код или его потомок. |
| Недоступный объект | Код или родитель недоступны в текущем контексте. |

## 7. Проверить архивирование

Назначение функции: проверить предметные ограничения перед архивированием проекта, этапа или кода затрат.

Входные данные: тип объекта, идентификатор, предприятие и метка изменения.

Алгоритм:

1. Получить актуальную запись после стандартной проверки Object Runtime.
2. Для `Project` найти активные этапы этого проекта.
3. Для `ProjectPhase` найти активные дочерние этапы.
4. Для `CostCode` найти активные дочерние коды затрат.
5. Внешние ссылки не считать основанием для блокировки архивирования.
6. При отсутствии запрещающих активных дочерних объектов передать команду в стандартный механизм архивирования.

Результат: архивированный объект либо предметная ошибка.

Ошибки:

| Ошибка | Условие |
|---|---|
| Есть активные этапы | Архивируется проект, у которого есть неархивные этапы. |
| Есть активные дочерние этапы | Архивируется этап с неархивными детьми. |
| Есть активные дочерние коды | Архивируется `CostCode` с неархивными дочерними кодами. |

## 8. Проверить удаление

Назначение функции: не допустить мягкое удаление объекта, на который ссылаются внутренние или внешние записи.

Входные данные: тип объекта, идентификатор, предприятие и метка изменения.

Алгоритм:

1. Получить актуальную запись после стандартной проверки Object Runtime.
2. Для `Project` проверить отсутствие этапов.
3. Для `ProjectPhase` проверить отсутствие дочерних этапов.
4. Через межмодульный контракт проверить отсутствие внешних ссылок на объект.
5. При отсутствии зависимостей выполнить стандартное мягкое удаление.

Результат: мягко удаленный объект либо отказ с причиной.

Ошибки:

| Ошибка | Условие |
|---|---|
| Есть дочерние объекты | Проект имеет этапы или этап имеет дочерние этапы. |
| Есть внешние ссылки | Объект используется заказом, аналитикой, документом, логистикой или другим потребителем. |

Для `CostCode` удаление также блокируется при наличии дочерних кодов или внешних ссылок потребителей.

## 9. Использование другими модулями

Внешние модули используют `Project` и `ProjectPhase` через зарегистрированные типы Object Runtime и свои поля-ссылки. Они не вызывают внутреннюю модель PR06 напрямую и не получают доступ к таблицам PR06.

Внешние модули используют `CostCode` через собственные поля-ссылки на `ProjectManagement:CostCode`. Прямые назначения `CostCode` к `Project` или `ProjectPhase` PR06 не создает.

Для прикрепления уже существующего документа используется операция document links PR05. PR06 передает тип и идентификатор записи проекта или этапа, но не создает документ и файл.
