# Backlog - 02 Составы и технологии

## 1. Назначение

Документ фиксирует отложенные вопросы и расширения, которые не входят в v1 нормативной модели модуля 02.

## 2. Отложенные зависимости

| ID | Тема | Причина |
|---|---|---|
| `PPD-BL-001` | Детальные проверки ссылок на конкретные ресурсы, рабочие места, оборудование, персонал, инструмент и оснастку | Требуется согласование межмодульных контрактов с `ResourceManagement`; базовые ресурсные типы уже определены. |
| `PPD-BL-002` | Календари, мощности, доступность и расчет загрузки | Требуется `ResourceManagement` / планирование; справочники календарей и графиков уже принадлежат `ResourceManagement`, расчет доступности и загрузки остается внешним. |
| `PPD-BL-003` | Документы, файлы, версии файлов, предпросмотр, хранение и права на файл | Требуется Document Management. |
| `PPD-BL-004` | Детальные печатные формы спецификаций и технологий | Требуется отдельное проектирование выходных форм. |
| `PPD-BL-005` | Автоматическое закрытие старой ревизии при выпуске новой | В v1 старая ревизия не изменяется скрыто. |
| `PPD-BL-006` | Отдельное право "создавать новые ревизии" | В v1 используется стандартная связка `Read` исходной ревизии + `Create` нового объекта. |
| `PPD-BL-007` | Настраиваемые единицы пользовательского ввода для `RateFor...Time` на уровне операции или ресурса | В v1 временные нормы операций хранятся в секундах; UI использует `Common.TimeAmountFormat` (`Standard` = `hh:mm:ss`, `Industrial` = нормо-часы с тремя десятичными знаками), но не вводит отдельную ЕИ на уровне операции или ресурса. |
| `PPD-BL-008` | Собственные `ValueSet` модуля 02 | В v1 подтвержденных настраиваемых списков модуля 02 нет. |
| `PPD-BL-009` | Проверить оставшиеся будущие части архитектуры `Nomenclature` и связанных основных данных | Текущий пакет использует `Nomenclature` как внешний объект `01_general_master_data`; будущие специализированные запросы и расширение границы не добавляются без отдельного решения. |

## 3. Не возвращать без нового решения

Следующие изменения требуют отдельного обсуждения и изменения `90_traceability_pr02.md`:

- вернуть `Status == Approved` как бизнес-фильтр продуктивного подбора;
- ввести отдельные permission-коды на создание, изменение и удаление строк компонентов;
- проектировать Resource Management или Document Management внутри модуля 02;
- публиковать глобальный пользовательский список всех `UseCondition` как основной сценарий вместо вкладок владельцев;
- использовать workflow-состояние как скрытый фильтр планирования или производства.
