# Пользовательские представления — Управление документацией

## 1. Назначение документа

Документ определяет списки, карточки, вкладки, окна выбора, колонки, поиск, фильтры, сортировку и специальные действия интерфейса модуля.

## 2. Общие правила интерфейса модуля

- интерфейс скрывает недоступные действия, сервер повторно проверяет права и бизнес-правила;
- архивные записи по умолчанию не показываются;
- для документа фильтр состояния содержит «Все, кроме архивных», «Черновики», «Опубликованные», «Архивные», «Все состояния»;
- для классификатора без жизненного цикла документа используется только поддерживаемый признак архивирования;
- пустое состояние объясняет причину и допустимое следующее действие;
- ошибки и результаты составных операций показываются на русском языке;
- действия над выбранной строкой находятся на панели инструментов;
- общий поиск остаётся на основной панели списка, остальные фильтры находятся в раскрываемой панели «Фильтры»;
- кнопка «Фильтры» располагается непосредственно над раскрываемой панелью и управляет её показом;
- для пользователя сохраняются последнее выбранное представление документов, поиск, фильтры и сортировка.

## 3. Раздел «Документы»

Пункт навигации «Документы» открывает три переключаемых представления. При первом открытии показывается «Список документов». При повторном открытии восстанавливается последнее состояние пользователя.

## 4. Карточка документа (`DocumentManagement.DocumentDetail`)

| Параметр | Значение |
|---|---|
| Титул | Документ |
| Вид представления | Карточка |
| Код представления | `DocumentManagement.DocumentDetail` |
| Тип представления | Форма объекта (`ObjectForm`) |
| Объект данных | Документ (`Document`) |
| Режимы карточки | создание, изменение, просмотр |

Панель действий: «Сохранить», «Опубликовать», «Вернуть в черновик», «Копировать», «Создать новую версию», «Архивировать», «Восстановить», «Закрыть» — в зависимости от состояния и прав.

Вкладки и группы полей:

| Вкладка | Содержимое |
|---|---|
| Основное | номер документа, версия, состояние, дата документа, наименование, каталог, тип документа, ответственное подразделение, ответственный, комментарий; после комментария — список содержимого |
| Связанные объекты | связанные записи бизнес-объектов |
| Версии | первая и последующие версии одной цепочки |
| Администрирование | системные сведения только для чтения |

Поле «Состояние» является только представлением текущего состояния платформенного жизненного цикла. Отдельное поле «Статус» (`StatusCode`) не используется. Для опубликованного и архивного документа бизнес-поля доступны только для чтения.

Действие «Создать новую версию» не открывает отдельное окно. Для опубликованного документа система определяет первую версию и следующий номер версии, создаёт новый черновик и открывает его карточку.

Колонки и действия совпадают с областью содержимого раздела 3.2. Список расположен после поля «Комментарий».

Колонки: тип связанного бизнес-объекта, наименование связанной записи, идентификатор связанной записи, доступность связанной записи. Действия: «Связать с записью», «Открыть связанную запись», «Отвязать». Недоступная запись показывается как «Связанный объект недоступен» без раскрытия данных.

| Параметр | Значение |
|---|---|
| Вид представления | Вкладка связанного списка |
| Владелец | Документ (`Document`) |
| Список | первая и последующие версии одной цепочки |
| Условие списка | первая версия и документы, у которых ссылка на первоначальный документ указывает на неё |

### 4.5. Вкладка «Администрирование»

Системные сведения показываются по текущему состоянию записи только для чтения: внутренний идентификатор (`Id`), предприятие (`TenantId`), внешний идентификатор (`ExternalId`), создано (`CreatedAtUtc`), создал (`CreatedBy`), изменено (`ModifiedAtUtc`), изменил (`ModifiedBy`), архивировано (`IsArchived`), дата архивирования (`ArchivedAtUtc`), архивировал (`ArchivedBy`), причина архивирования (`ArchiveReason`), удалено (`IsDeleted`), дата удаления (`DeletedAtUtc`), удалил (`DeletedBy`), причина удаления (`DeleteReason`). Технический `ConcurrencyToken` используется сервером и отдельно пользователю не показывается.

| Параметр | Значение |
|---|---|
| Титул | Прикрепить содержимое документа |
| Вид представления | Список выбора |
| Код представления | `DocumentManagement.DocumentContentLookup` |
| Тип представления | Список выбора (`LookupListView`) |

Поиск выполняется по номеру и наименованию содержимого, имени файла, номеру и наименованию документа. Фильтры: вид содержимого и расширение. Действия: «Открыть содержимое» для одной строки, «Прикрепить» для одной или нескольких строк, «Отмена». Мягко удалённые и недоступные записи не показываются.

## 7. Вкладка «Документы» в карточке записи бизнес-объекта

| Параметр | Значение |
|---|---|
| Вид представления | Вкладка связанного списка |
| Владелец | Запись бизнес-объекта внешнего модуля |
| Список | Документы, связанные с текущей записью |
| Условие списка | тип и идентификатор текущей записи совпадают с данными связи документа |
| Строка списка | Документ (`Document`) |
| Режимы карточки | изменение и просмотр |

Колонки документов: номер документа, версия, наименование, состояние, каталог, тип документа, ответственное подразделение, ответственный. При выборе документа ниже показывается содержимое с колонками из раздела 3.2 без даты создания.

Действия над документом: «Создать документ», «Прикрепить документ», «Открыть документ», «Отвязать документ». Действия над содержимым: «Загрузить файлы», «Прикрепить содержимое документа», «Открыть содержимое», «Отвязать содержимое».

Если документов нет, загрузка или прикрепление создаёт один документ для всех выбранных файлов или записей содержимого, связывает его с текущей записью и создаёт связи с содержимым. Каталог — корневой «Документы». Если тип для вида бизнес-объекта не настроен, он создаётся автоматически с названием вида бизнес-объекта.

Если документы есть, пользователь сначала выбирает один документ. Новая запись документа не создаётся. Если документ не выбран, действия загрузки и прикрепления содержимого недоступны.

При множественной загрузке результат показывает для каждого файла имя, итог «Загружен» или «Не загружен» и причину ошибки. Если обязательные данные нового документа определить нельзя, документ не создаётся и файлы не загружаются.

| Объект данных | Каталог документов (`DocumentFolder`) |

Поля: код каталога, наименование каталога, вышестоящий каталог, порядок, состояние архивирования. Действия: «Сохранить», «Архивировать», «Восстановить», «Закрыть».

## 9. Типы документов

### 9.1. Список типов документов (`DocumentManagement.DocumentTypeList`)

| Параметр | Значение |
|---|---|
| Титул | Типы документов |
| Вид представления | Список |
| Код представления | `DocumentManagement.DocumentTypeList` |
| Тип представления | Список объектов (`ObjectList`) |
| Объект данных | Тип документа (`DocumentType`) |

Колонки: код типа документа, наименование, хранилище, максимальный размер файла, разрешённые расширения, состояние архивирования. Поиск: код или наименование. Фильтр архивирования по умолчанию исключает архивные записи. Сортировка пользовательская; группировка отсутствует. Действия: «Создать тип», «Открыть», «Архивировать», «Восстановить».

### 9.2. Карточка типа документа (`DocumentManagement.DocumentTypeDetail`)

| Параметр | Значение |
|---|---|
| Титул | Тип документа |
| Вид представления | Карточка |
| Код представления | `DocumentManagement.DocumentTypeDetail` |
| Тип представления | Форма объекта (`ObjectForm`) |
| Объект данных | Тип документа (`DocumentType`) |
| Режимы карточки | создание, изменение, просмотр |

Поля: код типа документа, наименование, хранилище, максимальный размер файла, разрешённые расширения файлов, состояние архивирования. Действия: «Сохранить», «Архивировать», «Восстановить», «Закрыть».

При создании обязательное поле «Хранилище» заполняется системным хранилищем «База данных». Пользовательский выбор другого хранилища не входит в MVP. Код типа формируется автоматически, обязателен и может быть изменён вручную только до создания первого документа этого типа.

## 10. Хранилища документов

Представление и действия хранилищ не публикуются в MVP. Системная запись «База данных» создаётся начальными данными модуля; пользовательские формы хранилищ относятся к целевому расширению после MVP.

## 11. Настройки предприятия

Настройки «Максимальный размер файла» и «Разрешённые расширения файлов» редактируются в платформенной студии настроек (Studio Settings). Системное хранилище «База данных» назначается начальными данными модуля; отдельные объект, форма и пункт меню модуля не создаются.

## 14. Работа с файлами в интерфейсе

Карточки и коллекции используют стандартные компоненты Frontend Platform. Для
скалярного свойства объекта типа `File` применяется `FileField`; для действия
«Загрузить файлы» с параметром `DataType=File`, `Multiple=true` применяется
`FileUploadParameter`.
Предметный модуль не реализует собственный компонент выбора файла, не знает
физическое хранилище и не отображает физический путь.

Для встроенной коллекции действие загрузки размещается в toolbar коллекции и
получает родительский контекст стандартным `EmbeddedCollectionContext`. После
завершения загрузки стандартный runtime обновляет список. Общая кнопка создания
строки не требуется, если строка коллекции предназначена только для ссылки на
ресурс; действия строки скачивания/открытия, назначения основным и отвязки
остаются обычными action-ами.

В карточке документа и в списке содержимого имя файла показывается как ссылка,
а размер, состояние и действия отображаются по правилам `FileField`/
`FileUploadParameter`. Для множественной загрузки результат показывается по
каждому файлу, включая частичную ошибку и повторную попытку.
