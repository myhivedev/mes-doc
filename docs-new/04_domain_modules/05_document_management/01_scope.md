# Граница модуля — Управление документацией

## 1. Назначение документа

Документ определяет ответственность модуля, его внешние ссылки и ограничения первой версии.

## 2. Что входит в модуль

| Область | Входит | Комментарий |
|---|---|---|
| Документы и версии | Да | Каждая версия является отдельной записью документа с общим номером. |
| Каталоги документов | Да | Модуль владеет иерархическим классификатором. |
| Типы документов | Да | Тип задаёт хранилище и ограничения файлов. |
| Содержимое документов | Да | Поддерживаются виды «Файл», «Ссылка» и «Текст». |
| Связи с бизнес-объектами | Да | Используется универсальная ссылка без физического внешнего ключа. |
| Хранилища документов | Да, в MVP минимально | Создаётся системное хранилище «База данных»; пользовательские провайдеры и полный жизненный цикл отложены. |
| Поиск и пользовательские представления | Да | Полнотекстовый поиск по содержимому не входит. |
| Настройки предприятия | Да | Значения регистрируются в платформенном механизме настроек. |

Объекты владения: «Документ» (`Document`), «Каталог документов» (`DocumentFolder`), «Тип документа» (`DocumentType`), «Хранилище документов» (`DocumentStorage`), «Содержимое документа» (`DocumentContent`), «Связь документа с содержимым» (`DocumentContentLink`) и «Связь документа с бизнес-объектом» (`DocumentObjectLink`). Отдельный объект «Настройки управления документацией» (`DocumentManagementSettings`) не создаётся.

## 3. Что не входит в модуль

| Область | Не входит | Где должно быть описано |
|---|---|---|
| Внешние системы управления документами | Интеграционные контракты и обмен | После отдельного решения по интеграции. |
| Электронная подпись и юридически значимый обмен | Подписание и доверенная доставка | Отдельный модуль электронного документооборота. |
| Распознавание и полнотекстовый поиск | Индексация содержания файлов | Отдельное решение поиска. |
| Терминалы сбора данных | Специальные терминальные сценарии | Требования терминальных приложений. |
| Физическое уничтожение файлов | Сроки хранения и окончательная очистка | Политика хранения и уничтожения. |
| Отчёты и печатные формы | Специальные выходные документы не определены | Новый документ создаётся после появления требований. |

## 4. Граница с соседними модулями

| Смысл ссылки | Объект-владелец | Решение модуля |
|---|---|---|
| Ответственное подразделение | Производственная структура / `ProductionUnit` | Выбираются неархивные внутренние производственные единицы текущего предприятия; субподрядчики исключаются. |
| Ответственный сотрудник | Управление ресурсами / «Сотрудник» (`Personnel`) | Выбирается доступный сотрудник текущего предприятия. |
| Связанный бизнес-объект | Модуль-владелец типа объекта | Модуль хранит квалифицированный код типа и строковый идентификатор, а существование и доступ проверяет среда выполнения объектов. |
| Провайдер хранения и секреты | Платформенная конфигурация | Модуль хранит только ссылку на зарегистрированное хранилище; секреты в предметные объекты не попадают. |

## 6. Ограничения версии

- Все объекты и связи ограничены текущим предприятием (`TenantId`).
- Актуальный проектный источник — `C:\DMP\deliverables\ФТ Управление документами v4.0.docx`; версия 3.2 используется только как исходная база трассировки.

- Для 95% операций с метаданными целевое время не превышает 2 секунд; до начала скачивания — не более 3 секунд; проверка файла до передачи — не более 2 секунд.
- Расчётный профиль — до 1 млн документов на предприятие и до 100 одновременно работающих пользователей.
- Дополнительные обязательные поля по типу документа, внешние хранилища и расширенный контракт хранилищ отложены после MVP; базовый сценарий работает с системным хранилищем «База данных».
- Аудит скачивания и открытия ссылок выполняется через общий writer аудита, а защита изменений использует `ConcurrencyToken` Object Runtime.

## 7. Граница Content Storage

В scope модуля входит использование platform file capability, но не реализация
бинарного provider. Модуль отвечает за Document/DocumentContent owner policy,
бизнес-права и metadata; Content Storage отвечает за bytes, TTL и stream.
