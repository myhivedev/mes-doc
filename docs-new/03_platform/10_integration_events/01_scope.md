# Граница платформенной области — Integration Events

## 1. Назначение документа

Документ фиксирует, за что отвечает `Integration Events`, а за что отвечают
модули-владельцы событий, host, Audit History и будущая Integration Capability.

## 2. Что входит

| Обязанность | Входит | Не входит | Соседний владелец | Основание |
| --- | --- | --- | --- | --- |
| Envelope события | `IntegrationEventEnvelope`, `EventTypeCode`, `TenantId`, `CorrelationId` и payload. | Семантика payload конкретного события. | Модуль-источник события | `03_contracts.md` |
| Outbox-хранилище | Сохранение, чтение и состояние `OutboxMessage`. | База бизнес-состояния модуля-источника. | Модуль-источник и его persistence | `02_architecture.md` |
| Фоновая обработка | Выбор обработчика по `EventTypeCode`, повторные попытки и dead letter. | Бизнес-обработка события. | Модуль-потребитель или host-приложение | `04_runtime.md` |
| Операторские операции | Получение dead letter-записей, повторная постановка и подтверждение. | HTTP API и UI оператора. | Host-приложение и фронтенд-платформа | `03_contracts.md`, `08_operations.md` |
| Служебный контекст | Передача `TenantId` и `CorrelationId` в envelope. | Авторизация по одному только `TenantId`. | Tenant/Security и host-приложение | `05_security_and_audit.md` |

## 3. Что не входит

- бизнес-смысл и схема полезной нагрузки конкретного события;
- API и команда, породившие событие;
- доменные сущности Tenant/Security, Workflow, Configuration или Object Runtime;
- Audit History и политика хранения аудита;
- внешний брокер, соединители и транспорт между окружениями;
- отдельная inbox-таблица дедупликации потребителей;
- реестр событий с политикой версий;
- UI для оператора и общая frontend-оболочка;
- поток интеграции, сопоставление, внешний идентификатор и состояние синхронизации.

Эти исключения не являются пропущенными частями области: для каждого из них
владелец указан в таблице границ ниже или в таблице раздела 4.

## 4. Граница с соседними областями и модулями

| Соседняя область | Владелец соседней части | Граница Integration Events |
| --- | --- | --- |
| `Tenant/Security` | Tenant, пользователь, роль и смысл прав | Публикует события через общий издатель; Integration Events не определяет их смысл |
| `Configuration` | Схема Configuration, области действия и проекция | Потребляет `TenantCreated` через зарегистрированный обработчик; создание области действия принадлежит Configuration |
| `Workflow` | Команда Workflow и смысл состояния | Публикует события Workflow; обработка смысла Workflow принадлежит Workflow или обработчику host-приложения |
| `Object Runtime` | Конвейер изменения и полезная нагрузка изменения | Публикует `ObjectRuntime.MutationCompleted`; Integration Events только сохраняет envelope |
| `Audit History` | Запись аудита и история | Обработка outbox не является записью аудита |
| `Foundation` | Общие технические типы и application-контракты | Использование общих типов не передаёт их владение Integration Events |
| `фронтенд-платформа` | Общая оболочка, маршрутизация и приложения | Собственного frontend-контракта здесь нет |
| будущая `Integration Capability` | Внешние системы, соединители и потоки обмена | Может использовать механизм доставки, но не входит в эту область |

## 5. Соответствие требованиям

Граница должна быть понятна по владельцу каждого контракта. Это не переносит
семантику модуля-источника в Integration Events.

| Требование | Покрытие | Решение | Документ-владелец |
| --- | --- | --- | --- |
| Общий envelope и outbox | Полностью | Контейнер, хранение и состояние принадлежат Integration Events. | `02_architecture.md`, `03_contracts.md` |
| Семантика события и payload | Частично | Контракт публикуется через общий envelope, но смысл задаёт модуль-источник. | Модуль-источник; `03_contracts.md` |
| Обработка события | Частично | Integration Events вызывает зарегистрированный обработчик; бизнес-результат принадлежит потребителю. | Потребитель и host-приложение; `04_runtime.md` |
| Операторская диагностика | Частично | Application-порт подтверждён, HTTP API и UI не подтверждены. | Host-приложение и фронтенд-платформа; `08_operations.md` |
| Внешняя доставка и дедупликация | Не подтверждено | В текущий MVP не входят. | Будущая Integration Capability; `90_traceability.md` |

## 6. Ограничения версии

Текущий механизм работает внутри host-приложения и постоянного хранилища. Наличие
outbox-записи не доказывает атомарность с сохранением бизнес-состояния, доставку
во внешнюю систему или защиту от повторного выполнения обработчика. Эти свойства
остаются отдельными вопросами и не считаются частью MVP-контракта без доказательства.
