# Термины фронтенд-платформы DMP

## 1. Назначение документа

Документ фиксирует рабочие русские термины, предпочтительные английские названия и технические
алиасы для платформенной области «фронтенд-платформа».

Термины Configuration, Object Runtime, Tenant Security и других областей здесь
не переопределяются. Если фронтенд использует такой термин в своём runtime-контексте,
глоссарий указывает границу и ссылается на владельца определения.

## 4. Границы с соседними глоссариями

| Термин или группа | Владелец определения | Как использовать во фронтенд-платформе |
| --- | --- | --- |
| `Представление (View)`, `тип представления (View type)`, `шаблон представления (View template)`, `компоновка представления (View layout)` | [Термины Configuration](configuration_terms.md) | Использовать термин Configuration при обсуждении схемы или канонического артефакта. `Разрешённое runtime-представление` и `Настроенное представление` использовать только для контекста отображения фронтенда. |
| `Рендерер представления` | [Термины Configuration](configuration_terms.md) | Не дублировать как термин схемы. Фронтенд-платформа может описывать конкретные реализации рендереров фронтенда. |
| `Действие (Action)`, `способ ввода (Input method)`, `локальное поведение действия (Action local behavior)` | [Термины Configuration](configuration_terms.md) | Использовать термины Configuration для схемы артефакта и контракта ввода. Для UI фронтенда использовать `экран`, `диалог`, `элемент управления`. |
| `Object Runtime`, `Фасад runtime (Runtime Facade)`, операция изменения объекта | [Термины Object Runtime](object_runtime_terms.md) | Фронтенд отправляет запросы и отображает результаты; термины серверного исполнения остаются у Object Runtime. |
| Семантика прав, ролей и сессии | [Термины безопасности](security_terms.md) | Фронтенд использует права сессии для видимости и защиты маршрутов; авторизация остаётся у Tenant Security. |
| Семантика данных Value Sets и редактора данных | [Термины платформы](platform_terms.md) и документация Value Sets | Фронтенд-платформа владеет общей оболочкой и компонентами; Value Sets владеет поведением данных. |

## 5. Нежелательные формулировки

| Формулировка | Почему не использовать | Чем заменить |
| --- | --- | --- |
| Неясная формулировка для UI: `Surface / пользовательская поверхность` | Не говорит, является ли речь об экране, разделе интерфейса, способе ввода или рендерере. | Раздел интерфейса, экран, способ ввода, рендерер фронтенда или runtime-представление по контексту. |
| Представление без владельца (`View`) | Смешивает конфигурационный артефакт Configuration, модель runtime и видимый экран. | `Представление` для конфигурационного артефакта Configuration; `Разрешённое runtime-представление`; `экран`. |
| Редактор интерфейса для серверного контракта (`UI editor`) | Смешивает экран фронтенда и серверный конвейер редактора артефакта Configuration. | `Экран редактора` для фронтенда; `Редактор артефакта` для серверного контракта Configuration. |
| Меню без владельца (`Menu`) | Может означать конфигурационный артефакт Configuration `Menu`, навигацию оболочки или контекстное меню действий. | Артефакт `Menu`, `боковая навигация`, `меню действий` по контексту. |
| Проверка фронтенда как бизнес-проверка | Проверка UI помогает пользователю, но не заменяет серверную проверку и авторизацию. | Проверка формы, серверная проверка, проверка авторизации владельцем. |
