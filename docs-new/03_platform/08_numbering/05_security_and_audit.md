# Безопасность и аудит платформенной области — Numbering

## 1. Назначение документа

Документ разделяет контроль настройки правила, выполнение операции объекта и
журнал выдачи номера. Numbering не вводит отдельную модель прав.

## 2. Ресурсы и права

| Ресурс или действие | Кто владеет контролем | Что подтверждено |
| --- | --- | --- |
| Создание/изменение/публикация `NumberingRule` | Configuration и Tenant/Security | Используются общие права изменения конфигурационных артефактов |
| Создание объекта | Object Runtime и Domain Module | Numbering работает только внутри разрешённой операции |
| Ручное значение поля | Политика `NumberingManualInputPolicy` на `ObjectMember` | Не является permission |
| Чтение/изменение счётчика | Numbering | Отдельного пользовательского API в V1 нет |

## 3. Принятие решения и управление

```text
разрешение операции объекта
 -> Object Runtime запускает Numbering hook
 -> Numbering проверяет политики поля и кандидатов правил
 -> значение записывается только в разрешённую операцию
```

Если операция создания запрещена, Numbering не должен вызываться. `Forbidden`,
`Allowed` и `AdminOnly` являются значениями политики поля, а не ролями.

## 4. Контроли и риски

| Контроль | Назначение | Состояние |
| --- | --- | --- |
| Проверка `NumberingEnabled` | Не разрешать правило для поля без поддержки нумерации | Подтверждено Configuration validation |
| Проверка источников | Ограничить поля шаблона, условия и раздела счётчика | Подтверждено Configuration validation |
| Запрет неоднозначного приоритета | Не выдавать номер при равном максимальном `Priority` | Подтверждено runtime и validation |
| Уникальный ключ счётчика | Не создавать два счётчика для одного ключа | Подтверждено persistence index |
| Неиспользование номера повторно | Сохранять факт выделения при последующей ошибке | Подтверждено runtime поведением |

## 5. Аудит

`NumberingIssueLog` хранит operational-сведения о факте выдачи: правило,
счётчик, значение, объект, tenant/site/user, `CorrelationId`, configuration
entry, published version и время. Это запись Numbering, а не общий audit record.

Связь с `Audit History` и доставка отдельного события не считаются установленными
без соответствующего межмодульного контракта.

## 6. Покрытие и пробелы

- отдельный пользовательский интерфейс для просмотра и корректировки счётчиков не
  подтверждён;
- отдельное permission для ручной корректировки счётчика не реализовано;
- атомарность проверена на уровне текущего store и тестов, но production
  provider-specific concurrency evidence требует отдельной проверки;
- общая политика хранения и просмотра operational log не заменяет правила
  Audit History.
