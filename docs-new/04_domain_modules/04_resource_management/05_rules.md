# Правила - 04 Управление ресурсами

## 1. Назначение документа

Документ фиксирует предметные инварианты и ограничения изменения объектов
модуля `04_resource_management`.

Полный состав объектов, полей, ссылок и коллекций описан в
[`02_domain_model.md`](02_domain_model.md). Публикация через Object Runtime,
lookup и режимы коллекций описаны в
[`03_object_runtime_model.md`](03_object_runtime_model.md). Пользовательские
формы и действия в этот документ не входят.

## 2. Общие правила модуля

### 2.1 Область данных и ссылки

- Каждый объект, которым владеет модуль 04, принадлежит текущему `Tenant`.
- Для зависимого или связующего объекта `TenantId` совпадает с областью данных
  владельца и не изменяется отдельно.
- Ссылки между объектами разрешаются только в доступной области tenant и с
  учетом права чтения целевого объекта.
- Внешний объект проверяется через контракт модуля-владельца. Модуль 04 не
  читает таблицы внешних объектов напрямую.
- `WorkflowStateCode` не используется как универсальное условие выбора
  ресурсной ссылки. Ограничения выбора задаются типом ссылки, областью
  действия и предметной совместимостью.

### 2.2 Идентификация и наследование

- `Code` и `Name` обязательны для типов, наследующих каталоговый контракт
  `CommonCatalogObject`; их значения задаются при создании самостоятельного
  объекта по общим правилам Common и нумерации, если она подключена.
- Логический базовый тип не является самостоятельным объектом и не создает
  отдельную запись.
- Наследник получает правила базового типа. Поля и правила базового типа не
  дублируются отдельной предметной логикой наследника.
- Общий lookup создается только для подтвержденной полиморфной ссылки. В
  частности, `ToolBase` объединяет только `Tooling` и `Gage`; общего lookup
  `Resource` нет.

### 2.3 Архивирование и удаление

- Архивирование и мягкое удаление выполняются по общим правилам Common/Object
  Runtime, если для объекта не действует специальное правило ниже.
- Архивный или удаленный объект не предлагается для нового выбора по умолчанию.
- Уже сохраненная ссылка на архивный объект может отображаться в контексте
  владельца.
- Предметные ограничения удаления и архивирования не заменяют стандартную
  проверку прав.

## 3. Ресурсы и группы

Правила раздела применяются к самостоятельным типам `WorkPlace`, `Personnel`,
`Tooling`, `Gage`, `WorkPlaceGroup` и `PersonnelGroup` с учетом общих
контрактов логических типов `ResourceBase`, `ResourceGroupBase` и
`ResourceInResourceGroupBase`.

### 3.1 Иерархии групп

Инварианты:

| Правило | Проверка | Ошибка при нарушении |
|---|---|---|
| `WorkPlaceGroup.Parent` ссылается только на `WorkPlaceGroup` | Проверить тип выбранного родителя | Родитель имеет недопустимый тип |
| `PersonnelGroup.Parent` ссылается только на `PersonnelGroup` | Проверить тип выбранного родителя | Родитель имеет недопустимый тип |
| Группа не может быть родителем самой себя | Сравнить идентификаторы группы и родителя | Самоссылка запрещена |
| Группа не может быть перемещена в собственное поддерево | Проверить путь родителя относительно текущего узла | Перенос в собственное поддерево запрещен |
| Иерархия не содержит циклов | Проверить цепочку `Parent` при создании и изменении | Циклическая иерархия запрещена |
| Иерархии рабочих мест и сотрудников независимы | Не допускать ссылок между `WorkPlaceGroup` и `PersonnelGroup` | Несовместимый тип группы |
| Членство не дублируется в одной группе | Проверить пару владелец группы и ресурс | Повторное членство запрещено |

Runtime-метаданные `Root`, `Level`, `Path` и `HasChildren` вычисляются общей
платформенной capability и не изменяются пользователем. При изменении
`Parent` значения узла и его поддерева пересчитываются в одной операции.

Ограничения изменения:

| Поле / данные | Когда запрещено менять | Причина |
|---|---|---|
| `Parent` | При выборе объекта другого типа, самого объекта или его потомка | Сохранение независимой ациклической иерархии |
| `Root`, `Level`, `Path`, `HasChildren` | Всегда через пользовательский запрос | Это вычисляемые runtime-метаданные |
| Владелец элемента `Members` | После создания элемента коллекции | Элемент должен оставаться в контексте исходной группы |

### 3.2 Состав ресурсов в группах

Рабочее место может входить в группы рабочих мест, а сотрудник - в группы
сотрудников. Состав группы не меняет владельца ресурса и не создает общего
типа `Resource`.

Если ресурсная ссылка используется модулем 02 вместе с группой, группа
ограничивает множество допустимых кандидатов. Явно указанный ресурс должен
входить в указанную группу. Количество и альтернативные наборы ресурсных норм
определяются модулем 02.

### 3.3 Тип распределения группы и роль ресурса

`AllocationType` определяет смысл состава конкретной группы. Он не заменяет
правила ресурсной нормы и не превращает группу в универсальный ресурс.

| Правило | Проверка | Ошибка при нарушении |
|---|---|---|
| Тип распределения группы обязателен | `AllocationType` заполнен значением `ResourceGroup` или `AlternativeResources` | Не указан тип распределения группы |
| Группа `ResourceGroup` представляет единый комплект ресурсов | В составе группы существует ровно один элемент с `IsBasic = true` | Для группы ресурсов должен быть указан ровно один основной ресурс |
| Члены `AlternativeResources` являются взаимозаменяемыми кандидатами | Выбор одного или подмножества членов выполняется по количеству ресурсной нормы модуля 02 | Состав альтернативной группы использован как единый обязательный комплект |
| `IsBasic` задает роль элемента внутри его группы | Проверить признак элемента относительно `AllocationType` и состава группы | Некорректная роль ресурса в составе группы |
| Состав группы не смешивает виды ресурсов | Для `WorkPlaceGroup` допускаются только `WorkPlace`, для `PersonnelGroup` - только `Personnel` | В группу включен ресурс недопустимого типа |

Для `AlternativeResources` конкретный ресурс или подмножество ресурсов выбирается
модулем 02 с учетом количества нормы. Модуль 04 предоставляет состав группы и
проверяет принадлежность ссылок, но не определяет размер выбранного подмножества.

Ограничения изменения:

| Поле / данные | Когда запрещено менять | Причина |
|---|---|---|
| `AllocationType` | Если изменение нарушает состав группы или уже используемые ссылки на группу | Сохраняется смысл группы для потребляющих модулей |
| `IsBasic` элемента | Если новое значение нарушает правило состава группы `ResourceGroup` | Сохраняется единственный основной участник комплекта |

### 3.4 Уникальность ресурсов, групп и инструментов

Уникальность проверяется в пределах одного `Tenant`; для необязательного
`ExternalId` проверяется только непустое значение.

| Объект | Уникальное значение |
|---|---|
| `WorkPlace` | `Code`, `ExternalId` |
| `Personnel` | `Code`, `ConfirmationCode`, `ExternalId` |
| `WorkPlaceGroup` | `Code`, `ExternalId` |
| `PersonnelGroup` | `Code`, `ExternalId` |
| `WorkPlaceInWorkPlaceGroup` | Пара `WorkPlaceGroup` + `WorkPlace`, `ExternalId` |
| `PersonnelInPersonnelGroup` | Пара `PersonnelGroup` + `Personnel`, `ExternalId` |
| `Tooling` | `Code`, `ExternalId` для самостоятельного типа `Tooling` |
| `Gage` | `Code`, `ExternalId` для самостоятельного типа `Gage` |

## 4. Местоположения ресурсов

Общие правила `ResourceLocationBase` применяются к самостоятельным типам
`WorkPlaceLocation` и `PersonnelLocation`.

Инварианты:

| Правило | Проверка | Ошибка при нарушении |
|---|---|---|
| Местоположение принадлежит одному ресурсу своего типа | Для `WorkPlaceLocation` проверить `WorkPlace`, для `PersonnelLocation` - `Personnel` | Недопустимый владелец местоположения |
| `ProductionUnit` доступна в области tenant | Проверить внешний контракт модуля 03 | Производственная единица недоступна |
| `ValidFrom` не позже `ValidTo` | Проверить обе границы, если `ValidTo` задана | Некорректный период |
| Основное местоположение единственно для ресурса и периода | Проверить пересечение действующих основных записей | Пересекающиеся основные местоположения |
| `IsBasic = true` требует `IsPermanent = true` | Проверить комбинацию признаков | Запрещено временное основное местоположение |
| `Previous` образует цепочку только своего типа и ресурса | Проверить владельца, тип и отсутствие циклов | Недопустимая цепочка местоположений |
| У местоположения не более одного последующего звена | Проверить уникальность ссылки `Previous` внутри конкретного типа и ресурса | У местоположения несколько последующих основных звеньев |
| `ExternalId` местоположения уникален | Проверить непустой `ExternalId` отдельно для `WorkPlaceLocation` и `PersonnelLocation` | Дублирование внешнего идентификатора местоположения |

Допускаются постоянные неосновные местоположения и временные неосновные
местоположения. Для неосновного местоположения цепочка `Previous` не ведется.
Открытая верхняя граница периода задается `ValidTo = null`.

Ограничения изменения:

| Поле / данные | Когда запрещено менять | Причина |
|---|---|---|
| Владелец местоположения | После создания записи | История должна оставаться историей конкретного ресурса |
| `IsBasic` | После создания записи | Роль записи и принадлежность цепочке основных мест не меняются |
| `IsPermanent`, `ValidFrom`, `ValidTo`, `Previous` | Если изменение создает пересечение периодов или нарушает цепочку | Сохранение непротиворечивой истории |
| `Previous` | Для неосновного местоположения | Цепочка ведется только для основных постоянных местоположений |

Последующее основное местоположение, ссылающееся на запись через `Previous`,
блокирует физическое удаление этой записи. Исправление истории выполняется
корректирующей операцией с сохранением цепочки; подробный алгоритм создания,
изменения и удаления будет описан в отдельном документе операций модуля 04.

## 5. Персонал, квалификации, допуски и отсутствие

Инварианты:

| Правило | Проверка | Ошибка при нарушении |
|---|---|---|
| Квалификация принадлежит одному сотруднику | Проверить владельца коллекции `Personnel.Qualifications` | Недопустимый сотрудник |
| Разряд находится в диапазоне от 0 до 9 | Проверить значение `Grade` | Недопустимый разряд |
| У сотрудника не более одной основной квалификации | Проверить действующие записи с `IsBasic = true` | Дублирование основной квалификации |
| Допуск имеет вид допуска и период действия | Проверить `AllowanceType`, `ValidFrom` и `ValidTo` | Неполный или некорректный допуск |
| Период допуска корректен | Проверить `ValidFrom <= ValidTo` | Некорректный период допуска |
| `PersonnelAbsence` принадлежит одному сотруднику и имеет причину | Проверить владельца и `AbsenceReason` | Недопустимое отсутствие |
| Периоды отсутствия не имеют обратного порядка дат | Проверить границы периода | Некорректный период отсутствия |
| Даты приема и увольнения сотрудника последовательны | Если обе даты заданы, `DateOfJoining <= DateOfLeaving` | Дата увольнения раньше даты приема |
| Квалификация сотрудника не дублируется | Проверить уникальность пары `Personnel` + `Profession` + `Grade` | Такая квалификация уже назначена сотруднику |
| Допуски одного вида не пересекаются | Проверить отсутствие пересечения периодов для `Personnel` + `WorkPlace` + `AllowanceType` | Допуск того же вида уже действует в указанный период |
| `ExternalId` зависимых записей уникален | Проверить непустой `ExternalId` квалификации, допуска или отсутствия | Дублирование внешнего идентификатора |

`PersonnelAllowance.WorkPlace` является необязательной ссылкой. Она уточняет,
для какого рабочего места действует допуск, но не передает рабочему месту
владение допуском.

Ограничения изменения:

| Поле / данные | Когда запрещено менять | Причина |
|---|---|---|
| Владелец квалификации, допуска или отсутствия | После создания записи | Элемент остается в коллекции исходного сотрудника |
| `PersonnelQualification.IsBasic` | Если у сотрудника уже есть другая основная квалификация | Сохраняется единственность основной квалификации |
| `PersonnelAllowance.WorkPlace` | Если рабочее место недоступно или ссылка нарушает ограничения допуска | Сохраняется предметная применимость допуска |

Коды и непустые внешние идентификаторы `Profession`, `PaymentGroup`,
`PersonnelAllowanceType` и `AbsenceReason` уникальны в пределах tenant.

## 6. Календари, графики и назначения

Правила назначений применяются к самостоятельным типам, наследующим
`ResourceWorkSchedule`. Описания `WorkScheduleDescription` и
`ShiftRotationDescription` проверяются относительно своих владельцев.

### 6.1 Описания календарей и графиков

Инварианты:

| Правило | Проверка | Ошибка при нарушении |
|---|---|---|
| Описание принадлежит своему владельцу | Проверить контекст `DayType`, `WorkSchedule` или `ShiftRotationModel` | Недопустимый владелец описания |
| Интервал имеет корректные границы | Проверить `StartTime <= EndTime` по правилам локального времени | Некорректный интервал |
| Перерыв связан с интервалом рабочего времени того же типа дня | Проверить `DayTypeDescription.Parent` | Недопустимая связь интервала и перерыва |
| Корневой интервал не содержит номер перерыва | Для `PeriodType = ShiftWorkingTime` `BreakNumber` не заполнен | Номер перерыва задан для рабочего интервала |
| Перерыв содержит номер перерыва | Для `PeriodType = Break` `BreakNumber` заполнен положительным значением | Для перерыва не задан номер |
| Поля описания соответствуют типу графика | Проверить `WorkSchedule.Type` или тип модели | Несогласованные поля описания |
| Модель чередования смен относится к своему графику | Проверить `ShiftRotationModel.WorkSchedule` | График модели не соответствует ссылке |
| Описание перерыва имеет рабочий интервал того же типа дня | Для `PeriodType = Break` `Parent` заполнен и указывает на интервал `ShiftWorkingTime` | Перерыв не связан с рабочим интервалом |
| Рабочий интервал не имеет родителя | Для `PeriodType = ShiftWorkingTime` `Parent` не заполнен | Рабочий интервал ошибочно подчинен другому интервалу |
| Перерыв не образует вложенную иерархию | `Parent.PeriodType = ShiftWorkingTime` | Перерыв не может быть родителем другого перерыва |

`DayTypeDescription.Parent` является предметной связью интервала с перерывом,
а не наследованием типов. `ShiftRotationModel` может назначаться сотруднику
или группе сотрудников; назначение рабочему месту или группе рабочих мест не
вводится.

### 6.2 Праздничные даты и периоды календарей

| Правило | Проверка | Ошибка при нарушении |
|---|---|---|
| Дата праздничного календаря уникальна | В пределах tenant нет двух записей с одинаковым `Date` | На дату уже задана календарная запись |
| `Holiday.Year` соответствует `Holiday.Date` | Год даты равен `Year` | Дата не соответствует указанному году |
| `Holiday.FromDate` соответствует `Holiday.Year` | Если `FromDate` задана, ее год равен `Year` | Исходная дата переноса не соответствует году |
| Перенос выходного дня имеет исходную дату | Для `Type = TransferWeekend` `FromDate` заполнена; для остальных типов `FromDate` пуста | Некорректное заполнение исходной даты переноса |
| `WorkSchedule` имеет корректный период действия | `ValidFrom` и `ValidTo` заполнены, `ValidFrom <= ValidTo` | Некорректный период действия графика |
| `ShiftRotationModel` имеет корректный период действия | `ValidFrom` и `ValidTo` заполнены, `ValidFrom <= ValidTo` | Некорректный период действия модели сменности |
| Код и внешний идентификатор графика уникальны | Уникальна пара `Year` + `Code` и непустой `ExternalId` | Дублирование графика работы |
| Код и внешний идентификатор модели сменности уникальны | Уникальна пара `Year` + `Code` и непустой `ExternalId` | Дублирование модели чередования смен |
| Код и внешний идентификатор типа рабочего дня уникальны | Проверить `DayType.Code` и непустой `DayType.ExternalId` | Дублирование типа рабочего дня |

Для `WorkScheduleDescription` и `ShiftRotationDescription` сохраняются
условия, зависящие от типа владельца: для недельного типа задается
`DayOfWeek` или `HolidayType`, для циклического - положительные
`PeriodNumber` и `PeriodDuration` либо специальная праздничная запись, для
годового - `YearDay` соответствующего года. Отсутствие `DayType` означает
нерабочий день. В описании `ShiftRotationModel` поле `Shift` обязательно.

### 6.3 Назначения графиков

Инварианты:

| Правило | Проверка | Ошибка при нарушении |
|---|---|---|
| Назначение имеет владельца своего конкретного типа | Проверить коллекцию владельца | Недопустимый владелец назначения |
| `Permanent` и `Temporary` используют `WorkSchedule` | Проверить обязательность ссылки по `AssignmentType` | Для типа назначения не задан график |
| `Change` использует `DayType` и не заменяет базовый график | Проверить отсутствие `WorkSchedule` и наличие `DayType`; для персонала и группы сотрудников проверить `Shift` | Несогласованное временное изменение |
| Период назначения корректен | Проверить `ValidFrom <= ValidTo`, если `ValidTo` задана; для `Temporary` и `Change` `ValidTo` обязательна | Некорректный период назначения |
| `Previous` ссылается на прежнее назначение того же владельца и типа | Проверить тип, владельца и отсутствие цикла | Недопустимая временная цепочка |
| Назначения одного владельца одного уровня не пересекаются | Проверить периоды и тип назначения | Пересекающиеся назначения |

Для организационной единицы используется единый тип
`OrganizationalUnitWorkSchedule`; его владельцем может быть конкретный внешний
тип, разрешенный модулем 03. Назначения рабочих мест, групп рабочих мест,
сотрудников и групп сотрудников остаются отдельными типами.

Ограничения изменения:

| Поле / данные | Когда запрещено менять | Причина |
|---|---|---|
| Владелец назначения | После создания записи | Сохраняется принадлежность назначению конкретного типа |
| `AssignmentType` | Если новое значение делает набор полей несовместимым | Сохраняется согласованность назначения и временного изменения |
| `Previous` | При ссылке на другой тип назначения или другой уровень владельца | Временная цепочка не смешивает разные типы назначений |

Непустой `ExternalId` каждого самостоятельного типа назначения графика
(`OrganizationalUnitWorkSchedule`, `WorkPlaceGroupWorkSchedule`,
`WorkPlaceWorkSchedule`, `PersonnelGroupWorkSchedule`,
`PersonnelWorkSchedule`) должен быть уникален в пределах tenant.

## 7. Параметры операций и материально ответственное лицо

Общие ограничения `OperationParametersBase` применяются к трем самостоятельным
типам параметров и не означают создания записи самого базового типа.

### 7.1 Параметры операций

Инварианты:

| Правило | Проверка | Ошибка при нарушении |
|---|---|---|
| Для одного владельца существует не более одной записи параметров | Проверить владельца перед созданием и изменением | Дублирование параметров владельца |
| Тип параметров соответствует владельцу | Проверить `ProductionUnit`, `WorkPlace` или `Personnel` для конкретного типа | Несовместимый владелец параметров |
| Значения параметров доступны по правилам модуля 04 | Проверить собственные значения и их типы | Недопустимое значение параметра |
| Эффективные параметры имеют однозначный источник | Проверить собственные параметры и наследование от `ProductionUnit` | Неоднозначный источник параметров |

`ProductionUnitOperationParameters` принадлежит модулю 04 и доступен из
контекста внешней `ProductionUnit`. `WorkPlaceOperationParameters` и
`PersonnelOperationParameters` являются одиночными зависимыми объектами
соответствующих владельцев. Значения от `ProductionUnit` применяются только
при отсутствии собственного значения по правилам разрешения эффективных
параметров.

Ограничения изменения:

| Поле / данные | Когда запрещено менять | Причина |
|---|---|---|
| Владелец параметров | После создания записи | Сохраняется связь с конкретным владельцем |
| `ProductionUnitOfParentParameters` и эффективные значения | Всегда напрямую пользователем | Это результат разрешения параметров, а не собственные настройки |

### 7.2 Материально ответственное лицо

Инварианты:

| Правило | Проверка | Ошибка при нарушении |
|---|---|---|
| Назначение связывает доступные `ProductionUnit` и `Personnel` | Проверить ссылки через контракты владельцев | Недоступный объект назначения |
| Для одной пары `ProductionUnit` и `Personnel` нет дублирующего действующего назначения | Проверить уникальность действующей пары | Дублирование назначения |
| `ExternalId` назначения уникален | Проверить непустой `ExternalId` | Дублирование внешнего идентификатора материально ответственного лица |
| Назначение не передает владение производственной единицей или сотрудником | Проверить режим контекстной публикации | Недопустимое изменение владельца данных |

`MaterialResponsiblePerson` не является коллекцией-владельцем
`ProductionUnit` в доменной модели 04. Складские и логистические сценарии
используют этот факт через межмодульный контракт.

## 8. Правила удаления и архивирования

- Удаление или архивирование группы с активными непосредственными потомками
  запрещено общей hierarchy policy v1.
- Удаление элемента состава группы не должно удалять сам ресурс или группу.
- Удаление ресурса проверяется относительно его активных местоположений,
  назначений графика, квалификаций, допусков, отсутствий и других зависимых
  объектов по правилам владельца.
- Удаление или архивирование параметров не должно изменять владельца и не
  должно создавать новую запись параметров автоматически.
- Архивирование и удаление инструментов и оснастки в модуле 04 не означает
  движение, выдачу, возврат, ремонт, списание или фактическую эксплуатацию.
  Эти операции находятся за границей модуля.

## 9. Граница с другими модулями

| Модуль | Использование правил модуля 04 | Граница ответственности |
|---|---|---|
| `01_general_master_data` | `Profession`, `PaymentGroup`, `Nomenclature`, `NomenclatureVariant` и другие внешние справочники по контрактам | GMD владеет своими объектами и подтверждает их доступность |
| `02_product_process_definition` | Выбирает `WorkPlace`, `WorkPlaceGroup`, `Personnel`, `PersonnelGroup` и `ToolBase` в ресурсных нормах | PR02 владеет нормами, количеством, альтернативными наборами и правилами их применения; 04 предоставляет lookup и проверки отдельных ссылок |
| `03_plant_structure` | Предоставляет `OrganizationalUnit` и `ProductionUnit`; получает обратную навигацию к назначениям графиков и параметрам операций | PR03 владеет производственной структурой; 04 владеет своими назначениями и параметрами |
| `09` / `10` / APS | Используют сведения о ресурсах и эффективные параметры по опубликованным контрактам | Движение ресурсов, фактическое выполнение и автоматический подбор не принадлежат модулю 04 |

альтернативными наборами ресурсных норм и не выполняет фактический подбор
ресурсов.
