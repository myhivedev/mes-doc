# Модель среды выполнения объектов — Управление документацией

## 1. Назначение документа

Документ определяет публикацию объектов модуля через среду выполнения объектов (Object Runtime), правила представления, режимы коллекций, ограничения ссылок и подключённые платформенные возможности.

## 2. Базовое решение

- все объекты ограничены текущим предприятием (`TenantId`);
- предметные поля определены в [02_domain_model.md](02_domain_model.md);
- карточки и списки определены в [06_ui_views.md](06_ui_views.md);
- составные прикладные операции определены в [13_operations.md](13_operations.md);
- отдельный объект «Настройки управления документацией» (`DocumentManagementSettings`) не создаётся.

## 3. Объявляемые типы объектов

| Тип объекта | Русское название | Доступность через среду выполнения объектов | Примечание |
|---|---|---|---|
| Документ (`DocumentManagement:Document`) | Документ | список, карточка, создание, сохранение, переходы жизненного цикла | Корневой бизнес-объект; физическое удаление запрещено. |
| Каталог документов (`DocumentManagement:DocumentFolder`) | Каталог документов | иерархический список, карточка, создание, сохранение, архивирование | Иерархический классификатор; физическое удаление запрещено. |
| Тип документа (`DocumentManagement:DocumentType`) | Тип документа | список, карточка, создание, сохранение, архивирование | Классификатор; физическое удаление запрещено. |
| Содержимое документа (`DocumentManagement:DocumentContent`) | Содержимое документа | список, чтение, специальные операции | Корневой бизнес-объект; мягкое удаление. |
| Связь документа с содержимым (`DocumentManagement:DocumentContentLink`) | Связь документа с содержимым | коллекция документа и специальные операции | Доступ проверяется через документ-владелец; строка связи удаляется физически. |
| Связь документа с бизнес-объектом (`DocumentManagement:DocumentObjectLink`) | Связь документа с бизнес-объектом | коллекция документа и специальные операции | Доступ проверяется через документ-владелец; строка связи удаляется физически. |
| Хранилище документов (`DocumentManagement:DocumentStorage`) | Хранилище документов | системная запись в MVP | Публикация пользовательской формы и расширенного жизненного цикла отложена после MVP. |

## 4. Правила представления объектов

| Тип объекта | Правило представления | Источник |
|---|---|---|
| Документ (`Document`) | Номер документа и наименование документа | поля «Номер документа» (`Number`) и «Наименование документа» (`Name`) |
| Каталог документов (`DocumentFolder`) | Код каталога и наименование каталога | поля «Код каталога» (`Code`) и «Наименование каталога» (`Name`) |
| Тип документа (`DocumentType`) | Код типа документа и наименование типа документа | поля «Код типа документа» (`Code`) и «Наименование типа документа» (`Name`) |
| Содержимое документа (`DocumentContent`) | Номер содержимого при наличии и наименование содержимого | поля «Номер содержимого» (`Number`) и «Наименование содержимого» (`Name`) |
| Хранилище документов (`DocumentStorage`) | Код и наименование системного хранилища | системное хранилище «База данных» |

## 5. Объекты

### 5.1. Документ (`Document`)

| Элемент | Решение |
|---|---|
| Тип объекта | Документ (`DocumentManagement:Document`) |
| Представления | «Список документов» (`DocumentManagement.DocumentList`), «Документы с содержимым» (`DocumentManagement.DocumentWithContentList`), «Документы по каталогам» (`DocumentManagement.DocumentByFolderList`), «Карточка документа» (`DocumentManagement.DocumentDetail`) |
| Коллекции | «Содержимое» (`Contents`), «Связанные объекты» (`ObjectLinks`); режим — отдельные операции |
| Особые обработчики | формирование номера, начальная дата и версия, проверки сохранения, переходы жизненного цикла |

Ссылочные поля:

| Поле | Источник значений | Ограничение выбора |
|---|---|---|
| Каталог (`FolderId`) | Каталоги документов (`DocumentFolder`) | Неархивная часть иерархии текущего предприятия. |
| Тип документа (`DocumentTypeId`) | Типы документов (`DocumentType`) | Неархивный тип текущего предприятия. |
| Ответственное подразделение (`ProductionUnitResponsible`) | Производственные единицы (`ProductionUnit`) | Неархивная внутренняя производственная единица текущего предприятия; подрядчики исключены. |
| Ответственный (`ResponsibleEmployeeId`) | Сотрудники (`Personnel`) | Доступный сотрудник текущего предприятия. |
| Первоначальный документ (`InitialDocumentId`) | Документы (`Document`) | Заполняется системой только для последующей версии ссылкой на первую версию. |

### 5.2. Каталог документов (`DocumentFolder`)

| Элемент | Решение |
|---|---|
| Тип объекта | Каталог документов (`DocumentManagement:DocumentFolder`) |
| Представления | «Каталоги документов» (`DocumentManagement.DocumentFolderList`), «Карточка каталога документов» (`DocumentManagement.DocumentFolderDetail`) |
| Коллекции | Нет |
| Особые обработчики | проверка отсутствия циклов; создание корневого каталога «Документы» |

Ссылочные поля:

| Поле | Источник значений | Ограничение выбора |
|---|---|---|
| Вышестоящий каталог (`ParentId`) | Каталоги документов (`DocumentFolder`) | Текущее предприятие; нельзя выбрать текущий каталог или его потомка. |

### 5.3. Тип документа (`DocumentType`)

| Элемент | Решение |
|---|---|
| Тип объекта | Тип документа (`DocumentManagement:DocumentType`) |
| Представления | «Типы документов» (`DocumentManagement.DocumentTypeList`), «Карточка типа документа» (`DocumentManagement.DocumentTypeDetail`) |
| Коллекции | Нет |
| Особые обработчики | формирование кода; подстановка хранилища документов по умолчанию; блокировка изменения кода после создания первого документа типа |

Ссылочные поля:

| Поле | Источник значений | Ограничение выбора |
|---|---|---|
| Хранилище (`StorageId`) | Хранилища документов (`DocumentStorage`) | В MVP — системное активное хранилище «База данных» текущего предприятия. |

### 5.4. Содержимое документа (`DocumentContent`)

| Элемент | Решение |
|---|---|
| Тип объекта | Содержимое документа (`DocumentManagement:DocumentContent`) |
| Представления | «Содержимое документов» (`DocumentManagement.DocumentContentList`), «Выбор содержимого» (`DocumentManagement.DocumentContentLookup`) |
| Коллекции | Нет |
| Особые обработчики | проверка вида и способа хранения; мягкое удаление после удаления последней связи |

Ссылочных полей нет.

### 5.5. Хранилище документов (`DocumentStorage`)

| Элемент | Решение |
|---|---|
| Тип объекта | Хранилище документов (`DocumentManagement:DocumentStorage`) |
| Представления | Не публикуются в MVP; системная запись создаётся начальными данными. |
| Коллекции | Нет |
| Особые обработчики | Не утверждены. |

## 6. Коллекции среды выполнения объектов

| Владелец | Коллекция | Тип строки | Режим | Комментарий |
|---|---|---|---|---|
| Документ (`Document`) | Содержимое (`Contents`) | Связь документа с содержимым (`DocumentContentLink`) | Отдельные операции | Связи создаются, переназначаются и удаляются составными операциями модуля. |
| Документ (`Document`) | Связанные объекты (`ObjectLinks`) | Связь документа с бизнес-объектом (`DocumentObjectLink`) | Отдельные операции | Перед созданием связи проверяются тип, запись, предприятие и право просмотра. |
| Документ (`Document`) | Версии | Документ (`Document`) | Навигация | Список формируется по полю «Первоначальный документ» (`InitialDocumentId`) и не является сохраняемой коллекцией владельца. |

## 7. Подключённые возможности платформы

| Возможность | Решение модуля | Статус зависимости |
|---|---|---|
| Жизненные циклы (`Workflow`) | состояния и переходы документа определены в [04_workflows.md](04_workflows.md) | покрыто существующим планом платформы |
| Нумерация (`Platform Numbering`) | два опубликованных правила: код типа и номер документа | требует решения Главного архитектора, `DM-PD-005` |
| Настройки (`Settings`) | ограничения файлов | покрыто существующим контрактом; ссылочная настройка хранилища не входит в MVP |
| Пользовательские предпочтения (`User Preferences`) | сохраняются представление, поиск, фильтры и сортировка | требует решения Главного архитектора, `DM-PD-004` |
| Универсальная проверка связанной записи | проверяются тип, существование, предприятие и право просмотра | требует решения Главного архитектора, `DM-PD-001` |
| Иерархические объекты | чтение дерева и выбор родителя каталога | требует решения Главного архитектора, `DM-PD-002` |
| Защищённая конфигурация | регистрация внешних провайдеров и секреты | требуется только для целевого расширения внешнего хранения |
| Защита от одновременного изменения | общий `ConcurrencyToken` передаётся в mutation-контрактах | покрыто существующим механизмом Object Runtime |

## 8. Граница с интерфейсом

Среда выполнения объектов публикует типы, представления и обработчики. Конкретные колонки, поля, фильтры, вкладки, действия и состояния без данных определены только в [06_ui_views.md](06_ui_views.md) и здесь не повторяются.

## 9. ContentRef в Object Runtime

Объекты модуля публикуют метаданные файла через стандартную проекцию descriptor.
Загрузка, attach, detach и скачивание используют общие контракты среды
выполнения и Content Storage; специальный контроллер загрузки для модуля не
создаётся.
Если операция выполняется из встроенной коллекции содержимого в карточке
владельца, action может быть объявлен на типе строки коллекции и размещён через
`EmbeddedCollectionToolbar`. Object Runtime передаёт в action
`EmbeddedCollectionContext` с идентификатором владельца; предметный обработчик
использует этот контекст для создания или изменения строк коллекции.
