# Права доступа - 06 Управление проектами

## 1. Назначение документа

Документ определяет самостоятельно защищаемые объекты, стандартные permissions Object Runtime, роли и особые серверные проверки доступа PR06.

## 2. Принципы доступа

- область действия прав - текущее предприятие (`TenantId`);
- `Project`, `ProjectPhase` и `CostCode` являются отдельными permission resources;
- сервер проверяет право независимо от интерфейса;
- `ProjectBase` не имеет собственного ресурса прав;
- навигационные списки этапов используют права `ProjectPhase`;
- внешние document links проверяют права PR05 и доступ к связанному проекту или этапу;
- право просмотра не дает право изменения, архивирования, восстановления или удаления.

## 3. Самостоятельно защищаемые объекты

| Объект | Русское название | Стандартные права | Жизненный цикл | Основание |
|---|---|---|---|---|
| `ProjectManagement:Project` | Проект | `view`, `create`, `edit`, `delete`, `archive`, `restore` | Общие archive / restore / soft delete | Объект-владелец проекта. |
| `ProjectManagement:ProjectPhase` | Этап проекта | `view`, `create`, `edit`, `delete`, `archive`, `restore` | Общие archive / restore / soft delete | Самостоятельный объект этапа. |
| `ProjectManagement:CostCode` | Код затрат | `view`, `create`, `edit`, `delete`, `archive`, `restore` | Общие archive / restore / soft delete | Самостоятельный tenant-owned каталог PR06. |

## 4. Строки, защищаемые через владельца

| Строка / объект | Владелец | Как проверяется доступ |
|---|---|---|
| Навигационный список `Phases` | `Project` | Для просмотра требуется право `view` на `Project` и `ProjectPhase`; изменение выполняется правами `ProjectPhase`. |
| Навигационный список `Children` | `ProjectPhase` | Для просмотра требуется право `view` на родительский и дочерний `ProjectPhase`. |
| Навигационный список `CostCode.Children` | `CostCode` | Для просмотра требуется право `view` на родительский и дочерний `CostCode`; изменение выполняется правами `CostCode`. |
| Связь документа с проектом или этапом | `Document` в PR05 | Проверяются право на документ по правилам PR05 и право просмотра связанного `Project` / `ProjectPhase`. |

## 5. Роли

| Роль | Назначение | Область действия | Базовый доступ |
|---|---|---|---|
| Пользователь просмотра проектов | Просмотр проектов, этапов, кодов затрат и доступных внешних связей. | Предприятие | `view` на `Project`, `ProjectPhase` и `CostCode`. |
| Менеджер проектов | Ведение проектов, этапов и кодов затрат, включая структурные изменения. | Предприятие | `view`, `create`, `edit`, а также операции archive / restore / delete при наличии соответствующих разрешений. |
| Администратор управления проектами | Полное администрирование объектов PR06. | Предприятие | Все права на `Project` и `ProjectPhase`. |

Специальная роль контролера проекта в MVP не создается.

## 6. Матрица доступа ролей

| Объект или действие | Пользователь просмотра проектов | Менеджер проектов | Администратор управления проектами |
|---|:---:|:---:|:---:|
| Просматривать проекты | да | да | да |
| Просматривать этапы и дерево | да | да | да |
| Просматривать коды затрат и дерево | да | да | да |
| Создавать проекты | нет | да | да |
| Изменять проекты | нет | да | да |
| Создавать и изменять этапы | нет | да | да |
| Перемещать этапы в дереве | нет | да | да |
| Архивировать проекты и этапы | нет | да | да |
| Восстанавливать проекты и этапы | нет | да | да |
| Удалять проекты и этапы | нет | да | да |
| Создавать и изменять коды затрат | нет | да | да |
| Архивировать, восстанавливать и удалять коды затрат | нет | да | да |

Доступ к каждой операции дополнительно ограничивается предметными проверками [05_rules.md](05_rules.md). Наличие права не отменяет блокировку удаления проекта с этапами или внешними ссылками.

## 7. Особые правила доступа

- просмотр архивного проекта или этапа по существующей ссылке требует права `view`;
- архивные объекты не предлагаются для новых lookup независимо от роли;
- создание или изменение этапа требует права на `ProjectPhase` и права просмотра доступного проекта;
- создание или изменение `CostCode` требует соответствующего права и права просмотра доступного родителя, если он указан;
- выбор ответственного подразделения, исполнителя и сотрудника требует доступности соответствующей внешней записи;
- просмотр связанных документов дополнительно регулируется правами PR05;
- `ProjectBase` запрещено указывать в permission-конфигурации как отдельный ресурс;
- UI не является механизмом безопасности: все permissions и проверки выполняются на сервере.

## 8. Техническое отображение

| Предметное действие | Технический шаблон |
|---|---|
| Просмотр проекта | право `view` типа `ProjectManagement:Project` |
| Создание и изменение проекта | права `create` / `edit` типа `ProjectManagement:Project` |
| Просмотр этапа | право `view` типа `ProjectManagement:ProjectPhase` |
| Создание и изменение этапа | права `create` / `edit` типа `ProjectManagement:ProjectPhase` |
| Просмотр кода затрат | право `view` типа `ProjectManagement:CostCode` |
| Создание и изменение кода затрат | права `create` / `edit` типа `ProjectManagement:CostCode` |
| Архивирование | право `archive` соответствующего типа плюс проверки дочерних объектов |
| Восстановление | право `restore` соответствующего типа плюс проверка доступности родительских объектов |
| Удаление | право `delete` соответствующего типа плюс проверка внутренних и внешних ссылок |
