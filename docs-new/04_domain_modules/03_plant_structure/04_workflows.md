# Жизненные циклы - 03 Производственная структура

## 1. Назначение документа

Документ описывает жизненные циклы объектов модуля `03 Plant Structure`.

Доменная модель объектов описана в `02_domain_model.md`. Runtime-публикация и обработчики Object Runtime описаны в `03_object_runtime_model.md`. Проверки переходов описаны в `05_rules.md`.

## 2. Общее решение

Модуль не вводит физическое поле `Status` во все объекты. Статусная модель реализуется как возможность типа объекта через Object Runtime и механизм жизненного цикла.

Жизненный цикл включается только для организационных единиц:

| Тип объекта | Жизненный цикл | Причина |
|---|---|---|
| `OrganizationalUnit` | Да | Абстрактный базовый тип для единых правил ссылок и жизненного цикла организационных единиц. |
| `ProductionUnit` | Да | Собственная организационная единица используется в производственных, ресурсных и логистических сценариях. |
| `Subcontractor` | Да | Внешняя организационная единица используется как участник производственной структуры. |
| `Company` | Нет | Балансовая организация ведется как справочник без предметного жизненного цикла в модуле. |
| `OrganizationalUnitInventoryParameters` | Нет | Зависимый объект места хранения; его существование определяется владельцем. |
| `StorageArea` | Нет | Справочник зоны хранения; используется Common-архивирование, если оно включено контрактом. |
| `WarehouseBinType` | Нет | Справочник типов ячеек; используется Common-архивирование, если оно включено контрактом. |
| `WarehouseBin` | Нет | Объект складской ячейки; используется Common-архивирование, если оно включено контрактом. |

Для одного типа объекта нельзя одновременно использовать прямое архивирование Common и архивирование через жизненный цикл. Для `ProductionUnit` и `Subcontractor` архивирование выполняется через жизненный цикл.

Архивное состояние жизненного цикла синхронизируется с архивированием Common. Для объекта с жизненным циклом прямое изменение архивных полей Common не используется.

## 3. Модель OrganizationalUnitLifecycle

Жизненный цикл применяется к `ProductionUnit` и `Subcontractor`. `OrganizationalUnit` задает общую модель состояний и правил, но не создается пользователем напрямую.

Состояния:

| Состояние | Русское название | Назначение |
|---|---|---|
| `Draft` | Черновик | Объект находится в стадии подготовки. |
| `Published` | Опубликован | Объект находится в состоянии, предусмотренном политикой Workflow для рабочего использования. |
| `Archived` | Архивный | Объект выведен из рабочего использования в соответствии с политикой Workflow. |

Переходы:

| Переход | Из | В | Назначение |
|---|---|---|---|
| `Publish` | `Draft` | `Published` | Сделать организационную единицу доступной для использования. |
| `ReturnToDraft` | `Published` | `Draft` | Вернуть объект на доработку, если он еще не должен использоваться. |
| `Archive` | `Draft`, `Published` | `Archived` | Закрыть объект для нового использования. |
| `Restore` | `Archived` | `Draft` | Вернуть объект из архива на доработку перед повторной публикацией. |

Назначение состояний и переходов в этой таблице определяет жизненный цикл самой организационной единицы, но не задает фильтры ссылочных полей. Если ограничение lookup по состоянию Workflow требуется предметно, оно должно быть явно описано в правилах соответствующего ссылочного поля. В v1 выбор места хранения не ограничивается состоянием Workflow: активная организационная единица с `IsInventoryStorageLocation = true` доступна для выбора как в `Draft`, так и в `Published`.

## 4. Доступность объектов по состояниям

| Сценарий | `Draft` | `Published` | `Archived` |
|---|---:|---:|---:|
| Открытие карточки | да | да | да |
| Изменение рабочих полей карточки | да | нет | нет |

В состоянии `Published` рабочие поля `ProductionUnit` и `Subcontractor` редактируются только через `ReturnToDraft`.

Это ограничение распространяется на зависимый объект `OrganizationalUnitInventoryParameters`: параметры места хранения считаются рабочими данными владельца и могут изменяться только когда владелец находится в `Draft`. При `Published` или `Archived` параметры доступны только для чтения. Для изменения параметров опубликованную организационную единицу необходимо сначала вернуть в `Draft` пользователем, имеющим право `ReturnToDraft`.

## 5. Проверки переходов

| Переход | Проверки |
|---|---|
| `Publish` для `ProductionUnit` | Заполнены обязательные поля; иерархия не содержит циклов; `Main` рассчитан; для `Type = Enterprise` нет `Parent`; для остальных типов есть `Parent`; если `IsInventoryStorageLocation = true`, существует зависимая запись `OrganizationalUnitInventoryParameters`. |
| `Publish` для `Subcontractor` | Заполнены обязательные поля; если `IsInventoryStorageLocation = true`, существует зависимая запись `OrganizationalUnitInventoryParameters`. |
| `ReturnToDraft` | В v1 дополнительные проверки входящих зависимостей других модулей не выполняются. |
| `Archive` | Нет активных дочерних `ProductionUnit`; нет активных зон или ячеек ПР03, относящихся к архивируемой организационной единице как месту хранения. Входящие зависимости других модулей в v1 не проверяются. |
| `Restore` | Восстанавливаемый объект не нарушает уникальность бизнес-ключей и правила иерархии. |

Детальные бизнес-правила и сообщения об ошибках описываются в `05_rules.md`.

## 6. Объекты без жизненного цикла

Для `Company`, `StorageArea`, `WarehouseBinType` и `WarehouseBin` модуль не подключает Workflow. Их удаление и архивирование выполняются средствами Common/Object Runtime.

Для `OrganizationalUnitInventoryParameters` Workflow и Common archive не применяются. Запись создается системой при включении признака места хранения и физически удаляется в той же транзакции при его отключении; самостоятельные действия создания, удаления и архивирования не публикуются.
