# Эксплуатация — Фронтенд-платформа

## 1. Назначение документа

Документ описывает запуск, проверку готовности, диагностику и восстановление
фронтенд-приложений. Развёртывание серверной части, миграции данных и производственная политика
остаются у соответствующих владельцев.

## 2. Запуск и готовность

Рабочая область фронтенда объявляет:

| Шаг запуска | Условие | Идемпотентность | Критерий готовности | Откат |
| --- | --- | --- | --- | --- |
| Проверить Node | Версия `>=20.19.0 <21`. | Повторная проверка не изменяет состояние. | Версия удовлетворяет диапазону. | Установить поддерживаемую версию. |
| Проверить менеджер пакетов | Используется `pnpm@10.0.0`. | Повторная проверка не изменяет состояние. | Доступна требуемая версия. | Установить требуемую версию. |
| Проверить рабочую область | Доступны `apps/*` и `packages/*`. | Повторная проверка не изменяет состояние. | Рабочая область открывается без ошибки. | Исправить состав рабочей области. |

([пакет фронтенда][frontend-package]; [рабочая область][workspace])

### 2.1. Команды сборки и проверки

| Команда | Назначение |
| --- | --- |
| `pnpm lint` | Запустить стандартную проверку lint. |
| `pnpm lint:all` | Запустить проверку lint для приложений и пакетов. |
| `pnpm i18n:check` | Проверить словари локализации фронтенда. |
| `pnpm typecheck` | Запустить проверки TypeScript. |
| `pnpm build` | Собрать артефакты рабочей области. |
| `pnpm test` | Запустить тесты Vitest. |
| `pnpm test:e2e` | Запустить тесты Playwright. |

Команды приведены по `src/Frontend/package.json`; этот драфт не утверждает
политику CI или критерии выпуска сверх скриптов, присутствующих в коде.

### 2.2. Переменные окружения

| Переменная | Потребители | Значение |
| --- | --- | --- |
| `VITE_API_BASE_URL` | Запуск Admin, Runtime, Studio | Базовый URL для `PlatformHttpClient`. |
| `VITE_ADMIN_REMOTE_NAVIGATION_ENABLED` | Приложение Admin | Включает путь эффективной/удалённой навигации Admin с локальным резервным вариантом. |
| `VITE_ENABLE_FORCE_BOOTSTRAP` | Приложение Studio | Включает средства принудительного запуска Studio вне обычного производственного пути. |

([приложение Admin][admin-app]; [приложение Runtime][runtime-app]; [приложение Studio][studio-app])

## 3. Миграции

Миграции базы данных и предметных данных не принадлежат фронтенд-платформе.
Для клиентских пакетов отдельный шаг миграции кодом не подтверждён.

| Изменение | Порядок | Совместимость | Проверка | Откат |
| --- | --- | --- | --- | --- |
| Изменение пакета фронтенда или контракта runtime | Сначала обновить потребителей и проверки, затем пакет. | Проверяется по публичным экспортам и контрактам runtime. | `typecheck`, `build`, модульные/компонентные и e2e-тесты. | Вернуть совместимые пакет/контракт по принятой процедуре выпуска. |
| Изменение контракта серверной части | Сначала согласовать с владельцем API. | Фронтенд не меняет серверную семантику самостоятельно. | Контрактные тесты владельца API и проверки фронтенда. | Выполняется владельцем контракта серверной части. |

## 4. Диагностика

Эксплуатация фронтенд-платформы охватывает конфигурацию сборки/runtime для
приложений фронтенда. Она не владеет следующими темами:

- топология развёртывания серверной части;
- миграции базы данных;
- семантика хранения сессии Tenant Security;
- гарантии доступности Runtime API;
- гарантии доставки аудита/outbox;
- политика CDN, CSP, телеметрии и хранения журналов.

Для этих тем до объявления производственных гарантий нужно отдельно назначить
операционных владельцев.

### 4.1. Диагностика

Текущий код подтверждает видимые клиенту состояния входа, проверки сессии,
нейтральной стартовой страницы runtime, ошибки загрузки языкового каталога при
запуске Admin и резервного перехода на стартовую страницу при ошибке загрузки
точки входа runtime. Полная производственная классификация диагностики в этом
драфте не установлена и отслеживается в `90_traceability.md`.

| Сигнал | Диагностика | Действие | Критерий восстановления | Эскалация |
| --- | --- | --- | --- | --- |
| Ошибка проверки сессии | Результат HTTP `401`/`403` при запуске | Проверить сессию и доступность API | Сессия успешно проверена или показан экран входа | Tenant Security / владелец API |
| Ошибка точки входа runtime | Ошибка запроса или неполная модель | Проверить Runtime API и обязательные коды | Открыта стартовая страница или разрешённый маршрут | Object Runtime / Configuration |
| Ошибка каталога языка | Ошибка загрузки языкового каталога при запуске Admin | Проверить источник каталога и резервный вариант | Применён доступный резервный вариант | Владелец локализации |

## 5. Восстановление

| Ситуация | Действие | Состояние после действия | Ограничение | Проверка |
| --- | --- | --- | --- | --- |
| Приложение не собирается | Исправить зависимость или код и повторить сборку. | Артефакт собирается. | Сборка не подтверждает доступность серверной части. | `pnpm build` |
| Точка входа runtime недоступна | Проверить API; приложение остаётся на стартовой странице. | Пользователь видит нейтральное стартовое состояние. | Полная политика повторов не определена. | E2E-сценарий оболочки |

## 6. Откат и эскалация

| Ситуация | Действие | Критерий возврата | Ответственный | Следующий шаг |
| --- | --- | --- | --- | --- |
| Несовместимое изменение контракта фронтенда | Остановить выпуск и вернуть совместимую версию пакета. | Публичные экспорты и потребители снова согласованы. | Фронтенд-платформа и владелец API | Проверить `FE-DEC-01 — источник совместимости контрактов фронтенда`. |
| Ошибка контракта серверной части | Не исправлять серверную семантику в пользовательском слое; эскалировать владельцу. | API возвращает согласованную модель. | Владелец контракта серверной части | Обновить контрактные тесты и `03_contracts.md`. |

## 7. Content API

Frontend host должен пропускать лимит протокола загрузки не ниже лимита
платформы с учётом служебного overhead. Настройки retention и cleanup принадлежат
Content Storage, а не frontend application.
