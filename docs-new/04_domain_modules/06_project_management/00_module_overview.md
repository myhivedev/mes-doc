# Обзор модуля - 06 Управление проектами

## 1. Назначение модуля

Модуль управления проектами ведет проекты и структурные этапы проектов, используемые как общие аналитические измерения при планировании, учете и работе связанных прикладных объектов DMP.

В MVP модуль предоставляет:

- самостоятельное ведение `Project`;
- самостоятельное ведение `ProjectPhase`;
- принадлежность этапа проекту;
- произвольную структурную иерархию этапов внутри проекта;
- ответственные подразделения, ответственных сотрудников и организационные единицы-исполнители;
- lookup-источники проектов и этапов с согласованным выбором пары `Project` / `ProjectPhase`;
- самостоятельное ведение иерархического каталога `CostCode` в пределах tenant;
- связи проектов и этапов с объектами других модулей через внешние ссылки.

Модуль не реализует календарно-сетевое планирование проекта. Сроки, работы, связи работ, плановые и фактические показатели, варианты планов, baseline и контроль исполнения относятся к будущему функционалу планирования проекта.

## 2. Место модуля в DMP

Модуль относится к прикладной области `06_project_management`.

PR06 является владельцем объектов `Project` и `ProjectPhase`. Модули, в которых возникают заказы, аналитики, документы, логистические и плановые объекты, владеют собственными объектами и хранят ссылки на проект или этап проекта.

PR06 также владеет объектом `CostCode`. Внешние модули хранят собственные ссылки на него; прямой связи `CostCode` с `Project` или `ProjectPhase` нет.

Проект и этап проекта используются как сквозные аналитические разрезы, но это не передает владение ими потребляющим модулям. PR07 использует ссылки на проекты из заказов, PR05 предоставляет документные связи, а планирование и учет используют эти объекты в собственных сценариях.

## 3. Основные объекты

| Объект | Русское название | Назначение |
|---|---|---|
| `Project` | Проект | Самостоятельный объект PR06, объединяющий этапы и задающий верхний уровень проектной аналитики. |
| `ProjectPhase` | Этап проекта | Самостоятельный объект PR06, принадлежащий проекту и входящий в структурное дерево этапов. |
| `ProjectBase` | Общий логический предок проекта и этапа проекта | Логическая абстракция общих полей и правил. Не является runtime object type, пользовательским объектом, lookup-источником или отдельным объектом прав. |
| `CostCode` | Код затрат | Самостоятельный каталоговый объект PR06 с иерархией и обязательной tenant-границей. |

## 4. Ключевые проектные решения

| Решение | Суть | Документ |
|---|---|---|
| Граница MVP | В MVP входят `Project` и `ProjectPhase` как структурные и аналитические объекты. Высокоуровневый план проекта и контроль исполнения не входят. | [01_scope.md](01_scope.md) |
| Логическое наследование | `ProjectBase` сохраняется как общий логический предок. `Project` и `ProjectPhase` остаются отдельными бизнес-объектами и типами Object Runtime. | [02_domain_model.md](02_domain_model.md) |
| Структура этапов | `ProjectPhase.Parent -> ProjectPhase` поддерживает произвольное дерево внутри одного проекта. Иерархия не задает сроки и зависимости работ. | [02_domain_model.md](02_domain_model.md) |
| Согласованность аналитик | При заполненном `Project` список этапов фильтруется по проекту. При выборе этапа проект подставляется автоматически. Противоречивую пару сохранить нельзя. | [03_object_runtime_model.md](03_object_runtime_model.md) |
| Ответственность и исполнение | В `ProjectBase` используются `ResponsibleProductionUnit -> ProductionUnit`, `ResponsiblePerson -> Personnel` и `ExecutorOrganizationalUnit -> OrganizationalUnit`. Допустимые исполнители: собственная производственная единица и субподрядчик. | [02_domain_model.md](02_domain_model.md) |
| Жизненный цикл MVP | Прикладные `Status` и workflow для объектов PR06 не вводятся. Используются стандартные операции Object Runtime, архивирование и удаление по правилам модуля. | [05_rules.md](05_rules.md) |
| Коды затрат | `CostCode` является самостоятельным объектом PR06 с иерархией в пределах tenant. Прямой связи с `Project` и `ProjectPhase` нет. | [02_domain_model.md](02_domain_model.md) |
| Документы | PR06 не создает документы и файлы. К проекту или этапу можно прикрепить существующий документ через document links PR05. | [01_scope.md](01_scope.md) |
| Владение | PR06 владеет проектами и этапами; PR07 и другие модули используют только внешние ссылки на них. | [01_scope.md](01_scope.md) |

## 5. Зависимости от Foundation, Common и платформы

| Зависимость | Использование |
|---|---|
| `00_common` | Общие поля, tenant-граница, стандартное представление, архивирование, мягкое удаление, восстановление и Object Runtime. |
| `03_platform` и Foundation | Контракты Object Runtime, lookup, проверка ссылок, стандартные операции, IAM и технические данные. |
| `03_plant_structure` | `ProductionUnit`, `OrganizationalUnit` и `Subcontractor`; используется для ответственного подразделения и организации-исполнителя. |
| `04_resource_management` | `Personnel`; используется для ответственного сотрудника. |
| `05_document_management` | Существующие документы и document links с проектом или этапом. Документы, файлы и их жизненный цикл принадлежат PR05. |
| `07_order_management` | Заказы и позиции заказов используют внешние ссылки на `Project` и `ProjectPhase`; ведение проектов PR07 не выполняет. |
| `08_planning_scheduling` | Будущие плановые объекты могут использовать проект и этап как аналитические ссылки. План проекта не входит в MVP PR06. |
| `01_general_master_data` / общий контур аналитик | Внешние потребители могут ссылаться на `ProjectManagement:CostCode`; владение каталогом и его иерархией остается у PR06. |

## 6. Связь с требованиями

Источник требований: исходное проектное решение `DMP ПР06 Управление проектами_исх. ТР v0.1.docx` и раздел PR06 в `001_dmp_functional_requirements_and_constraints.md`.

| Требование | Покрытие |
|---|---|
| `REQ-06-B-001` | Входит: ведение `Project` и `ProjectPhase` в PR06. Контрольные точки исключены из текущего MVP и отложены в состав будущего плана проекта. |
| `REQ-06-B-002` | Не входит в MVP: высокоуровневый план по этапам, срокам и ожидаемым результатам. |
| `REQ-06-B-003` | Входит: PR06 ведет самостоятельный tenant-owned каталог `CostCode` с иерархией. Прямые связи с проектом и этапом не создаются. |
| `REQ-06-B-004` | Входит частично: проект и этап предоставляются как аналитические ссылки; конкретные поля ссылок принадлежат внешним модулям. |
| `REQ-06-B-005` | Не входит в MVP: версии базового плана. |
| `REQ-06-B-006` | Не входит в MVP: прикладной контроль состояния проекта и этапа. |

Трассировка отличий исходного ПР, DMP_DATA и принятых решений ведется в [90_traceability_pr06.md](90_traceability_pr06.md).
