# Граница модуля - 03 Производственная структура

## 1. Назначение документа

Документ фиксирует границы прикладного модуля **03 Производственная структура**: какие предметные объекты входят в модуль, какие объекты являются внешними ссылками, какие элементы исходного проектного решения не проектируются в этом модуле и какие ограничения должны учитываться при последующей детализации доменной модели, Object Runtime, UI и прав.

## 2. Назначение модуля

Модуль предназначен для ведения производственной структуры предприятия: собственных организационных единиц, субподрядчиков, балансовых организаций, мест хранения, зон хранения и складских ячеек.

Модуль является справочным модулем. Он не реализует производственные операции, управление ресурсами, движение запасов, расчет остатков, учет партий, графики работ, назначения персонала и оборудования.

## 3. Связь с функциональными требованиями

| Требование | Учет в модуле |
| --- | --- |
| REQ-03-B-001 | Ведение внутренних производственных единиц реализуется объектом `ProductionUnit`, наследником `OrganizationalUnit`. |
| REQ-03-B-002 | Ведение внешних элементов производственной структуры реализуется объектом `Subcontractor`, наследником `OrganizationalUnit`. |
| REQ-03-B-003 | Места хранения моделируются как `OrganizationalUnit` с признаком `IsInventoryStorageLocation` и зависимыми параметрами хранения. |
| REQ-03-B-004 | Зоны хранения и складские ячейки входят в модуль как `StorageArea`, `WarehouseBinType`, `WarehouseBin`. |
| REQ-03-B-005 | Принадлежность зон и ячеек задается ссылкой на место хранения, представленное `OrganizationalUnit`. |
| REQ-03-C1-001 | Площадки, участки, посты, зоны отгрузки и временного хранения ведутся как элементы производственной структуры или как места хранения в пределах объектов модуля. |
| LIM-03-O-001 | Детальная транспортная, инженерная и пространственная инфраструктура не входит в модуль. |
| LIM-03-O-002 | Сложные правила доступности мест хранения, зон и ячеек для процессов, материалов или пользователей не входят в первую границу модуля. |
| LIM-03-O-003 | Дополнительные условные зависимости между полями `OrganizationalUnitInventoryParameters`, включая требования к местам назначения в зависимости от `Transfer*DefaultType`, отложены до уточнения логики на последующих этапах. В v1 поля редактируются независимо, кроме явно установленных инвариантов ПР03. |

## 4. Объекты, которыми владеет модуль

| Объект | Русское название | Назначение | Примечание |
| --- | --- | --- | --- |
| `OrganizationalUnit` | Организационная единица | Абстрактный базовый объект для ссылок на собственные и внешние элементы производственной структуры. | Полноценный абстрактный контракт для Object Runtime и baseline; физически хранится в одной таблице с дискриминатором. |
| `ProductionUnit` | Производственная единица | Собственная организационная единица предприятия: предприятие, площадка, подразделение, цех, участок, склад и другие типы. | Наследник `OrganizationalUnit`. |
| `Subcontractor` | Субподрядчик | Внешняя организационная единица, используемая в производственной структуре. | Наследник `OrganizationalUnit`. Ссылка на `Contractor` внешняя и необязательная. |
| `Company` | Организация | Балансовая организация для аналитики и внешних связей. | Не является `Tenant`, `Site`, `ProductionUnit` или `Contractor`. |
| `OrganizationalUnitInventoryParameters` | Параметры места хранения | Зависимые параметры места хранения. | Создаются только для `OrganizationalUnit` с признаком `IsInventoryStorageLocation`. |
| `StorageArea` | Зона хранения | Зона внутри места хранения. | Ссылается на `OrganizationalUnit`, доступную как место хранения. |
| `WarehouseBinType` | Тип складской ячейки | Классификатор типов складских ячеек. | Справочник модуля. |
| `WarehouseBin` | Складская ячейка | Ячейка внутри места хранения и, при необходимости, зоны хранения. | Ссылается на место хранения; иерархия ячеек не должна образовывать циклы. Запас может размещаться в любой ячейке, включая имеющую дочерние ячейки. |

## 5. Внешние объекты и ссылки

| Внешний объект или механизм | Владелец | Использование в модуле |
| --- | --- | --- |
| `Contractor` | `01_general_master_data` | Необязательная ссылка из `Company` и `Subcontractor`, если балансовая организация или субподрядчик представлены контрагентом. |
| `InventoryLocationControlType` | `01_general_master_data` | Существующий SystemEnum GMD переиспользуется полями параметров места хранения без повторного объявления в ПР03. |
| `Tenant` | Платформа / ядро | Граница данных, доступа и конфигурации. Не является объектом модуля. |
| `Site` | Платформа / ядро | Платформенный scope внутри tenant для площадочных прав, настроек и видимости. Может быть связан с `ProductionUnit` типа `Site`, но не является объектом модуля. |
| Settings | Платформа / модуль-владелец настройки | Старые параметры `PlantParameters` не являются объектом модуля; настройки регистрируются владельцами прикладной логики. |
| Ресурсы, рабочие места, персонал, оборудование | Модуль управления ресурсами | Используют ссылки на производственную структуру, но не входят в модуль. |
| Движение запасов, остатки, партии, логистические операции | Модуль производственной логистики | Используют места хранения и параметры хранения, но не входят в модуль. |
| Параметры операций производственной единицы | Модуль управления ресурсами | `ProductionUnitOperationParameters` принадлежит модулю управления ресурсами. Модуль 03 предоставляет `ProductionUnit` как внешний объект ссылки и не изменяет параметры. |
| Назначения графиков организационных единиц | Модуль управления ресурсами | `OrganizationalUnitWorkSchedule` принадлежит модулю управления ресурсами и ссылается на `OrganizationalUnit`. В модуле 03 допускается только обратная навигация к связанным назначениям. |

## 6. Системные enum и ValueSet

Модуль владеет системными enum, которые используются в полях объектов модуля:

- `ProductionUnitType`;
- `OrganizationalUnitKind`;
- `WIPSegmentStage`;
- `WIPActionTransferYieldType`;
- `WIPActionTransferRejectType`;
- `WIPActionTransferScrapType`.

`InventoryLocationControlType` не принадлежит ПР03: модуль переиспользует SystemEnum с тем же именем и значениями `None = 0`, `Enable = 1`, `Mandatory = 2`, уже реализованный в `01_general_master_data`.

Состав значений `ProductionUnitType`:

| Код | Русское название |
| --- | --- |
| `Enterprise` | Предприятие |
| `Site` | Площадка |
| `Department` | Подразделение |
| `Shopfloor` | Цех |
| `ShopfloorArea` | Производственный участок |
| `Warehouse` | Склад |
| `RepairService` | Ремонтная служба |
| `Other` | Другое |

Состав `ProductionUnitType` является закрытым для v1 и не расширяется отдельными значениями для линий, постов, отделов, служб, бюро, кладовых и других упомянутых в требованиях элементов. Если семантика элемента соответствует существующему типу, используется этот тип; в остальных случаях используется `Other`, а конкретное назначение отражается в наименовании и описании производственной единицы.

Собственные `ValueSet` в модуле на текущем этапе не вводятся. Классификаторы контрагентов и контактов относятся к `01_general_master_data` и не фиксируются в модуле.

## 7. Граница производственной структуры

`ProductionUnit` поддерживает иерархию через ссылку `Parent`. В одном `Tenant` допускается несколько корневых `ProductionUnit` типа `Enterprise`. Корневой элемент имеет `Parent = null`.

Для некорневых производственных единиц в v1 не задается матрица допустимых сочетаний типов родителя и потомка. После корневого `Enterprise` допускается произвольная последовательность значений `ProductionUnitType`, кроме размещения другого `Enterprise` в качестве дочернего узла.

Поле `Main` используется как root-ссылка hierarchy capability Object Runtime. Для корневого `Enterprise` поле `Main` указывает на сам объект. Поле не редактируется пользователем.

`ProductionUnit` типа `Site` представляет площадку в производственной структуре. Если для площадки требуется платформенная область прав, настроек или видимости, соответствующий платформенный `Site` связывается с этой `ProductionUnit`. Обратное требование не вводится: производственная площадка может существовать без отдельного платформенного `Site`.

## 8. Граница мест хранения

Место хранения представляется `OrganizationalUnit` с признаком `IsInventoryStorageLocation = true`. Местом хранения допускается как `ProductionUnit`, так и `Subcontractor`.

Для такой организационной единицы ведется один зависимый объект `OrganizationalUnitInventoryParameters`. Снятие признака места хранения запрещено при наличии неархивированных и неудаленных зон хранения или складских ячеек модуля ПР03. После успешной проверки признаку присваивается значение `false`, а зависимые параметры физически удаляются в рамках той же операции сохранения.

Проверка входящих ссылок и блокирующего использования из других модулей не входит в v1: общий платформенный механизм dependency checks отсутствует. До его появления целостность своих ссылок при отключении или архивировании объекта обеспечивает модуль-потребитель.

`StorageArea` и `WarehouseBin` выбирают только активные организационные единицы, доступные как места хранения. Состояние Workflow организационной единицы не ограничивает этот выбор: место хранения в `Draft` допускается наравне с местом хранения в `Published`. Зона хранения, ячейка и родительская ячейка должны относиться к одному месту хранения.

Сквозной контракт для ПР03 и всех модулей-потребителей: если объект содержит связанную пару ссылок на место хранения и `WarehouseBin`, выбор ячейки доступен только после выбора места хранения. Без места хранения ссылка на ячейку должна быть пустой. Lookup ячейки ограничивается выбранным местом хранения; при очистке или замене места хранения выбранная ячейка очищается. Ограничение обеспечивается одновременно UI и серверной валидацией модуля, сохраняющего такую пару ссылок.

## 9. Элементы источников вне границы модуля

| Элемент источника | Решение |
| --- | --- |
| `PlantParameters` | Не проектируется как объект модуля. Старые поля распределяются по settings владельцев прикладной логики или удаляются из целевой модели. |
| `ProductionUnitOperationParameters` | Не включается во владение модулем 03; объект и его настройки принадлежат модулю управления ресурсами. |
| `InventoryStatus` | Внешний объект будущего модуля производственной логистики. В v1 ПР03 сохраняет nullable GUID-колонки будущих ссылок, но не публикует их в Object Runtime/baseline и UI до появления стабильного контракта `InventoryStatus`. |
| Статусы справочников из старой модели | Не переносятся как универсальное поле `Status`. Жизненный цикл проектируется только там, где он нужен предметно. |
| Расширенные правила доступности мест хранения | Отдельная проработка за пределами первой границы модуля. |
