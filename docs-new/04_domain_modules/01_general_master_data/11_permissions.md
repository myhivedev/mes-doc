# Права доступа - 01 General Master Data

## 1. Назначение документа

Документ фиксирует проектное решение по доступу к объектам модуля `01 General Master Data`: какие объекты защищаются самостоятельными правами, какие роли вводятся для модуля и какие особые правила доступа применяются.

Документ не описывает кнопки интерфейса, стандартные действия Object Runtime и внутреннюю реализацию Tenant Security.

## 2. Принципы доступа

GMD использует стандартную модель прав Object Runtime:

| Действие | Смысл |
|---|---|
| Просмотр | Пользователь может видеть объект в списках, карточках и списках выбора. |
| Создание | Пользователь может создать новый объект. |
| Изменение | Пользователь может изменить существующий объект. |
| Удаление | Пользователь может удалить или архивировать объект в рамках правил GMD. |

Жизненный цикл защищается отдельно от изменения карточки:

| Действие | Смысл |
|---|---|
| Просмотр жизненного цикла | Пользователь видит состояние объекта и доступные переходы. |
| Выполнение перехода | Пользователь может выполнить разрешенный переход жизненного цикла. |

Строки коллекций, которые сохраняются как часть карточки владельца, не получают собственных прав доступа. Просмотр и изменение таких строк проверяются через права на объект-владелец.

Если строка коллекции создается, изменяется или удаляется отдельной операцией Object Runtime, она получает собственные стандартные права как самостоятельный объект доступа.

## 3. Самостоятельно защищаемые объекты

| Объект | Русское название | Стандартные права | Жизненный цикл | Основание |
|---|---|---|---|---|
| `Unit` | Единица измерения | Просмотр, создание, изменение, удаление | Нет | Ведется самостоятельным списком и карточкой. |
| `UnitGroup` | Группа единиц измерения | Просмотр, создание, изменение, удаление | Нет | Ведется самостоятельным списком и карточкой. |
| `NomenclatureGroup` | Группа номенклатуры | Просмотр, создание, изменение, удаление | Нет | Ведется самостоятельным списком и карточкой. |
| `NomenclatureKind` | Вид номенклатуры | Просмотр, создание, изменение, удаление | Да | Ведется самостоятельным списком и карточкой. |
| `Nomenclature` | Номенклатурная позиция | Просмотр, создание, изменение, удаление | Да | Основной объект GMD. |
| `NomenclatureVariant` | Исполнение НП | Просмотр, создание, изменение, удаление | Нет | Редактируется отдельными операциями из карточки НП и может выбираться в других объектах. |
| `SerialNumber` | Серийный номер | Просмотр, создание, изменение, удаление | Нет | Ведется самостоятельным реестром. |
| `PackSet` | Набор упаковок | Просмотр, создание, изменение, удаление | Нет | Ведется самостоятельным списком и карточкой. |
| `Pack` | Упаковка | Просмотр, создание, изменение, удаление | Нет | Редактируется отдельными операциями для типовых и индивидуальных упаковок. |
| `TransportUnitType` | Тип единицы транспортировки | Просмотр, создание, изменение, удаление | Нет | Ведется самостоятельным списком и карточкой. |
| `NomenclatureParameter` | Реквизит номенклатуры | Просмотр, создание, изменение, удаление | Да | Ведется самостоятельным списком и карточкой. |
| `ContractorGroup` | Группа контрагентов | Просмотр, создание, изменение, удаление | Нет | Ведется самостоятельным списком и карточкой. |
| `Contractor` | Контрагент | Просмотр, создание, изменение, удаление | Нет | Ведется самостоятельным списком и карточкой. |

## 4. Строки, защищаемые через владельца

| Строка / объект | Владелец | Как проверяется доступ |
|---|---|---|
| `UnitOfOperation` | `UnitGroup`, `Nomenclature`, `Pack`, `TransportUnitType` | Через права на владельца, в карточке которого редактируется строка. |
| `NomenclatureParameterAssignment` | `NomenclatureKind`, `Nomenclature` | Через права на вид НП или НП, в карточке которых редактируется назначение. В карточке реквизита показывается обзор назначений. |
| `NomenclatureParameterEnumValue` | `NomenclatureParameter` | Через права на реквизит номенклатуры. |
| `NomenclatureParameterValue` | `Nomenclature` | Через права на НП. |
| `NomenclatureVariantParameterValue` | `NomenclatureVariant` | Через права на исполнение НП. |
| `SerialNumberParameterValue` | `SerialNumber` | Через права на серийный номер. |
| `ContractorInContractorGroup` | `ContractorGroup` | Через права на группу контрагентов. |
| `ContractorContact` | `Contractor` | Через права на контрагента. |

Если для строки будет включен режим отдельных операций Object Runtime, строка переносится в раздел 3 и получает собственные стандартные права.

## 5. Роли

| Роль | Назначение | Область действия | Базовый доступ |
|---|---|---|---|
| Администратор общей НСИ | Полное ведение объектов GMD. | Предприятие | Все стандартные права и права жизненного цикла на объекты GMD. |
| Пользователь общей НСИ | Просмотр справочников и основных данных GMD. | Предприятие | Просмотр самостоятельных объектов GMD. |
| Методолог общей НСИ | Ведение классификаторов, видов, реквизитов, единиц измерения, упаковок и типов единиц транспортировки. | Предприятие | Ведение справочников настройки GMD; выполнение жизненного цикла видов НП и реквизитов НП. |
| Ответственный за номенклатуру | Ведение НП, исполнений НП, упаковок НП и серийных номеров. | Предприятие | Просмотр настроек GMD; ведение НП и связанных объектов; выполнение жизненного цикла НП. |
| Ответственный за контрагентов | Ведение контрагентов, групп и контактов. | Предприятие | Просмотр, создание и изменение контрагентов и групп контрагентов. |

Удаление и архивирование справочников в рабочих ролях не включается по умолчанию. Такое право назначается администратору общей НСИ или отдельной роли сопровождения НСИ.

## 6. Матрица доступа ролей

В матрице используются сокращения:

| Сокращение | Состав прав |
|---|---|
| Просмотр | Просмотр объекта. Для объектов с жизненным циклом также просмотр состояния жизненного цикла. |
| Ведение | Просмотр, создание и изменение объекта. |
| Жизненный цикл | Выполнение переходов жизненного цикла. |
| Все действия | Просмотр, создание, изменение, удаление и жизненный цикл, если он есть у объекта. |

| Объект | Администратор общей НСИ | Пользователь общей НСИ | Методолог общей НСИ | Ответственный за номенклатуру | Ответственный за контрагентов |
|---|---|---|---|---|---|
| Единицы измерения | Все действия | Просмотр | Ведение | Просмотр | Просмотр |
| Группы единиц измерения | Все действия | Просмотр | Ведение | Просмотр | Просмотр |
| Группы номенклатуры | Все действия | Просмотр | Ведение | Просмотр | Просмотр |
| Виды номенклатуры | Все действия | Просмотр | Ведение, жизненный цикл | Просмотр | Просмотр |
| Номенклатурные позиции | Все действия | Просмотр | Просмотр | Ведение, жизненный цикл | Просмотр |
| Исполнения НП | Все действия | Просмотр | Просмотр | Ведение | Просмотр |
| Серийные номера | Все действия | Просмотр | Просмотр | Ведение | Просмотр |
| Наборы упаковок | Все действия | Просмотр | Ведение | Просмотр | Просмотр |
| Упаковки | Все действия | Просмотр | Ведение | Ведение | Просмотр |
| Типы единиц транспортировки | Все действия | Просмотр | Ведение | Просмотр | Просмотр |
| Реквизиты номенклатуры | Все действия | Просмотр | Ведение, жизненный цикл | Просмотр | Просмотр |
| Группы контрагентов | Все действия | Просмотр | Просмотр | Просмотр | Ведение |
| Контрагенты | Все действия | Просмотр | Просмотр | Просмотр | Ведение |

## 7. Особые правила доступа

| Сценарий | Правило доступа |
|---|---|
| Создание на основании существующего объекта | Требуется просмотр исходного объекта и создание нового объекта. Политика предзаполнения описана в `13_operations.md`. |
| Изменение строки коллекции | Требуется право изменения объекта-владельца, если строка сохраняется как часть карточки владельца. |
| Просмотр списка выбора | Требуется право просмотра выбираемого объекта. |
| Выполнение перехода жизненного цикла | Требуется право выполнения перехода жизненного цикла для данного типа объекта. |
| Изменение опубликованного объекта | Выполняется по правилам `04_workflows.md`: объект сначала возвращается в черновик, если для него включен жизненный цикл. |
| Ведение упаковок | `Pack` является единым типом объекта для типовых и индивидуальных упаковок. Матрица не разделяет права на упаковки набора и индивидуальные упаковки НП. Если такое разделение потребуется, его нужно проектировать отдельным условием доступа по владельцу упаковки или отдельной моделью объектов. |
| Сервисные функции GMD | Не являются пользовательскими правами доступа. Доступ к ним определяется правами на объекты, которые читает или изменяет вызывающий сценарий. |

## 8. Техническое отображение

Технические решения для реализации:

| Элемент | Решение |
|---|---|
| Код модуля | `GeneralMasterData` |
| Область действия прав | Предприятие |
| Кто может назначать права | Администратор предприятия |
| Область назначения ролей | Предприятие |
| Корпоративные роли | Не вводятся в v1. Если появится корпоративная НСИ, роли корпоративной области проектируются отдельно. |

Коды ролей:

| Роль | Код роли |
|---|---|
| Администратор общей НСИ | `GeneralMasterDataAdmin` |
| Пользователь общей НСИ | `GeneralMasterDataUser` |
| Методолог общей НСИ | `GeneralMasterDataMethodologist` |
| Ответственный за номенклатуру | `GeneralMasterDataNomenclatureResponsible` |
| Ответственный за контрагентов | `GeneralMasterDataContractorResponsible` |
