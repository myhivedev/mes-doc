# Заинтересованные стороны DMP

## 1. Назначение

Документ фиксирует группы заинтересованных сторон, которые должны учитывать концепция, архитектура и проектная документация DMP.

Документ не назначает конкретных персональных владельцев и не заменяет матрицу согласования документов.

## 2. Группы заинтересованных сторон

| Группа | Интерес к системе | Какие документы читают в первую очередь |
| --- | --- | --- |
| Руководство производственного контура | Прозрачность заказов, сроки, WIP, загрузка ресурсов, управляемость внедрения. | `01_concept`, `02_architecture` |
| Производственные пользователи | Выполнение операций, диспетчеризация, фактические данные, удобство рабочих сценариев. | `04_domain_modules`, frontend-документы владельцев |
| Планирование и диспетчеризация | Расписания, очереди, приоритеты, перепланирование и связь с заказами и ресурсами. | `04_domain_modules/08_planning_scheduling`, `02_architecture` |
| Качество | Контроль операций, несоответствия, результаты проверок и трассируемость. | `04_domain_modules`, `03_platform/09_audit_history` |
| Интеграторы | Обмен с ERP, CAD/PDM, MDC, оборудованием и внешними сервисами. | `02_architecture/07_integration_architecture.md`, документы владельцев контрактов, будущая область интеграций |
| Архитекторы и технические лиды | Границы платформы, модулей, данных, контрактов, deployment и технических решений. | `02_architecture`, `03_platform`, `90_traceability` документов-владельцев, `10_backlog` |
| Разработчики backend/frontend | Контракты, runtime-правила, стандарты модулей, frontend platform и границы реализации. | `03_platform`, `04_domain_modules` |
| QA | Проверяемые требования, acceptance criteria, E2E и traceability. | `03_platform/*/07_quality.md`, `90_traceability` документов-владельцев, `10_backlog` |
| DevOps/SRE | Deployment, диагностика, эксплуатация, восстановление и наблюдаемость. | `02_architecture/06_deployment_architecture.md`, `03_platform/*/08_operations.md`; будущий `07_operations` только для сквозных runbooks |
| Заказчик и представители предприятий | Понятная область системы, бизнес-цели, ограничения и эффект внедрения. | `01_concept`, `02_architecture` |

## 3. Принципы взаимодействия с документацией

- Верхний слой должен быть понятен без знания внутренней истории обсуждений.
- Детальные решения должны иметь владельца и ссылку из верхнего слоя.
- Открытые вопросы не должны маскироваться под утверждённые требования.
- Импортированные копии исходников и исследовательские материалы используются для анализа, но не являются финальной нормативной базой.
