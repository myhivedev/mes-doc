# Обзор модуля — Управление документацией

## 1. Назначение модуля

Модуль ведёт документы предприятия, их версии, каталоги, типы, содержимое и связи с бизнес-объектами DMP. Пользователь работает с файлами, внешними ссылками и текстом через единый объект «Содержимое документа» (`DocumentContent`).

## 2. Место модуля в DMP

Модуль относится к прикладной области `05_document_management`. Он использует общие объекты, среду выполнения объектов, жизненные циклы, нумерацию, настройки, управление доступом и историю аудита платформы.

## 3. Основные объекты

| Пользовательское название | Техническое имя | Назначение |
|---|---|---|
| Документ | `Document` | Хранит реквизиты одной версии документа. |
| Каталог документов | `DocumentFolder` | Формирует иерархию электронного архива. |
| Тип документа | `DocumentType` | Задаёт классификацию, хранилище и ограничения файлов. |
| Хранилище документов | `DocumentStorage` | Системная запись хранилища; в MVP используется только хранилище «База данных». |
| Содержимое документа | `DocumentContent` | Хранит один файл, одну ссылку или один текст. |
| Связь документа с содержимым | `DocumentContentLink` | Связывает документ с переиспользуемым содержимым. |
| Связь документа с бизнес-объектом | `DocumentObjectLink` | Связывает документ с записью объекта другого модуля. |

## 4. Ключевые проектные решения

| Решение                         | Суть                                                                                                                                  | Документ                                 |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| Версионность                    | Новая версия сохраняет номер документа, увеличивает номер версии и создаётся в состоянии «Черновик».                                  | [04_workflows.md](04_workflows.md)       |
| Нумерация                       | Платформа формирует код типа и номер документа; номер документа разрешено изменить вручную.                                           | [05_rules.md](05_rules.md)               |
| Неизменяемое содержимое         | После первого прикрепления к документу не изменяются двоичные данные и имя файла, адрес ссылки или текст. Для исправления создаётся новая запись содержимого. | [05_rules.md](05_rules.md)               |
| Удаление содержимого без связей | После удаления последней связи содержимое сразу удаляется мягко в той же целостной операции.                                          | [13_operations.md](13_operations.md)     |
| Настройки                       | Настройки предприятия хранятся платформенным механизмом, отдельный доменный объект настроек не создаётся.                             | [16_settings.md](16_settings.md)         |
| Ответственное подразделение     | Поле «Ответственное подразделение» (`ProductionUnitResponsible`) ссылается на внутреннюю производственную единицу (`ProductionUnit`). | [02_domain_model.md](02_domain_model.md) |

## 5. Зависимости от Common и платформы

- общие поля, архивирование и мягкое удаление — `00_common`;
- проверка универсальной ссылки — среда выполнения объектов;
- состояния и переходы документа — платформа жизненных циклов;
- автоматическое формирование номеров — платформа нумерации;
- значения настроек предприятия — платформенный механизм настроек;
- роли и серверная проверка доступа — управление идентификацией и доступом;
- история значимых операций — общая подсистема аудита.

## 9. Платформенные зависимости

Решения модуля, для которых требуется развитие или подтверждение возможностей платформы, отделены от предметных открытых вопросов. Единый перечень приведён в [90_traceability_pr05.md](90_traceability_pr05.md). Предложения по изменению существующих планов работ и созданию новых задач имеют статус «Требует решения Главного архитектора»; до согласования задачи в `plans` не создаются.

## 10. Платформенное содержимое

Файловое `DocumentContent` использует `ContentRef` и descriptor Platform Content
Storage; модуль не знает таблицу, provider или физический путь. URL и Text
остаются предметными значениями. См. [границу capability](../../03_platform/13_content_storage/00_platform_overview.md).
