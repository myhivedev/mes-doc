# Предлагаемая реализация в SIGMA.MES

Основная идея: связать производственный график и проект подготовки документации через отдельный объект — **контрольную связь подготовки производства**.

Проектное управление не рассчитывает производственный график. Оно получает из модуля планирования требуемые даты начала изготовления узлов и на их основании рассчитывает план подготовки документации назад от заданных сроков.

## 1. Разделение ответственности модулей

| Модуль | Ответственность |
|---|---|
| Управление заказами | Заявка производству, производственные заказы |
| Структуры и технологии | Состав изделия, схема деления, версии структуры, маршруты изготовления |
| Планирование | Разузлование, расчёт графика изготовления изделия, узлов и деталей |
| Управление проектами | Формирование и расчёт графика подготовки документации |
| Управление документами | Состав, версии, согласование и выпуск документации |
| Управление операциями | Фактическое выполнение производственных операций |

## 2. Сквозной процесс

```text
Заявка производству
        ↓
Выбор версии изделия и схемы деления
        ↓
Автоматическое выделение крупных узлов
        ↓
Формирование этапов сборки и потребностей в узлах
        ↓
Разузлование и расчёт производственного графика
        ↓
Определение дат начала изготовления крупных узлов
и входящих в них деталей
        ↓
Формирование контрольных связей подготовки производства
        ↓
Создание проекта подготовки документации
        ↓
Создание этапа проекта для каждого крупного узла
        ↓
Наполнение этапов работами по шаблонам
        ↓
Обратный расчёт сроков работ
        ↓
Контроль выпуска документации и факта выполнения
```

## 3. Выделение крупных узлов

Крупные узлы должны определяться по утверждённой версии схемы деления, а не вводиться пользователем повторно.

Для узла схемы деления предлагаются признаки:

- `Уровень планирования`;
- `Признак крупного узла`;
- `Изготавливается отдельным производственным заказом`;
- `Этап сборки-потребитель`;
- `Правило комплектования`;
- `Ответственное подразделение`;
- `Шаблон подготовки документации`.

Крупным считается узел, который:

- является сборочной единицей;
- выделен как самостоятельный объект планирования;
- имеет собственный цикл изготовления или производственный заказ;
- требуется на определённом этапе сборки изделия.

**Сходящие детали** — все нижестоящие элементы производственной структуры крупного узла до границ других самостоятельно планируемых крупных узлов.

## 4. Производственный график

Модуль планирования выполняет разузлование и рассчитывает:

- сроки изготовления деталей;
- сроки изготовления сборочных единиц;
- сроки начала и завершения изготовления крупного узла;
- срок передачи узла на этап сборки изделия;
- резервы и выявленные дефициты.

Для подготовки документации используется ранняя дата начала работ в производственном контуре крупного узла:

`Дата начала контура узла = минимальная дата начала изготовления узла и всех сходящих деталей`

Требуемая дата выпуска документации:

`Требуемая дата выпуска = дата начала контура узла − нормативный резерв`

Нормативный резерв может включать:

- передачу документации в производство;
- проверку применимости версии;
- подготовку программ и оснастки;
- технологическое освоение;
- организационный резерв.

Если резерв не задан, используется нулевое значение.

## 5. Контрольная связь подготовки производства

Предлагаемый бизнес-класс: **Контрольная связь подготовки производства**.

| Атрибут | Назначение |
|---|---|
| Заявка производству | Исходная потребность |
| Версия изделия | Зафиксированная конфигурация |
| Версия схемы деления | Источник состава |
| Крупный узел | Планируемый узел |
| Этап сборки | Где требуется узел |
| Потребность этапа сборки | Связь с количеством и сроком |
| Версия производственного плана | Источник расчётных дат |
| Объект производственного плана | Заказ, этап, партия или операция |
| Плановое начало изготовления | Полученная производственная дата |
| Нормативный резерв | Смещение срока выпуска документации |
| Требуемая дата выпуска документации | Ограничение проекта |
| Проект | Проект подготовки документации |
| Этап проекта | Этап по крупному узлу |
| Статус синхронизации | Актуально, изменено, требует принятия |
| Версия исходных данных | Защита от повторной обработки |

Эта сущность обеспечивает трассировку:

`Заявка → изделие → крупный узел → этап сборки → производственный план → этап проекта → документация`

## 6. Проект подготовки документации

Для заявки создаётся один проект типа, например:

- «Конструкторско-технологическая подготовка производства»;
- «Подготовка производства изделия»;
- «НИОКР и подготовка производства».

Для каждого крупного узла автоматически создаётся отдельный этап проекта.

Пример структуры:

```text
Проект подготовки изделия
├── Узел 01
│   ├── Разработка конструкторской документации
│   ├── Проверка и согласование
│   ├── Разработка технологических процессов
│   ├── Проектирование оснастки
│   ├── Разработка управляющих программ
│   └── Контрольная точка «Документация выпущена»
├── Узел 02
│   └── ...
└── Узел 03
    └── ...
```

Наполнение этапа производится по шаблону, выбранному по типу узла, виду производства или сложности.

Для работы задаются:

- нормативная длительность;
- трудоёмкость в нормо-часах;
- требуемые квалификации;
- календарь;
- предшествующие работы;
- тип связи;
- задержка или опережение;
- результат работы;
- требуемая документация;
- ответственное подразделение.

## 7. Расчёт сроков проекта

Этап рассчитывается назад от требуемой даты выпуска документации.

1. Окончание этапа устанавливается равным требуемой дате выпуска.
2. Работы создаются по шаблону.
3. С учётом зависимостей, длительности и календарей рассчитываются даты окончания и начала работ.
4. Рассчитывается требуемая дата начала этапа.
5. Проверяется возможность выполнения с учётом текущей даты и доступности исполнителей.

Если расчётная дата начала уже прошла, система не должна автоматически сокращать нормативы. Она фиксирует:

- отрицательный временной резерв;
- величину прогнозного опоздания;
- проблемные работы;
- необходимость изменения производственного или проектного срока.

Детальная оптимизация загрузки производственных ресурсов остаётся в модуле планирования.

## 8. Перепланирование

Изменение производственного графика не должно сразу перезаписывать утверждённый проектный план.

При изменении заявки, структуры или производственных дат система:

1. Находит затронутые крупные узлы.
2. Пересчитывает требуемые даты документации.
3. Сравнивает их с действующим проектным планом.
4. Создаёт предложение изменения и черновую версию плана.
5. Показывает отклонения по этапам и работам.
6. После подтверждения публикует новую версию.
7. Сохраняет предыдущий базовый план для сравнения.

Статусы синхронизации:

- актуально;
- источник изменён;
- требуется перерасчёт;
- требуется принятие;
- принято;
- отклонено;
- связь устарела;
- ошибка исходных данных.

## 9. Защита от дублирования

Необходимы уникальные ограничения:

- проект: `заявка + версия изделия + вид проекта`;
- крупный узел: `версия схемы деления + узел`;
- этап проекта: `проект + крупный узел`;
- потребность: `этап сборки + крупный узел`;
- работа по шаблону: `этап проекта + постоянный код пункта шаблона`.

Повторный расчёт обновляет существующие связи и создаёт новую версию плана, но не создаёт повторные проекты, этапы и работы.

Опубликованные объекты не удаляются: они получают признак «замещён новой версией» или «утратил актуальность».

## 10. Основные бизнес-классы и связи

```text
ЗаявкаПроизводству
 ├── ВерсияИзделия
 │    └── ВерсияСхемыДеления
 │         └── УзелСхемыДеления
 │              └── ВыделениеКрупногоУзла
 ├── ЭтапСборки
 │    └── ПотребностьЭтапаСборки ── КрупныйУзел
 ├── ВерсияПроизводственногоПлана
 │    └── ОбъектПроизводственногоПлана
 └── КонтрольнаяСвязьПодготовки
      ├── КрупныйУзел
      ├── ПотребностьЭтапаСборки
      ├── ОбъектПроизводственногоПлана
      └── ЭтапПроекта

Проект
 └── ЭлементПроекта
      ├── Этап
      ├── Работа
      └── КонтрольнаяТочка
           ├── Зависимость
           ├── ПотребностьВКвалификации
           ├── НазначениеИсполнителя
           ├── ФактВыполнения
           └── ТребованиеКДокументации
```

## 11. Фиксация факта

Факт выполнения проектных работ может поступать:

- непосредственно от исполнителя;
- из маршрута согласования документа;
- из события утверждения или выпуска документации;
- из связанной задачи подразделения.

Этап крупного узла считается завершённым, когда:

- обязательные работы завершены;
- обязательные документы выпущены в требуемых версиях;
- достигнута контрольная точка готовности документации.

Готовность должна передаваться в производственное планирование как предупреждение или ограничение. Она не должна автоматически изменять опубликованный производственный план без отдельного согласованного процесса.

## Ограничения решения

- Используется только утверждённая версия структуры изделия.
- Без опубликованного производственного плана проектный график считается предварительным.
- Содержание и версии документов ведутся в управлении документами.
- Подробное производственное расписание не переносится в управление проектами.
- Автоматическое перепланирование опубликованного проекта без подтверждения запрещено.
- При изменении состава изделия должна выполняться оценка влияния на крупные узлы и документацию.
