# Обзор платформенной области — Value Sets

## 1. Назначение области

Value Sets хранит фактические элементы наборов значений, строит эффективный
набор для текущего контекста и предоставляет API для runtime и редактора данных.
Схема набора (`ValueSet`) является артефактом Configuration; Value Sets
использует опубликованные метаданные схемы, но не владеет ею.

## 2. Место в платформе

```text
Configuration
  Схема ValueSet
             |
             | опубликованная схема / начальные данные
             v
Value Sets
  ValueSetDataSet + ValueSetItem
             |
       +-----+-----+
       |           |
       v           v
  Runtime API   Data Editor API
```

Потребители используют стабильные `ValueSetCode` и `ValueSetItem.Code`, а не
внутренние идентификаторы строк. Общая карта взаимодействий находится в
[интеграционной архитектуре](../../02_architecture/07_integration_architecture.md).

### 2.1. Ключевые термины

| Русский термин | Технический термин | Значение |
| --- | --- | --- |
| Набор значений | `ValueSet` | Определение источника допустимых значений в Configuration |
| Данные набора значений | `ValueSetData` | Фактические элементы, которыми владеет Value Sets |
| Элемент набора | `ValueSetItem` | Одна фактическая строка набора |
| Набор данных значений | `ValueSetDataSet` | Хранимый контейнер элементов одного `ValueSetCode` |
| Эффективный набор | effective value set | Результат выбора строк для текущей области данных |
| Область данных набора | data scope | `Global`, `Tenant` или `Site` |
| Переопределение элемента | scoped override | Более специфичная строка с тем же `Code` |

`SystemEnum` не является редактируемым набором значений Value Sets. Его значения
задаются кодом или системным поставщиком значений (provider) и обслуживаются вне
`DMP.Platform.ValueSets`. Полный список терминов ведётся в
[платформенном глоссарии][platform-terms].

## 3. Основные возможности

| Возможность | Назначение | Статус | Основание |
| --- | --- | --- | --- |
| Хранение элементов | Хранить `ValueSetDataSet` и `ValueSetItem` | Подтверждено MVP | Модель и persistence Value Sets |
| Эффективный набор | Выбирать одну строку для каждого `Code` по приоритету `Site` > `Tenant` > `Global` | Подтверждено MVP | Runtime и тесты области |
| Runtime API | Возвращать элементы и options с учётом контекста | Подтверждено MVP | Контракты и API Value Sets |
| Data editor API | Просматривать, создавать, изменять, активировать и деактивировать элементы | Подтверждено MVP | Контракты и сервис редактора |
| Плоская иерархическая структура | Поддерживать `Flat` и `Hierarchical` наборы | Подтверждено MVP | Контракт `Structure` и проверки |

## 4. Ключевые решения

| Решение | Суть | Документ-владелец |
| --- | --- | --- |
| Владелец `ValueSet` schema | Схема и её публикация принадлежат Configuration; Value Sets хранит только опубликованные метаданные и данные | `../02_configuration/` |
| Области данных | Элементы могут иметь область `Global`, `Tenant` или `Site`; приоритет effective-результата — `Site` > `Tenant` > `Global` | `02_architecture.md`, `04_runtime.md` |
| Граница `SystemEnum` | `SystemEnum` не входит в Value Sets и не является режимом редактируемого набора | `../02_configuration/artifact_types/system_enum.md` |

## 6. Статус реализации

| Состояние | Значение | Основание |
| --- | --- | --- |
| Подтверждено MVP | Хранилище, области данных, построение эффективного набора, иерархия, API, серверная часть и интеграция редактора данных в Studio | Код, контракты и интеграционные тесты |
| Подтверждено, но ограничено | Проекция и начальные данные зависят от композиции host-приложения; удаление элементов и событие сброса кэша не входят в текущий контракт | `90_traceability.md` |
| Будущая доработка | Удаление элементов, метка удаления унаследованной строки, отдельная локализация элементов и export/import между окружениями; интеграция в Admin и другие приложения не подтверждена | `90_traceability.md` и backlog |
