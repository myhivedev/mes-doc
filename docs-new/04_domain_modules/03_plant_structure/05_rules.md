# Правила и ограничения - 03 Производственная структура

## 1. Назначение документа

Документ фиксирует инварианты, проверки и ограничения изменения данных модуля `03 Plant Structure`.

Поля объектов описаны в `02_domain_model.md`. Runtime-обработчики, которые вызывают проверки, описаны в `03_object_runtime_model.md`. Жизненный цикл описан в `04_workflows.md`.

## 2. Общие правила

Все правила применяются в пределах одного `Tenant`, если в правиле явно не указано иное.

Object Runtime должен применять общие правила Common:

- `TenantId` ссылочного объекта должен совпадать с `TenantId` владельца;
- пользователь не редактирует системные поля Common.

## 3. Правила OrganizationalUnit

| Код | Правило | Проверка | Сообщение |
|---|---|---|---|
| `PS-OU-001` | Конкретный тип обязателен | `UnitKind` заполнен значением `ProductionUnit` или `Subcontractor`. | Вид организационной единицы должен быть указан. |
| `PS-OU-002` | Прямое создание абстрактного объекта запрещено | Пользовательский create-запрос к `OrganizationalUnit` отклоняется. | Организационная единица создается как производственная единица или субподрядчик. |
| `PS-OU-003` | Наименование обязательно | `Name` заполнено. | Наименование организационной единицы должно быть заполнено. |
| `PS-OU-004` | Параметры хранения существуют только для места хранения | Если `IsInventoryStorageLocation = true`, существует одна запись `OrganizationalUnitInventoryParameters`; если `false`, такой записи нет. | Параметры хранения допускаются только для организационной единицы, являющейся местом хранения. |

## 4. Правила ProductionUnit

| Код | Правило | Проверка | Сообщение |
|---|---|---|---|
| `PS-PU-001` | Тип производственной единицы обязателен | `Type` заполнен. | Тип производственной единицы должен быть указан. |
| `PS-PU-002` | Корневой элемент имеет тип `Enterprise` | Если `Parent = null`, то `Type = Enterprise`. | Корневой элемент производственной структуры должен иметь тип Предприятие. |
| `PS-PU-003` | `Enterprise` является только корнем | Если `Type = Enterprise`, то `Parent = null`. | Производственная единица типа Предприятие не должна иметь вышестоящую производственную единицу. |
| `PS-PU-004` | Некорневой элемент имеет родителя | Если `Type != Enterprise`, то `Parent` заполнен. | Для производственной единицы должен быть указан вышестоящий элемент. |
| `PS-PU-005` | `Main` указывает на корень дерева | `Main` равно корневой `ProductionUnit` типа `Enterprise` текущей ветки. | Главная производственная единица должна указывать на корневое предприятие. |
| `PS-PU-006` | `Main` не редактируется пользователем | Значение `Main` изменяется только hierarchy capability Object Runtime. | Главная производственная единица рассчитывается системой. |
| `PS-PU-007` | Иерархия не содержит циклов | Проверка выполняется hierarchy capability Object Runtime по `Parent`. | Производственная структура не должна содержать циклов. |
| `PS-PU-008` | Родитель находится в том же tenant | `Parent.TenantId = ProductionUnit.TenantId`. | Вышестоящая производственная единица должна относиться к тому же tenant. |
| `PS-PU-009` | `Site` является производственной площадкой | `Type = Site` используется только для `ProductionUnit`, не для `Subcontractor` и не для платформенного `Site`. | Тип Площадка применяется только к производственной единице. |
| `PS-PU-010` | Служебные поля иерархии не редактируются пользователем | `Main`, `Level`, `Path` и виртуальное поле `HasChildren` изменяются только hierarchy capability Object Runtime. | Служебные поля иерархии рассчитываются системой. |
| `PS-PU-011` | Типы некорневых узлов комбинируются свободно | Для `Type != Enterprise` не проверяется матрица совместимости `Parent.Type -> Type`. Применяются только общие правила наличия родителя, tenant, циклов и запрет дочернего `Enterprise`. | Нет ошибки совместимости типов родителя и дочерней производственной единицы. |

Уникальность `Code` и `ExternalId` задается по общим правилам Common и baseline-конфигурации объекта. Если область уникальности не задана явно в baseline, проверка выполняется в пределах `Tenant`.

## 5. Правила Subcontractor

| Код | Правило | Проверка | Сообщение |
|---|---|---|---|
| `PS-SC-001` | Ссылка на контрагента необязательна | Для `Contractor` допускается пустое значение. | Нет ошибки. |
| `PS-SC-002` | Контрагент должен быть внешним объектом GMD | Если `Contractor` заполнен, он должен существовать в `01_general_master_data` и быть доступен текущему пользователю. | Указанный контрагент недоступен. |
| `PS-SC-003` | Субподрядчик допускается как место хранения | Если `IsInventoryStorageLocation = true`, для него применяются правила места хранения. | Параметры хранения субподрядчика должны соответствовать правилам места хранения. |

## 6. Правила Company

| Код | Правило | Проверка | Сообщение |
|---|---|---|---|
| `PS-CO-001` | Организация является балансовой организацией | `Company` не используется как `Tenant`, `Site`, `ProductionUnit` или `Contractor`. | Организация не заменяет tenant, площадку, производственную единицу или контрагента. |
| `PS-CO-002` | Ссылка на контрагента необязательна | Для `Contractor` допускается пустое значение. | Нет ошибки. |
| `PS-CO-003` | Контрагент должен быть внешним объектом GMD | Если `Contractor` заполнен, он должен существовать в `01_general_master_data` и быть доступен текущему пользователю. | Указанный контрагент недоступен. |

## 7. Правила места хранения

| Код | Правило | Проверка | Сообщение |
|---|---|---|---|
| `PS-ST-001` | Место хранения задается признаком организационной единицы | `StorageArea.Warehouse`, `WarehouseBin.Warehouse` и поля `*Warehouse` в параметрах хранения выбирают только активные `OrganizationalUnit` с `IsInventoryStorageLocation = true`. Состояние Workflow (`Draft` или `Published`) на допустимость выбора не влияет. | Выбранная организационная единица не является доступным местом хранения. |
| `PS-ST-002` | Параметры хранения принадлежат одной организационной единице | Для одной `OrganizationalUnit` существует не более одной записи `OrganizationalUnitInventoryParameters`. | Для места хранения уже существуют параметры хранения. |
| `PS-ST-003` | Снятие признака места хранения проверяется по зависимым объектам ПР03 | При изменении `IsInventoryStorageLocation` с `true` на `false` не должно быть неархивированных и неудаленных `StorageArea` и `WarehouseBin` ПР03, относящихся к организационной единице. Если проверка не пройдена, изменение отклоняется и значение признака не изменяется. Если проверка пройдена, признак устанавливается в `false`, а связанная запись `OrganizationalUnitInventoryParameters` удаляется в рамках той же операции сохранения. | Нельзя отключить место хранения, пока у него есть неархивированные и неудаленные зоны или складские ячейки ПР03. |

Правило `PS-ST-004` зарезервировано для будущей проверки ссылок на `InventoryStatus`. В v1 оно не регистрируется и не выполняется, поскольку status-поля не публикуются в Object Runtime.

## 8. Правила StorageArea

| Код | Правило | Проверка | Сообщение |
|---|---|---|---|
| `PS-SA-001` | Зона относится к месту хранения | `Warehouse.IsInventoryStorageLocation = true`. | Зона хранения должна относиться к месту хранения. |
| `PS-SA-002` | Наименование обязательно | `Name` заполнено. | Наименование зоны хранения должно быть заполнено. |
| `PS-SA-003` | Код зоны уникален в пределах места хранения | Для одного `Warehouse` не должно быть двух активных зон с одинаковым `Code`. | Код зоны хранения должен быть уникален в пределах места хранения. |
| `PS-SA-004` | Нельзя архивировать зону с активными ячейками | Нет активных `WarehouseBin`, ссылающихся на зону. | Нельзя архивировать зону хранения, пока в ней есть активные складские ячейки. |
| `PS-SA-005` | Изменение места хранения зоны не нарушает принадлежность ячеек | При изменении `Warehouse` у зоны нет неархивированных и неудаленных `WarehouseBin`, ссылающихся на эту зону. | Нельзя изменить место хранения зоны, пока в ней есть неархивированные и неудаленные складские ячейки. |

## 9. Правила WarehouseBinType

| Код | Правило | Проверка | Сообщение |
|---|---|---|---|
| `PS-WBT-001` | Наименование обязательно | `Name` заполнено. | Наименование типа складской ячейки должно быть заполнено. |
| `PS-WBT-002` | Код типа уникален | В пределах `Tenant` нет активного типа складской ячейки с таким же `Code`. | Код типа складской ячейки должен быть уникальным. |
| `PS-WBT-003` | Нельзя архивировать используемый тип | Нет активных `WarehouseBin`, ссылающихся на тип. | Нельзя архивировать тип складской ячейки, пока он используется. |

## 10. Правила WarehouseBin

| Код | Правило | Проверка | Сообщение |
|---|---|---|---|
| `PS-WB-001` | Ячейка относится к месту хранения | `Warehouse.IsInventoryStorageLocation = true`. | Складская ячейка должна относиться к месту хранения. |
| `PS-WB-002` | Обозначение обязательно | `Identification` заполнено. | Обозначение складской ячейки должно быть заполнено. |
| `PS-WB-003` | Обозначение уникально в пределах места хранения | Для одного `Warehouse` нет активной ячейки с таким же `Identification`. | Обозначение складской ячейки должно быть уникально в пределах места хранения. |
| `PS-WB-004` | Зона принадлежит тому же месту хранения | Если `StorageArea` заполнена, то `StorageArea.Warehouse = Warehouse`. | Зона хранения должна относиться к тому же месту хранения, что и складская ячейка. |
| `PS-WB-005` | Родительская ячейка принадлежит тому же месту хранения | Если `Parent` заполнена, то `Parent.Warehouse = Warehouse`. | Вышестоящая складская ячейка должна относиться к тому же месту хранения. |
| `PS-WB-006` | Иерархия ячеек не содержит циклов | Проверка выполняется hierarchy capability Object Runtime по `Parent`. | Иерархия складских ячеек не должна содержать циклов. |
| `PS-WB-007` | Нельзя архивировать ячейку с активными дочерними ячейками | Нет активных `WarehouseBin`, у которых `Parent` равен текущей ячейке. | Нельзя архивировать складскую ячейку, пока у нее есть активные дочерние ячейки. |
| `PS-WB-008` | Изменение места хранения ячейки не нарушает иерархию | При изменении `Warehouse` у ячейки нет неархивированных и неудаленных дочерних ячеек. `Parent` и `StorageArea` должны быть пустыми либо относиться к новому `Warehouse` в рамках той же операции. | Нельзя изменить место хранения ячейки, пока у нее есть неархивированные и неудаленные дочерние ячейки или связи с прежним местом хранения. |
| `PS-WB-009` | Служебные поля иерархии не редактируются пользователем | `Root`, `Level`, `Path` и виртуальное поле `HasChildren` изменяются только hierarchy capability Object Runtime. | Служебные поля иерархии рассчитываются системой. |
| `PS-WB-010` | Запас допускается в любом узле иерархии ячеек | Наличие активных дочерних `WarehouseBin` не запрещает использовать текущую ячейку для размещения запаса. Проверки и списки выбора не требуют `HasChildren = false`. | Складская ячейка может использоваться для размещения запаса независимо от наличия дочерних ячеек. |

## 11. Правила параметров хранения

| Код | Правило | Проверка | Сообщение |
|---|---|---|---|
| `PS-IP-001` | Владелец является местом хранения | `OrganizationalUnit.IsInventoryStorageLocation = true`. | Параметры хранения можно задать только для места хранения. |
| `PS-IP-002` | Ячейка отпуска выбирается только для МХ отпуска | Если `ReleaseWarehouseBin` заполнено, то `ReleaseWarehouse` обязательно и `ReleaseWarehouseBin.Warehouse = ReleaseWarehouse`. | Сначала выберите МХ отпуска; ячейка отпуска должна относиться к выбранному МХ. |
| `PS-IP-003` | Ячейка списания выбирается только для МХ списания | Если `IssueWarehouseBin` заполнено, то `IssueWarehouse` обязательно и `IssueWarehouseBin.Warehouse = IssueWarehouse`. | Сначала выберите МХ списания; ячейка списания должна относиться к выбранному МХ. |
| `PS-IP-004` | Ячейка выпуска выбирается только для МХ выпуска | Если `OutputWarehouseBin` заполнено, то `OutputWarehouse` обязательно и `OutputWarehouseBin.Warehouse = OutputWarehouse`. | Сначала выберите МХ выпуска; ячейка выпуска должна относиться к выбранному МХ. |
| `PS-IP-005` | Ячейка брака выбирается только для МХ брака | Если `ScrapWarehouseBin` заполнено, то `ScrapWarehouse` обязательно и `ScrapWarehouseBin.Warehouse = ScrapWarehouse`. | Сначала выберите МХ брака; ячейка брака должна относиться к выбранному МХ. |
| `PS-IP-006` | Порядок отбора неотрицательный | `PickingOrder >= 0`. | Порядок отбора не может быть отрицательным. |
| `PS-IP-007` | Стадия контроля серийных номеров допустима | Если `WIPSerialNumbersControlStage` заполнено, значение равно `InQueue`, `InProcessing` или `ForTransfer`. | Недопустимая стадия контроля серийных номеров. |
| `PS-IP-008` | Стадии НЗП включают очередь | В битовой маске `SegmentStageUsage` установлен флаг `InQueue`: `(SegmentStageUsage & InQueue) = InQueue`. | Стадии НЗП должны включать стадию В очереди. |
| `PS-IP-009` | Стадия контроля СН входит в стадии НЗП | Если `WIPSerialNumbersControlStage` заполнено, соответствующий ему флаг установлен в битовой маске `SegmentStageUsage`. | Стадия контроля серийных номеров должна входить в стадии НЗП. |
| `PS-IP-010` | Параметры передела применяются только к уровню передела | `ScrapWarehouse`, `ScrapWarehouseBin`, `WIPSerialNumbersControlStage`, `SegmentStageUsage`, `TransferYieldDefaultType`, `TransferRejectDefaultType`, `TransferScrapDefaultType` редактируются только если `OrganizationalUnit.IsSegmentLevel = true`. Зарезервированные status-поля в Object Runtime v1 не публикуются. | Параметр доступен только для организационной единицы уровня передела. |
| `PS-IP-011` | Параметры хранения инициализируются значениями по умолчанию | При автоматическом создании `OrganizationalUnitInventoryParameters` система устанавливает значения по умолчанию, определенные для его обязательных полей в `02_domain_model.md`. | Параметры хранения должны быть созданы с корректными начальными значениями. |
| `PS-IP-012` | Параметры хранения изменяются только у владельца в черновике | Изменение `OrganizationalUnitInventoryParameters` допускается только если состояние связанной `ProductionUnit` или `Subcontractor` равно `Draft`. Проверка применяется в Object Runtime независимо от UI и способа вызова. | Параметры места хранения можно изменить только после возврата организационной единицы в черновик. |

В v1 таблица `PS-IP-*` является исчерпывающим набором межполевых ограничений `OrganizationalUnitInventoryParameters`. Дополнительная условная проверка сочетаний `Transfer*DefaultType`, мест хранения и остальных настроек не выполняется: поля редактируются независимо, а содержательную корректность их заполнения контролирует пользователь. Такая логика может быть расширена на последующих этапах после уточнения производственных и логистических сценариев.

## 12. Правила удаления и архивирования

| Объект | Ограничение |
|---|---|
| `ProductionUnit` | Нельзя архивировать опубликованный объект с активными дочерними производственными единицами. |
| `Subcontractor` | В v1 дополнительных ограничений по входящим ссылкам других модулей нет. |
| `Company` | Нельзя архивировать организацию, если на нее ссылаются активные производственные единицы. |
| `OrganizationalUnitInventoryParameters` | Физически удаляется только системной синхронизацией при изменении `IsInventoryStorageLocation` владельца с `true` на `false`. Самостоятельные delete/archive и мягкое удаление запрещены. |
| `StorageArea` | Нельзя архивировать зону с активными складскими ячейками. |
| `WarehouseBinType` | Нельзя архивировать тип, используемый активными складскими ячейками. |
| `WarehouseBin` | Нельзя архивировать ячейку с активными дочерними ячейками. Входящие ссылки других модулей в v1 не проверяются. |

Межмодульные dependency checks отложены из v1 до появления общего платформенного механизма входящих зависимостей. ПР03 проверяет только принадлежащие ему объекты и ссылки. До реализации общего механизма модуль-потребитель обязан не допускать недопустимое использование отключенных или архивированных объектов ПР03 и корректно обрабатывать их состояние при чтении.
