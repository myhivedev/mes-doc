# Backlog - 06 Управление проектами

## 1. Назначение документа

Документ содержит расширения PR06, которые осознанно не входят в MVP. Записи backlog не являются утвержденными требованиями текущей версии и не должны добавляться в доменную модель без отдельного решения.

## 2. Отложенные расширения

| ID | Область | Содержание | Причина отложения |
|---|---|---|---|
| `PR06-BL-001` | План проекта | Ввести объект плана проекта с работами, связями, календарными ограничениями и вариантами планирования. | В MVP `ProjectPhase` является только структурным и аналитическим объектом. |
| `PR06-BL-002` | План-факт | Добавить плановые и фактические показатели выполнения этапов и внутренние графики выполнения. | Показатели должны принадлежать вариантам и версиям плана проекта. |
| `PR06-BL-003` | Baseline | Ввести версии базового плана и операцию фиксации baseline. | Зависит от модели проектного плана и контроля исполнения. |
| `PR06-BL-004` | Контрольные точки | Ввести контрольные точки как элементы плана, связанные с работами и зависимостями. | Контрольная точка не является самостоятельным типом этапа проекта. |
| `PR06-BL-005` | Workflow | Определить состояния и переходы проекта / этапа, если появится процесс публикации, утверждения или контроля. | В MVP достаточно стандартных операций Object Runtime. |
| `PR06-BL-006` | Назначение CostCode | При необходимости ввести отдельные ограничения допустимых кодов затрат для аналитических объектов. | В MVP нет прямой связи `CostCode` с `Project` или `ProjectPhase`; внешние потребители используют собственные ссылки. |
| `PR06-BL-008` | Глобальный список этапов | Добавить отдельный список `Этапы проектов` с массовым поиском и обработкой. | В MVP этапы доступны из карточки проекта и через lookup. |
| `PR06-BL-009` | Наследование ответственности | Добавить автоматическое наследование или UI-подсказку значений ответственности проекта в этап. | В MVP значения этапа вводятся отдельно и не наследуются. |
| `PR06-BL-010` | Проектные отчеты | Добавить отчеты по портфелю проектов, структуре этапов, план-факту и затратам. | Нет утвержденной модели план-фактных и затратных данных. |

## 3. Правила работы с backlog

- запись backlog не создает объект, поле, enum, permission или пункт меню текущего MVP;
- перед реализацией расширения нужно обновить [90_traceability_pr06.md](90_traceability_pr06.md) и соответствующие нормативные документы;
- изменения контракта использования `CostCode` должны быть согласованы с PR01 и потребляющими аналитическими модулями;
- проектный план должен быть спроектирован отдельно от структурного дерева `ProjectPhase`;
- `04_workflows.md` создается только после принятия прикладного workflow.
