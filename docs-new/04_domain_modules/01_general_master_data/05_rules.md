# Правила поведения - 01 General Master Data

## 1. Назначение документа

Документ фиксирует правила проверки и поведения объектов `01 General Master Data`.

Документ не повторяет полный состав полей. Поля и связи описаны в `02_domain_model.md`, граница модуля - в `01_scope.md`, трассировка решений ПР01 - в `90_traceability_pr01.md`.

## 2. Общие правила GMD

Для всех объектов GMD действуют правила Common:

- системные поля Common не редактируются пользователем напрямую;
- `Presentation` не является физическим полем GMD;
- `Status` из ПР01 не переносится как универсальное поле GMD;
- архивирование и мягкое удаление выполняются по правилам `00_common`;
- полный жизненный цикл подключается только для типов объектов, которым он нужен.

Все записи объектов GMD имеют `TenantId`.

Правила области предприятия:

- при создании корневого объекта `TenantId` берется из контекста Object Runtime;
- для дочернего или связующего объекта `TenantId` должен совпадать с `TenantId` владельца;
- пользовательский запрос не должен менять `TenantId`;
- ссылка на другой объект GMD допустима только в пределах того же предприятия, если отдельным правилом не описан сценарий между предприятиями.

## 3. Ссылки на внешние объекты

GMD хранит внешние ссылки только как значения своих полей и не владеет жизненным циклом внешних объектов.

| Ссылка | Правило проверки |
|---|---|
| `Lot` | Допустима только как внешний владелец партионного пересчета `UnitOfOperation`. |
| `ProductionUnit`, `Personnel`, `OrganizationalUnit`, `WarehouseBin`, `InventoryAnalyticGroup` | Проверяется существование и доступность ссылочного объекта через модуль-владелец. |
| `TransportUnit` | Не используется как объект GMD. В GMD допускается только `TransportUnitType`. |

Если модуль-владелец внешнего объекта еще не реализован, GMD фиксирует тип ссылки и предметное ограничение выбора. Проверка доступности внешнего объекта относится к модулю-владельцу.

## 4. Единицы измерения

### Unit

Правила:

- `Acronym` обязателен;
- `Precision` обязателен;
- `Precision` должен быть в диапазоне `0..8`;
- `OKEI` и `InternationalAcronym` не заменяют `Code` из `CommonCatalogObject`.

### UnitGroup

Правила:

- `BaseUnit` обязателен;
- `BaseUnit.TenantId` должен совпадать с `UnitGroup.TenantId`;
- пересчеты группы задаются через `UnitOfOperation`;
- базовая ЕИ группы не изменяется, если у `UnitGroup` есть активные `UnitOfOperation`.

## 5. UnitOfOperation

`UnitOfOperation` должен иметь ровно одного владельца и ровно одну цель пересчета.

### Владельцы

Ровно одно из полей должно быть заполнено:

```text
UnitGroup
Nomenclature
Lot
Pack
TransportUnitType
```

### Цели

Ровно одно из полей должно быть заполнено:

```text
ToUnit
ToPack
ToNomenclature
```

### Матрица допустимых пар

| Владелец | Цель | Правило |
|---|---|---|
| `UnitGroup` | `ToUnit` | Общий пересчет из базовой ЕИ группы в дополнительную ЕИ. |
| `Nomenclature` | `ToUnit` | Пересчет для конкретной НП из ее базовой ЕИ в дополнительную ЕИ. |
| `Lot` | `ToUnit` | Партионный пересчет, если коэффициент зависит от партии. |
| `Pack` | `ToUnit` | Упаковка содержит количество в ЕИ. |
| `Pack` | `ToPack` | Упаковка содержит другую упаковку. |
| `TransportUnitType` | `ToNomenclature` | Вместимость типа единицы транспортировки: количество НП в ее базовой учетной ЕИ на одну единицу транспортировки данного типа. |

Другие пары запрещены.

### Общие проверки

Правила:

- `ConversionFactor` должен быть больше нуля;
- `ApplicationArea` хранит флаги `UnitApplicationAreaFlags`: `Production = 1`, `Purchase = 2`, `Sale = 4`;
- если `ApplicationArea` не заполнено, единица операции применяется во всех областях;
- `Precision` должен быть в диапазоне `0..8`;
- если `IsDivisible = false`, количество в этой единице операции не должно иметь дробную часть;
- `TenantId` должен совпадать с `TenantId` владельца пересчета;
- если цель пересчета является объектом GMD, ее `TenantId` должен совпадать с `UnitOfOperation.TenantId`.

### Единица операции по умолчанию

`IsDefault` действует в разрезе владельца и областей применения.

Для одного владельца и каждой отдельной области применения допускается не более одной активной записи `UnitOfOperation` с `IsDefault = true`.

Если у двух записей по умолчанию одного владельца пересекаются области применения, запись должна быть отклонена. Пустое `ApplicationArea` считается пересечением с любой областью применения.

При создании НП должна быть создана базовая запись:

```text
Nomenclature = текущая НП
ToUnit = Nomenclature.Unit
ConversionFactor = 1
ApplicationArea не заполнено
IsDefault = true
```

При смене `Nomenclature.Unit` базовая запись `UnitOfOperation` должна быть синхронизирована с новой базовой ЕИ. Ограничения изменения базовой ЕИ описаны в правилах `Nomenclature`.

## 6. Номенклатура

### NomenclatureGroup

Правила:

- иерархия групп не должна содержать циклов;
- `Parent` должен относиться к тому же предприятию;
- группу нельзя сделать дочерней самой себе;
- группу нельзя архивировать, если у нее есть неархивные дочерние группы или неархивные НП.

### NomenclatureKind

Правила:

- вид НП используется для классификации и набора реквизитов;
- архивный вид НП нельзя назначать новой НП;
- назначения реквизитов вида НП нельзя удалить или изменить, если по ним уже есть строки значений.

### Nomenclature

Правила:

- `Unit`, `ApplicationArea` и `NomenclatureType` обязательны;
- `ApplicationArea` хранит один или несколько флагов enum `ApplicationArea`: `Production = 1`, `Maintenance = 2`;
- `Unit.TenantId` должен совпадать с `Nomenclature.TenantId`;
- если заполнены `NomenclatureKind`, `NomenclatureGroup`, `PackSet`, `BaseManufacturer`, их `TenantId` должен совпадать с `Nomenclature.TenantId`;
- если `BaseManufacturer` заполнен, `BaseManufacturer.Category` должен содержать флаг `Manufacturer`;
- `ExpirationTime` допустим только вместе с заполненным правилом контроля срока годности;
- если контроль срока годности отключен, поля периода и значения срока годности должны быть пустыми или игнорироваться правилом нормализации;
- если `PackSet` заполнен, `PackSet.BaseUnitId` должен быть равен `Nomenclature.UnitId`;
- если при создании `ObtainMethod` не указан и `NomenclatureType` равен `ComponentPart`, `AssemblyUnit` или `RoughPart`, устанавливается `ObtainMethod = Production`;
- если при создании `ProcessType` не указан и `NomenclatureType` равен `ComponentPart`, `AssemblyUnit` или `RoughPart`, устанавливается `ProcessType = Production`;
- `IsMain` и `BlankSize` не входят в целевую модель до ответа аналитика.

Производственно-логистические поля НП остаются в GMD как политики и значения по умолчанию. Ссылочные объекты этих полей проверяются через соответствующие модули-владельцы.

### Смена базовой ЕИ НП

Изменение `Nomenclature.Unit` разрешается только в состояниях, где жизненный цикл НП допускает изменение правил измерения и пересчета.

При разрешенной смене `Nomenclature.Unit`:

- базовая `UnitOfOperation` синхронизируется по правилу раздела `UnitOfOperation`;
- назначенный `PackSet` остается допустимым только если `PackSet.BaseUnitId` равен `Nomenclature.UnitId`;
- каждая активная дополнительная `UnitOfOperation` НП должна пройти правила раздела `UnitOfOperation`;
- цепочки пересчета индивидуальных упаковок НП должны завершаться `ToUnit = Nomenclature.Unit` или иметь дальнейший пересчет в `Nomenclature.Unit`.

Изменение НСИ не пересчитывает уже созданные документы, операции и остатки модулей-потребителей.

### NomenclatureVariant

Правила:

- исполнение должно принадлежать одной НП;
- `NomenclatureVariant.TenantId` должен совпадать с `Nomenclature.TenantId`;
- для одной НП допускается не более одного активного исполнения с `IsBasic = true`;
- если `Nomenclature.IsVariantRequired = true`, операции, которым нужна конкретизация НП, должны требовать исполнение.

## 7. Упаковки и единицы транспортировки

### PackSet

Правила:

- `BaseUnit` обязателен;
- `BaseUnit.TenantId` должен совпадать с `PackSet.TenantId`;
- набор упаковок описывает допустимые упаковки для НП, но не фактические упаковочные единицы.

### Pack

Правила:

- должен быть заполнен ровно один владелец: `PackSet` или `Nomenclature`;
- `Pack.Type` не вводится и не валидируется как физическое поле;
- тип упаковки определяется владельцем;
- `TenantId` упаковки должен совпадать с `TenantId` владельца;
- пересчет упаковки задается через `UnitOfOperation`;
- упаковка и ее начальные `UnitOfOperation` создаются атомарно; сохранение не допускается, если
  переданная коллекция не задает один однозначный ациклический путь в базовую ЕИ владельца;
  такой способ необходим, потому что при добавлении пересчетов только после первого сохранения
  упаковки пользователь может завершить редактирование индивидуальной упаковки и номенклатуры
  до настройки пересчетов, оставив сохраненную номенклатуру с нарушенной цепочкой пересчета;
- при удалении номенклатуры ее индивидуальные упаковки и принадлежащие им пересчеты удаляются
  каскадно с тем же режимом удаления;
- физические характеристики упаковки, правила хранения, паллетизация, возвратность, остатки и движения относятся к логистическим модулям, а не к правилам GMD v1.

### TransportUnitType

Правила:

- `TransportUnitType` является справочным типом, а не фактической единицей транспортировки;
- фактический `TransportUnit` не создается и не изменяется через GMD;
- вместимость по НП описывается через `UnitOfOperation` с владельцем `TransportUnitType` и целью `ToNomenclature`;
- `PackageNomenclature`, если заполнена, должна ссылаться на активную НП того же предприятия.

## 8. Серийные номера

Правила:

- `Nomenclature` обязателен;
- `TenantId` серийного номера должен совпадать с `Nomenclature.TenantId`;
- если заполнено `NomenclatureVariant`, оно должно принадлежать той же НП;
- если `Manufacturer` заполнен, `Manufacturer.TenantId` должен совпадать с `SerialNumber.TenantId`;
- если `Manufacturer` заполнен, `Manufacturer.Category` должен содержать флаг `Manufacturer`;
- `AssemblyKitYear` и `OrdinalNumber` обязательны;
- `SerialNumber` обязателен;
- уникальность серийного номера задается в пределах НП и предприятия;
- остатки, местонахождение, движения и операционные состояния серийного номера относятся к модулям учета движения и прослеживаемости.

## 9. Реквизиты номенклатуры

### NomenclatureParameter

Правила:

- `AttributeCode` обязателен и должен быть стабильным кодом реквизита;
- `DataType` обязателен;
- `AssignmentArea` обязателен и хранит одно значение enum `NomenclatureParameterAssignmentArea`;
- если `DisplayName` не заполнено, в пользовательском интерфейсе для подписи реквизита используется `Name`;
- `AllowedValuesSource` должен иметь одно из значений: `None`, `LocalEnum`, `ValueSet`;
- если `AllowedValuesSource = ValueSet`, поле `ValueSetCode` обязательно;
- если `AllowedValuesSource != ValueSet`, поле `ValueSetCode` должно быть пустым;
- если `DataType` является строковым, `Length` должен быть больше нуля;
- если `DataType` является числовым, `Precision` должен быть в допустимом диапазоне;
- тип данных реквизита нельзя менять после появления назначений или строк значений;
- `AllowedValuesSource` нельзя менять после появления строк значений этого реквизита.

### NomenclatureParameterAssignment

Правила:

- `NomenclatureParameter` обязателен;
- назначение может быть общим, назначением на `NomenclatureKind` или прямым назначением на `Nomenclature`;
- нельзя одновременно назначить реквизит на `NomenclatureKind` и `Nomenclature`;
- хотя бы один признак применимости значения должен быть включен;
- `OrdinalNumber` определяет порядок отображения внутри применимой группы реквизитов;
- `DefaultValue`, если заполнено, должно соответствовать типу данных реквизита и источнику допустимых значений;
- область назначения нельзя менять после появления строк значений по этому назначению.

Эффективный набор реквизитов НП вычисляется из применимых назначений:

```text
общие назначения
назначения вида НП
прямые назначения НП
```

Прямое назначение на НП используется для исключительных случаев и не заменяет типовую настройку через `NomenclatureKind`.
Поскольку `NomenclatureParameter.AssignmentArea` хранит ровно одно значение, корректно настроенный реквизит назначается только на своем уровне. Одновременные назначения одного реквизита на разных уровнях считаются некорректной конфигурацией, а не механизмом переопределения.

### NomenclatureParameterEnumValue

Правила:

- `NomenclatureParameter` обязателен;
- `Number` обязателен и является локальным кодом значения;
- `Name` обязателен;
- `Number` должен быть уникален в пределах `NomenclatureParameter`;
- локальные значения допустимы только для реквизитов с `AllowedValuesSource = LocalEnum`;
- значение нельзя удалить, если оно используется в строках значений реквизитов.

### Строки значений реквизитов

Правила применяются к:

```text
NomenclatureParameterValue
NomenclatureVariantParameterValue
SerialNumberParameterValue
```

Для объектов других модулей должны применяться такие же правила в модуле-владельце.

Общие проверки строки значения:

- владелец значения обязателен;
- `NomenclatureParameter` обязателен;
- `AttributeCode` должен совпадать с `NomenclatureParameter.AttributeCode`;
- `ValueType` должен соответствовать `NomenclatureParameter.DataType`;
- для одного владельца и одного реквизита допускается не более одной активной строки значения;
- значение должно быть допустимо для уровня владельца: НП, исполнение НП, серийный номер или внешний тип объекта-владельца;
- реакция на `IsMandatory` при сохранении и публикации владельца откладывается до отдельного уточнения требований; сам признак пока не запрещает отсутствие или пустое значение;
- должно быть заполнено только одно типизированное поле значения, соответствующее `ValueType`, если тип не допускает составное значение;
- для `LocalEnum` в `ReferenceCode` хранится `NomenclatureParameterEnumValue.Number`;
- для `ValueSet` в `ReferenceCode` хранится код значения Platform ValueSetData;
- значение по умолчанию хранится на назначении реквизита, а не в строке значения как отдельный признак.

Для `Nomenclature.ParameterValues` действуют дополнительные правила:

- в коллекции существуют только фактически созданные строки значений; отсутствующие значения не материализуются при открытии карточки;
- значение общего или видового реквизита может быть удалено без удаления назначения;
- для реквизита с `AssignmentArea = Nomenclature` сохранение значения атомарно создает прямое назначение, а удаление значения атомарно удаляет это назначение;
- прямое назначение реквизита на конкретную НП не существует без соответствующей строки значения.

## 10. Контрагенты

### Contractor

Правила:

- `Type` обязателен;
- `Category` обязателен;
- `Type` использует системный enum `ContractorType`;
- `Category` использует флаговый системный enum `ContractorCategoryFlags`;
- `Category` должна поддерживать несколько значений для одного контрагента;
- группа полей "Настройки для ТОиР" доступна, если `Category` содержит хотя бы один флаг: `Supplier`, `Manufacturer`, `Builder`;
- договоры, цены, банковские реквизиты, условия поставки и CRM-сценарии не входят в правила GMD v1.

### ContractorGroup

Правила:

- группа контрагентов является справочником GMD;
- архивную группу нельзя использовать для нового включения контрагента.

### ContractorInContractorGroup

Правила:

- `ContractorGroup` обязателен;
- `Contractor` обязателен;
- `TenantId` связи должен совпадать с `TenantId` группы и контрагента;
- один контрагент может быть включен в одну группу только один раз.

### ContractorContact

Правила:

- `Contractor` обязателен;
- `ContactType` обязателен;
- `TenantId` контакта должен совпадать с `Contractor.TenantId`;
- `ContactType` использует набор значений `GMD.ContractorContactType` с начальными значениями `Supervisor` и `ContactPerson`;
- для одного `Contractor + ContactType` допускается один контакт.

## 11. Машиночитаемая идентификация

GMD не проектирует собственные `BarcodeTemplate`, `BarcodeData` или `Barcode`.

Объекты GMD могут подключать общую возможность машиночитаемой идентификации по `REQ-00-B-019..REQ-00-B-022`.

Правила генерации, хранения, проверки контекста и количества идентификаторов на объект определяются в Common/Platform, не в GMD.

## 12. Нумерация

GMD не проектирует собственные `NumeratorDescriptor`, `NumeratorDescription`, `Numerator` или `NumeratorValue`.

GMD объявляет поля, доступные для автоматической нумерации, например:

```text
Nomenclature.Code
SerialNumber.SerialNumber
```

Правила нумерации, шаблоны, условия, область действия, счетчики выполнения и момент присвоения номера описываются в Platform Numbering.

`IsLotsControlRequired` и `SerialNumbersControlType` используются как предметные признаки контроля партий и серийных номеров. Они не задают формат номера и не являются профилем нумерации.

## 13. Удаление и архивирование

Для GMD действуют правила `00_common`.

Специальные правила GMD:

- при удалении НП строки `UnitOfOperation`, владельцем которых является эта НП, удаляются вместе с НП;
- `NomenclatureParameter` нельзя удалить, если есть `NomenclatureParameterAssignment` с ссылкой на этот реквизит;
- `NomenclatureParameterEnumValue` нельзя удалить, если есть строки значений реквизитов с этим локальным значением;
- `NomenclatureParameterAssignment` нельзя удалить, если есть строки значений реквизитов с ссылкой на это назначение, кроме системного атомарного удаления прямого назначения вместе со значением на карточке НП;
- так как отдельная таблица `NomenclatureParameterDefaultValue` в целевой модели не вводится, каскадное удаление значения по умолчанию из ПР01 заменяется удалением поля `DefaultValue` вместе с `NomenclatureParameterAssignment`.
