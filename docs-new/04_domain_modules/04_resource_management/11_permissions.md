# Права доступа - 04 Управление ресурсами

## 1. Назначение документа

Документ определяет права доступа к объектам модуля `04 Управление ресурсами`,
прикладные роли, область их действия и правила доступа к зависимым данным и
ссылкам на объекты других модулей.

Документ не описывает пользовательские формы, стандартную реализацию
Tenant Security или права на объекты, которыми владеют другие модули.

## 2. Принципы доступа

Модуль использует стандартные права Object Runtime для самостоятельных типов:

| Действие | Смысл |
|---|---|
| `View` | Просмотр объекта в списках, карточках и lookup. |
| `Create` | Создание объекта. |
| `Edit` | Изменение объекта. |
| `Delete` | Удаление объекта в пределах `DeleteCapability` и правил Common. |
| `Archive` | Архивирование объекта, если оно разрешено контрактом типа. |
| `Restore` | Восстановление объекта из архива, если оно разрешено контрактом типа. |

Право `ViewTechnicalData` в версии v1 модуля 04 не регистрируется. Секция
«Администрирование» Common не включается в предметные требования модуля.

Область действия ролей - весь текущий tenant. Связь с `ProductionUnit` не
является границей прав и не ограничивает доступ пользователя отдельным
подразделением.

Для нового выбора ссылка должна быть доступна по праву `View` на целевой
объект. Право `Create` или `Edit` на справочник, из которого выбирается
значение, для этого не требуется. Для внешнего объекта права определяются
модулем-владельцем.

Стандартные операции и права проверяются на сервере. Скрытие действия в UI не
заменяет проверку права.

Вложенные данные не получают отдельных permission codes только из-за того,
что они являются элементами коллекции. Их доступ определяется правами на
объект-владелец и режимом коллекции Object Runtime.

## 3. Самостоятельно защищаемые объекты

Эти типы имеют собственные object contracts и могут быть источниками
самостоятельных списков, карточек и lookup.

| Объект | Русское название | Стандартные права | Жизненный цикл | Основание |
|---|---|---|---|---|
| `WorkPlace` | Рабочее место | Просмотр, создание, изменение, удаление, архивирование, восстановление | Только стандартный Common, если capability включена | Самостоятельный справочный объект рабочего места. |
| `Personnel` | Сотрудник | Просмотр, создание, изменение, удаление, архивирование, восстановление | Только стандартный Common, если capability включена | Самостоятельный объект персонала. |
| `WorkPlaceGroup` | Группа рабочих мест | Просмотр, создание, изменение, удаление, архивирование, восстановление | Только стандартный Common, если capability включена | Самостоятельный иерархический объект. |
| `PersonnelGroup` | Группа сотрудников | Просмотр, создание, изменение, удаление, архивирование, восстановление | Только стандартный Common, если capability включена | Самостоятельный иерархический объект. |
| `Profession` | Профессия | Просмотр, создание, изменение, удаление, архивирование, восстановление | Только стандартный Common, если capability включена | Самостоятельный справочник персонала. |
| `PaymentGroup` | Группа оплаты | Просмотр, создание, изменение, удаление, архивирование, восстановление | Только стандартный Common, если capability включена | Самостоятельный справочник персонала. |
| `PersonnelAllowanceType` | Вид допуска сотрудника | Просмотр, создание, изменение, удаление, архивирование, восстановление | Только стандартный Common, если capability включена | Самостоятельный справочник видов допусков. |
| `AbsenceReason` | Причина отсутствия | Просмотр, создание, изменение, удаление, архивирование, восстановление | Только стандартный Common, если capability включена | Самостоятельный справочник причин отсутствия. |
| `Holiday` | Праздничная дата | Просмотр, создание, изменение, удаление, архивирование, восстановление | Только стандартный Common, если capability включена | Самостоятельный объект производственного календаря. |
| `DayType` | Тип рабочего дня | Просмотр, создание, изменение, удаление, архивирование, восстановление | Только стандартный Common, если capability включена | Самостоятельный справочник типов рабочих дней. |
| `WorkSchedule` | График работы | Просмотр, создание, изменение, удаление, архивирование, восстановление | Только стандартный Common, если capability включена | Самостоятельный объект графика. |
| `ShiftRotationModel` | Модель чередования смен | Просмотр, создание, изменение, удаление, архивирование, восстановление | Только стандартный Common, если capability включена | Самостоятельный объект модели сменности. |
| `Tooling` | Технологическая оснастка | Просмотр, создание, изменение, удаление, архивирование, восстановление | Только стандартный Common, если capability включена | Самостоятельный тип общего хранения `ToolBase`. |
| `Gage` | Контрольно-измерительный инструмент | Просмотр, создание, изменение, удаление, архивирование, восстановление | Только стандартный Common, если capability включена | Самостоятельный тип общего хранения `ToolBase`. |

`ToolBase` не является самостоятельным permission resource. Он используется как
абстрактный reference-only тип для общего lookup, который возвращает
`Tooling` или `Gage`. Право просмотра и переход к карточке проверяются по
конкретному типу найденного объекта.

## 4. Данные, защищаемые через владельца или контекст

Следующие типы не получают отдельных permission codes в v1, если они
публикуются только через коллекцию, одиночное зависимое свойство или контекст
внешнего владельца.

| Строка / объект | Владелец или контекст | Как проверяется доступ |
|---|---|---|
| `WorkPlaceInWorkPlaceGroup` | `WorkPlaceGroup.Members` | Через права на `WorkPlaceGroup`; ссылка на `WorkPlace` проверяется по `View`. |
| `PersonnelInPersonnelGroup` | `PersonnelGroup.Members` | Через права на `PersonnelGroup`; ссылка на `Personnel` проверяется по `View`. |
| `WorkPlaceLocation` | `WorkPlace.Locations` | Через права на `WorkPlace`; ссылки на `ProductionUnit` проверяются по правилам PR03. |
| `PersonnelLocation` | `Personnel.Locations` | Через права на `Personnel`; ссылка на `ProductionUnit` проверяется по правилам PR03. |
| `PersonnelQualification` | `Personnel.Qualifications` | Через права на `Personnel`; ссылки на `Profession` и `PaymentGroup` требуют `View`. |
| `PersonnelAllowance` | `Personnel.Allowances` | Через права на `Personnel`; ссылки на `WorkPlace` и `PersonnelAllowanceType` требуют `View`. |
| `PersonnelAbsence` | `Personnel.Absences` | Через права на `Personnel`; ссылка на `AbsenceReason` требует `View`. |
| `DayTypeDescription` | `DayType.Descriptions` | Через права на `DayType`. |
| `WorkScheduleDescription` | `WorkSchedule.Descriptions` | Через права на `WorkSchedule`. |
| `ShiftRotationDescription` | `ShiftRotationModel.Descriptions` | Через права на `ShiftRotationModel`. |
| `WorkPlaceGroupWorkSchedule` | `WorkPlaceGroup.WorkSchedules` | Через права на `WorkPlaceGroup`; ссылка на `WorkSchedule` требует `View`. |
| `WorkPlaceWorkSchedule` | `WorkPlace.WorkSchedules` | Через права на `WorkPlace`; ссылка на `WorkSchedule` требует `View`. |
| `PersonnelGroupWorkSchedule` | `PersonnelGroup.WorkSchedules` | Через права на `PersonnelGroup`; ссылка на `WorkSchedule` требует `View`. |
| `PersonnelWorkSchedule` | `Personnel.WorkSchedules` | Через права на `Personnel`; ссылка на `WorkSchedule` и `ShiftRotationModel` требует `View`. |
| `OrganizationalUnitWorkSchedule` | Контекст `OrganizationalUnit` | Право на внешний `OrganizationalUnit` определяется PR03; ссылка на `WorkSchedule` требует `View` в 04. |
| `ProductionUnitOperationParameters` | Навигация `ProductionUnit.OperationParameters` | Доступ к контексту `ProductionUnit` определяется PR03; изменение параметров выполняется по правилам владельца настройки в 04. |
| `WorkPlaceOperationParameters` | `WorkPlace.OperationParameters` | Через права на `WorkPlace`; максимум одна запись. |
| `PersonnelOperationParameters` | `Personnel.OperationParameters` | Через права на `Personnel`; максимум одна запись. |
| `MaterialResponsiblePerson` | Контексты `ProductionUnit` и `Personnel` | Через доступный контекст; при создании и изменении проверяются права `View` на обе ссылки. Обратная навигация из `Personnel` не передает ему владение объектом. Отдельный универсальный список не создается. |

Обратная навигация к данным другого владельца не передает права владения. В
частности, просмотр допусков через `WorkPlace.PersonnelAllowances` не делает
`WorkPlace` владельцем `PersonnelAllowance`.

Если зависимый тип позднее будет опубликован как самостоятельный объект с
отдельными операциями, он переносится в раздел 3 и получает собственные
стандартные права.

## 5. Роли

Роли отражают область ответственности пользователя, а не логическую
иерархию типов. `Personnel` является ресурсом и наследуется от `ResourceBase`,
но для управления ветками данных используется отдельная роль.

| Роль | Код роли | Назначение | Область действия | Базовый доступ |
|---|---|---|---|---|
| Администратор управления ресурсами | `ResourceManagementAdmin` | Полное администрирование модуля 04. | Tenant | Все стандартные права на самостоятельные объекты, включая `Delete`, `Archive` и `Restore`. |
| Пользователь управления ресурсами | `ResourceManagementUser` | Просмотр ресурсных данных и доступных ссылок. | Tenant | `View` самостоятельных объектов модуля. |
| Ответственный за рабочие места | `WorkPlaceResponsible` | Ведение рабочих мест, групп рабочих мест и местоположений. | Tenant | `View`, `Create`, `Edit`; `Archive` и `Restore` при наличии capability; без `Delete`. |
| Ответственный за персонал | `PersonnelResponsible` | Ведение сотрудников и связанных данных персонала. | Tenant | `View`, `Create`, `Edit`; `Archive` и `Restore` при наличии capability; без `Delete`. |
| Ответственный за графики работы | `WorkScheduleResponsible` | Ведение графиков, типов дней и моделей чередования смен. | Tenant | `View`, `Create`, `Edit`; `Archive` и `Restore` при наличии capability; без `Delete`. |
| Ответственный за инструмент и оснастку | `ToolingResponsible` | Ведение `Tooling` и `Gage`. | Tenant | `View`, `Create`, `Edit`; `Archive` и `Restore` при наличии capability; без `Delete`. |

## 6. Матрица доступа ролей

В матрице используются сокращения:

владельца, указанные в разделе 4. Это правило не отменяет право `View` на
объект, выбранный в ссылочном поле.

## 7. Особые правила доступа

| Сценарий | Правило доступа |
|---|---|
| Просмотр списка и карточки | Требуется `View` конкретного самостоятельного типа. |
| Новый lookup | Требуется `View` целевого объекта; архивные и удаленные объекты по умолчанию не предлагаются. |
| Сохраненная ссылка | Уже сохраненная ссылка может отображать архивный объект по общим правилам Common; удаленный объект скрывается в обычном режиме. |
| Изменение вложенной коллекции | Требуется `Edit` объекта-владельца; отдельное право на строку не требуется. |
| Создание зависимого объекта | Требуется право ведения объекта-владельца и `View` всех ссылочных объектов. |
| Иерархия групп | Операции с `Parent` выполняются по правам соответствующей группы; проверяются однотипность и отсутствие циклов. |
| Назначение графика | Изменение выполняется через права объекта-владельца назначения; отдельного общего права для абстрактного `ResourceWorkSchedule` нет. |
| Параметры операций | Изменение выполняется через права соответствующего владельца; отдельные права для `GetOperationParameters` в v1 не вводятся. |
| Выбор `ToolBase` | Объединенный lookup возвращает только `Tooling` и `Gage`; право проверяется по конкретному найденному типу. |
| Внешний объект | 04 не выдает права на `ProductionUnit`, `OrganizationalUnit`, `EquipmentUnit`, `Nomenclature` или другие объекты соседних модулей. Требуется право просмотра по правилам модуля-владельца. |
| Удаление | Требуется отдельное право `Delete` и разрешение `DeleteCapability`; `Edit` не заменяет `Delete`. |
| Архивирование и восстановление | Требуются отдельные права `Archive` и `Restore`, если capability типа это допускает. Прикладного workflow в 04 v1 нет. |
| Техническая секция Common | Право `ViewTechnicalData` в 04 v1 не регистрируется и не назначается. |
| Движение инструмента | Права и операции движения, выдачи, возврата, ремонта и списания в 04 не создаются. |

## 8. Техническое отображение

Permission code самостоятельного типа строится по соглашению:

```text
ResourceManagement.{ObjectTypeCode}.{Verb}
```

Примеры:

```text
ResourceManagement.WorkPlace.View
ResourceManagement.WorkPlace.Create
ResourceManagement.WorkPlace.Edit
ResourceManagement.WorkPlace.Delete
ResourceManagement.WorkPlace.Archive
ResourceManagement.WorkPlace.Restore
```

Регистрация permission выполняется модулем в configuration/security
регистрации. Контракт Object Runtime и baseline описывают тип, представления,
capability и режимы коллекций, но не выдают права ролям автоматически.

Отдельные permission codes для `ResourceBase`, `ResourceGroupBase`,
`ResourceWorkSchedule`, `OperationParametersBase` и `ToolBase` не создаются:
базовые типы не являются самостоятельными permission resources.
