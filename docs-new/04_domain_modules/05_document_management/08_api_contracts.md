# Программные контракты — Управление документацией

## 1. Назначение

Документ фиксирует обязательное поведение программного интерфейса (API) без назначения конкретных адресов и протокола. Технические маршруты определяются при реализации по стандартам платформы.

## 2. Общие требования

- идентификаторы предприятия и пользователя берутся из доверенного контекста, а не из изменяемых полей запроса;
- интерфейс и программный интерфейс выполняют одинаковые серверные проверки;
- операции возвращают пользовательское сообщение и стабильный технический код результата;
- чтение не раскрывает данные другого предприятия или недоступной связанной записи;
- изменение защищается общим механизмом конкурентного доступа Object Runtime через `ConcurrencyToken`.

## 3. Стандартные контракты объектов

Для документов, каталогов, типов и содержимого используются стандартные контракты среды выполнения объектов: чтение списка, чтение карточки, создание, сохранение и поддерживаемые переходы жизненного цикла. Обязательные правила приведены в `05_rules.md`, права — в `11_permissions.md`.

## 4. Составные операции

| Пользовательская операция | Вход | Результат |
|---|---|---|
| Создать новую версию | идентификатор опубликованного документа и метка изменения | идентификатор нового черновика |
| Копировать документ | идентификатор документа, признаки переноса содержимого и связей | идентификатор самостоятельного черновика |
| Загрузить файлы | идентификатор документа либо записи бизнес-объекта, набор файлов | результат отдельно по каждому файлу; при необходимости идентификатор созданного документа |
| Добавить ссылку | документ, наименование, адрес HTTP/HTTPS | созданное содержимое и связь |
| Добавить текст | документ, наименование, текст | созданное содержимое и связь |
| Прикрепить содержимое документа | документ либо запись бизнес-объекта, идентификаторы содержимого | созданные связи; при необходимости созданный документ |
| Отвязать содержимое | документ, содержимое, метка изменения | обновлённый состав содержимого; признак мягкого удаления при последней связи |
| Назначить основным | документ, выбранная связь | обновлённые признаки основного содержимого |
| Связать документ с записью | документ, квалифицированный код типа, строковый идентификатор записи | созданная связь |
| Отвязать документ от записи | идентификатор связи | подтверждение удаления связи |
| Открыть содержимое | идентификатор содержимого и контекст документа | поток файла, текст либо адрес ссылки по виду содержимого |

## 5. Частичная загрузка

Множественная загрузка возвращает по каждому файлу: исходное имя, итог «Загружен» или «Не загружен», код и текст ошибки. Ошибка одного файла не скрывает результаты остальных. Если обязательные данные нового документа определить нельзя, документ не создаётся и ни один файл не загружается.

## 6. Ошибки

Минимальные категории: недостаточно прав, неверное состояние, обязательное поле не заполнено, объект другого предприятия, конфликт изменения, недопустимое расширение, превышен размер, некорректная ссылка, дублирующая связь, недоступная запись бизнес-объекта, ошибка хранилища.

## 7. Граница Content API

`UploadFiles` сначала использует платформенный протокол загрузки и затем
передаёт `ContentRef` стандартному action модуля. Скачивание и открытие
выполняются через защищённую конечную точку Content Storage после проверки
владельца. Если action вызывается из встроенной коллекции, идентификатор
владельца передаётся через стандартный `EmbeddedCollectionContext`; модуль
может использовать его для создания связей или строк содержимого без
специальной конечной точки. Модуль 05 не публикует собственный контроллер
бинарных данных.

В пользовательском интерфейсе параметр action `DataType=File` с
`ComponentCode=FilePicker` отображается стандартным `FileUploadParameter`;
режим `Multiple=false/true` задаёт выбор одного или нескольких файлов.
После выбора и успешной загрузки компонент передаёт action набор финализированных
ссылок/descriptor; он не передаёт локальный путь и не вызывает API модуля 05 для
загрузки бинарных данных. Если в будущем модуль использует скалярное свойство
типа `File`, оно отображается стандартным `FileField` и не превращается в
множественное поле.
