# Метрики успеха DMP

## 1. Назначение

Документ фиксирует верхнеуровневые признаки успеха DMP. На текущем этапе исходные материалы задают направления эффекта, но не задают числовые KPI. Поэтому документ отделяет качественные метрики от открытого решения о целевых числах.

## 2. Качественные метрики

| Метрика | Что должно улучшиться | Связанная бизнес-цель |
| --- | --- | --- |
| Прозрачность выполнения заказов | Состояние заказа, операций и отклонений доступно в едином цифровом контуре. | Повысить прозрачность выполнения заказов. |
| Длительность производственного цикла | Управление планом и фактом должно снижать задержки и простои между этапами. | Сократить производственный цикл. |
| Объём незавершённого производства | Потоки материалов, партий и операций становятся управляемыми и измеримыми. | Снизить WIP. |
| Загрузка оборудования и ресурсов | Данные о ресурсах и фактическом исполнении используются для планирования и диспетчеризации. | Повысить загрузку оборудования. |
| Унификация процессов | Предприятия используют общие правила и платформенные механизмы вместо набора локальных решений. | Унифицировать процессы. |
| Доступность производственных данных | Данные пригодны для отчётности, аналитики, аудита и интеграций. | Создать единое пространство данных. |

## 3. Метрики готовности документации

Для архитектурного этапа важны не только бизнес-эффекты, но и готовность проектной документации:

- верхний слой `01_concept` и `02_architecture` содержит нормализованные документы, а не source-копии;
- для каждой платформенной области есть владелец документации;
- детальные документы не дублируют верхнюю архитектуру;
- открытые решения имеют устойчивые ID и маршрут в `10_backlog`,
  `90_traceability.md` или ADR, если для ADR принято отдельное решение;
- source-копии разобраны или явно оставлены как импортированный справочный материал.
